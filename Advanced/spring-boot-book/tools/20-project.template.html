Project: Library Loans API

Time to put the whole book together. You'll build a small but production-shaped REST API for a library: a catalogue of books, members, and loans with real rules — at most three books at a time, nothing new while something is overdue, and never lending the last copy twice. It uses Flyway, Spring Data JPA, transactions with optimistic locking, validation, Problem Details, metrics, an injected clock, and tests at every level of the pyramid.

You will build

  • A package-by-feature layout: catalog, members, loans, web.
  • A Flyway schema with seed data, mapped by JPA entities that protect their own invariants.
  • Business rules in a plain LoanPolicy, orchestrated by a transactional service with a testable Clock.
  • A REST layer with DTO records, validation, paging and RFC 9457 errors mapped in one advice.
  • Unit, slice and integration tests, a metric for loan outcomes, and a runnable demo.

📝 The complete project is in playground/reference/ (clone the playground from coder-hop/springboot-book-playground if you don't have it). Run it with cd playground/reference && ../mvnw spring-boot:run and try curl localhost:8080/api/books; run its tests with ../mvnw test. Every file below is copied from there, and the book's checker compiles and tests them on every build.

🧠 Analogy: the library itself. The front desk (controllers) talks to visitors and fills in forms (DTOs); it doesn't walk into the stacks. The librarian (LibraryService) handles each loan as one complete transaction, consulting the rulebook on the wall (LoanPolicy). The shelves and the card index (repositories, tables) only store things. Each role can change without the others noticing.

The rules and the service

The lending rules are a plain class with no database access: give it the facts, it says yes or throws LoanRefused with a machine-readable code. That makes the rules readable in one place and testable in milliseconds:

{{file:src/main/java/com/example/library/loans/LoanPolicy.java}}

The service gathers the facts, applies the policy and changes state — all in one transaction. If anything fails, nothing is half-done: no copy disappears without a loan, and vice versa. If two requests try to take the last copy at the same moment, the @Version check makes the second commit fail with an optimistic-locking exception instead of over-lending (Chapter 15). Each outcome increments a library.loans counter tagged with a bounded outcome (Chapter 18).

{{file:src/main/java/com/example/library/loans/LibraryService.java}} {{file:src/main/java/com/example/library/catalog/CatalogService.java}} {{file:src/main/java/com/example/library/NotFoundException.java}}

💡 Why the class-level @Transactional(readOnly = true)? Every method is read-only by default (cheaper for Hibernate), and the methods that write opt in with their own @Transactional. Forgetting it on a new write method then fails loudly instead of silently auto-committing statement by statement.

Recap

  • Package by feature; dependencies point downwards; DTOs at the edge, entities inside.
  • Flyway owns the schema (ddl-auto: validate); database constraints back up the Java rules.
  • Entities guard invariants; a pure policy class holds the rules; one transactional service method per business operation; @Version for concurrency.
  • One @RestControllerAdvice maps every failure to a typed RFC 9457 problem.
  • Tests at three levels — policy, service with a movable Clock, web slice — plus one end-to-end HTTP test.

Exercises

Exercise 1 🟢 easy concept

Why does LoanController return LoanDto instead of the Loan entity? Name three problems returning the entity would cause.

Show solution

(1) Lazy relationships (book, member) would be serialised after the transaction ends → LazyInitializationException, or N+1 queries with open-in-view. (2) The JSON shape would change whenever the entity changes — the API contract would follow the database. (3) Internal fields (the member's e-mail, the book's version) would leak, and bidirectional links could recurse.

Exercise 2 🟢 easy concept

The loan limit is configured as library.max-open-loans: 3. How would you set it to 5 in production without rebuilding, and what happens if someone sets it to 0?

Show solution

Set the environment variable LIBRARY_MAXOPENLOANS=5 (or --library.max-open-loans=5). LibraryProperties is @Validated with @Min(1), so 0 makes the application fail at startup with a binding report naming the property and its origin — rather than refusing every loan at runtime.

Exercise 3 🟢 easy concept

Two members request the last copy of a book at exactly the same moment. Walk through what happens, step by step.

Show solution

Both transactions load the book (available = 1, version = n), both pass the policy, both call lend() (available = 0 in memory) and insert a loan. At commit, each issues UPDATE book … WHERE id = ? AND version = n. The first succeeds (version becomes n+1); the second updates 0 rows, Hibernate throws an optimistic-lock exception, the whole second transaction — including its loan insert — rolls back, and ApiErrors returns 409 "Concurrent update". The database CHECK would also have caught a negative value.

Exercise 4 🟢 easy concept

Which test would fail first, and with what kind of message, if someone removed @Transactional from LibraryService.borrow?

Show solution

Because the class is @Transactional(readOnly = true), borrow would run read-only: Hibernate wouldn't flush the change to available, and on some databases the insert would be rejected. LibraryServiceTest.borrowingTakesACopyAndSetsTheDueDate would fail its assertion that one copy is left (expected 1 but was 2) — the class-level default turned a silent bug into a visible one.

Exercise 5 🟡 medium design · playground

Add loan renewal: POST /api/loans/{id}/renew extends the due date by loanDays, at most twice, and never for an overdue loan. Where does each rule go? Sketch the changes to Loan, the service and the advice.

Show solution

Add a renewals column (Flyway V3__loan_renewals.sql: ALTER TABLE loan ADD COLUMN renewals INT NOT NULL DEFAULT 0). In Loan, a method renew(LocalDate today, int days, int maxRenewals) that throws if the loan is closed, overdue (isOverdue(today)) or already renewed maxRenewals times, then does dueOn = dueOn.plusDays(days); renewals++. In LibraryService, a @Transactional renew(Long loanId) that loads the loan and calls it with the clock and properties. Throw a LoanRefused("renewal-limit", …) so the existing advice maps it to 409. Tests: unit-test Loan.renew directly; one service test that moves the clock.

Exercise 6 🟡 medium code · playground

Add a test to BookControllerTest that checks a duplicate ISBN returns 409 with the duplicate problem type.

Show solution

Stub the exact arguments the controller passes (taken from the JSON), or use any() matchers.

Exercise 7 🟡 medium design

The checks in borrow count open loans and then insert. Two concurrent requests from the same member for two different books could both see 2 open loans and both succeed, giving 4. The book's @Version doesn't help here. Propose two fixes.

Show solution

(1) Lock the member row first: a repository method with @Lock(PESSIMISTIC_WRITE) (SELECT … FOR UPDATE) so a member's concurrent borrows are serialised; cheap, because conflicts per member are rare. (2) Give Member an openLoans counter with @Version, incremented in borrow — then the second transaction fails optimistically like the book does. (A database-level constraint isn't easy for "count ≤ 3"; a trigger would work but hides logic.)

Exercise 8 🟡 medium ops

Write the PromQL-style questions you'd put on a dashboard for this service using its metrics: http.server.requests and library.loans. What would you alert on?

Show solution

Panels: request rate and p95 latency per uri (http_server_requests_seconds), 5xx ratio, loans per minute by outcome (rate(library_loans_total[5m])), and the share of outcome="unavailable" (demand the library can't meet). Alerts: 5xx ratio above 1% for 5 minutes; p95 latency above an SLO; readiness DOWN; a sudden drop of outcome="ok" to zero during opening hours.

Exercise 9 🔴 hard design · playground

Add reservations: when no copy is available, a member can reserve the book; when a copy is returned, the oldest reservation gets a 3-day hold and an e-mail. Describe the schema change, the transaction boundaries and how the e-mail is sent safely.

Show solution

Schema (V3): reservation(id, book_id, member_id, created_at, status, hold_until) with an index on (book_id, status, created_at). giveBack (one transaction): close the loan, then — instead of book.giveBack() putting the copy on the shelf — find the oldest WAITING reservation; if one exists, set it to HOLD with hold_until = today + 3 and keep the copy reserved (a reserved count on Book), then publish HoldPlaced. A @TransactionalEventListener sends the e-mail after commit (optionally @Async, or via an outbox table for guaranteed delivery). A daily @Scheduled job expires holds and passes the copy to the next reservation. borrow must then allow the holder to take the reserved copy and refuse others.

Exercise 10 🔴 hard mini-project · playground

Secure the API (Chapter 17): JWT resource server; SCOPE_library:admin may add books and see overdue loans; any authenticated member may borrow, but only for themselves (the JWT sub is the member's e-mail). List the changes and the tests you'd add.

Show solution

Add spring-boot-starter-security-oauth2-resource-server (+ -security-test). A SecurityFilterChain: POST /api/books and GET /api/loans/overdue → hasAuthority("SCOPE_library:admin"); /actuator/health/** → permitAll(); everything else authenticated(); stateless; resource server with issuer-uri. Change NewLoan to only carry the ISBN and resolve the member from @AuthenticationPrincipal Jwt (members.findByEmail(jwt.getSubject())) — the client can no longer borrow for someone else. Protect GET /api/members/{id}/loans with @PreAuthorize comparing the member's e-mail to authentication.name, or an admin scope. Tests: jwt() post-processors for admin vs member on each endpoint, 401 without a token, and 403 for a member reading someone else's loans; the integration test gets a @TestConfiguration JwtDecoder or uses MockMvc with jwt().
