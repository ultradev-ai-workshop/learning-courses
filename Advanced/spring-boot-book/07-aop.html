AOP & Proxies

@Transactional, @Cacheable, @Async, @PreAuthorize, @Retryable, @Validated — some of Spring's most useful features are one annotation. They all work the same way: Spring wraps your bean in a proxy that runs extra code around your methods. This chapter explains proxies and Aspect-Oriented Programming (AOP), shows you how to write your own aspects, and explains the classic trap that catches every Spring developer once: self-invocation.

You will learn

  • What a proxy is, and the difference between JDK dynamic proxies and CGLIB class proxies.
  • AOP vocabulary: aspect, join point, advice, pointcut, weaving.
  • Writing @Aspect classes with @Before, @Around, @AfterReturning, @AfterThrowing, @After.
  • The pointcut language: execution, within, @annotation, bean, args, combining with &&/||/!.
  • The limits of proxy-based AOP: self-invocation, private and final methods, and how to work around them.

What is a proxy?

A proxy is an object that stands in for another one. It has the same type, so callers can't tell the difference, and it forwards each call to the real object (the target) — doing something extra before, after or instead of it.

Spring creates proxies in a BeanPostProcessor (step 6 of the lifecycle in Chapter 3): the post-processor receives the finished bean and returns a proxy in its place. There are two kinds:

  • JDK dynamic proxy: implements the target's interfaces. Only interface methods can be intercepted, and you can't cast it to the class.
  • CGLIB proxy: a generated subclass of the target class, overriding its methods. Works without interfaces. Spring Boot uses CGLIB by default (spring.aop.proxy-target-class=true).

The pointcut language

Spring AOP uses AspectJ's pointcut syntax. The most common designators:

PointcutMatches
execution(public * *(..))any public method
execution(* com.shop.service.*.*(..))any method of a class directly in com.shop.service
execution(* com.shop..*Service.find*(Long, ..))find… methods of …Service classes anywhere under com.shop, first parameter Long
within(com.shop.web..*)every method of classes in that package tree
@annotation(com.shop.Audited)methods annotated @Audited
@within(org.springframework.stereotype.Service)methods of classes annotated @Service
bean(*Repository)beans whose name ends with Repository (Spring-specific)
args(String, ..)methods whose first runtime argument is a String

In execution(modifiers? return-type declaring-type? name(params) throws?), * matches one element, .. matches any number of parameters or sub-packages. Combine pointcuts with &&, || and !, and name them with @Pointcut to reuse them.

The self-invocation trap

A proxy only sees calls that go through it. When a method of the bean calls another method of the same bean, it calls this.method() — the target, not the proxy — so no advice runs:

The same thing silently breaks @Transactional, @Cacheable and @Async on internal calls. Ways out, best first:

  1. Restructure: move the advised method to another bean and inject it. Usually clearer anyway.
  2. Inject yourself lazily (ObjectProvider<Self> or @Lazy self-injection) as above.
  3. Use the programmatic API for that one spot — TransactionTemplate instead of @Transactional (Chapter 15).
  4. Use AspectJ weaving (compile- or load-time) instead of proxies — powerful but adds build complexity.

⚠️ Other things proxies can't intercept. private methods, final methods and static methods can't be overridden by a CGLIB subclass, so advice on them never runs — and no error tells you. Calls made in the constructor or in @PostConstruct run on the raw target before the proxy exists. Keep advised methods public (package-private works with CGLIB, but public is the convention).

Recap

  • A proxy stands in for a bean and intercepts calls. Boot uses CGLIB subclass proxies by default; JDK proxies only implement interfaces.
  • Aspect = advice + pointcut. Advice kinds: @Before, @AfterReturning, @AfterThrowing, @After, @Around (most powerful, use with care).
  • Pointcuts: execution(…), within(…), @annotation(…), bean(…), args(…), combined with && || !. Annotation-driven aspects are the most maintainable.
  • @Order: lowest value = outermost aspect.
  • Self-invocation, private/final/static methods and constructor calls bypass the proxy — for your aspects and for @Transactional, @Cacheable, @Async…

Exercises

Exercise 1 🟢 easy concept

Explain the difference between a JDK dynamic proxy and a CGLIB proxy. Which one does Spring Boot use by default, and what does that let you do?

Show solution

A JDK proxy implements the target's interfaces and can only intercept interface methods; it can't be cast to the concrete class. A CGLIB proxy is a runtime subclass that overrides the class's (non-final) methods. Boot defaults to CGLIB (spring.aop.proxy-target-class=true), so you can inject beans by their concrete class and advise classes that have no interface.

Exercise 2 🟢 easy concept

What does each pointcut match? (a) execution(* com.shop..*.delete*(..)) (b) within(com.shop.web.*) (c) @annotation(org.springframework.transaction.annotation.Transactional) (d) execution(String *(String))

Show solution

(a) Methods whose name starts with delete, any parameters, in any class in com.shop or its sub-packages. (b) All methods of classes directly in com.shop.web (not sub-packages; that would be com.shop.web..*). (c) Methods annotated @Transactional (not classes annotated with it — that's @within). (d) Any method returning String with exactly one String parameter.

Write an aspect that prints calling <method> before every public method of a Greeter service.

Exercise 4 🟢 easy predict

A @Service has @Cacheable("prices") public Price price(String sku) and public List<Price> prices(List<String> skus) which calls price(sku) in a loop. Calling prices(...) twice with the same SKUs hits the database how many times per SKU?

Show solution

Twice — once per call — because prices() calls price() on this, bypassing the caching proxy. Only external calls to price() are cached. Fix: move price() to a separate bean (e.g. PriceLookup) or use a self-reference through the proxy.

Exercise 5 🟡 medium code

Create an @Around aspect for methods annotated @Masked that replaces every digit in a String return value with *, except the last 4 characters. Apply it to String cardNumber() returning "4111111111111111".

Show solution

Changing a return value is only possible with @Around. @AfterReturning can see the result but not replace it.

Exercise 6 🟡 medium code

Write an aspect that counts exceptions per exception class thrown by any method in a package, using @AfterThrowing. Trigger an IllegalArgumentException twice and an IllegalStateException once, then print the counts.

Show solution

Declaring the advice parameter as RuntimeException also filters: only exceptions of that type trigger it. The exception still reaches the caller — @AfterThrowing observes, it doesn't handle.

Exercise 7 🟡 medium debug

An aspect on @Audited methods works for public void approve() but never runs for @Audited private void notifyManager() or @Audited public final void archive(). No error is reported. Explain each case.

Show solution

A CGLIB proxy is a subclass that intercepts by overriding methods. private methods aren't inherited, and final methods can't be overridden, so the proxy can't intercept either — and calls to them from other methods of the class are self-invocations anyway. Make advised methods public and non-final, and call them from another bean.

Exercise 9 🔴 hard code

Implement a @RateLimited(perSecond = 2) aspect: per annotated method, allow at most N calls in the current second and throw IllegalStateException("rate limit exceeded") otherwise. Call the method 3 times quickly and print the outcomes.

Show solution

ConcurrentHashMap.compute makes the read-modify-write atomic per key. A fixed one-second window is the simplest algorithm; token buckets (as in Bucket4j or Resilience4j) give smoother limits. Spring Framework 7 also ships @ConcurrencyLimit, which limits concurrent calls rather than calls per second.

Exercise 10 🔴 hard mini-project · playground

Build an audit trail: an @Audited(action = "…") annotation; an aspect that, after a successful call, records action, the method's first argument and the current user (from a CurrentUser bean holding a name) into an AuditTrail bean (a thread-safe list). Failed calls are recorded with FAILED. Annotate approve(String invoiceId) and reject(String invoiceId) (which throws for ids starting with X), run a few calls and print the trail.

Show solution
