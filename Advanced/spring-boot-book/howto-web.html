Solution

  • The Exception catch-all also catches Spring Security's AccessDeniedException if it reaches MVC — rethrow it or map it to 403 explicitly.

Paginate and sort a list endpoint

GET /books returns 50 000 rows. Clients need ?page=2&size=20&sort=title,desc, with limits.

PageableSpring Data web supportChapter 14

Solution

Accept a Pageable parameter — Spring Data binds page, size and sort — and return a stable JSON shape with PagedModel. Boot configures all of it with spring.data.web.pageable.* properties:

Pitfalls

  • Sorting by arbitrary client input can sort by unindexed columns (slow) or leak field names; restrict allowed sort properties if the table is large.
  • Deep pages (page=5000) are slow with OFFSET; offer keyset/"after id" pagination or Slice for infinite scrolling.
  • Don't add @EnableSpringDataWebSupport yourself: it makes Boot's auto-configuration back off, and spring.data.web.* settings such as max-page-size are silently ignored (the limit falls back to 2000).
  • Don't return PageImpl directly — its JSON structure isn't a stable API (Spring Data warns about it at runtime).

Log every request with its duration

Operations wants one log line per request: method, path, status and time — including 404s.

OncePerRequestFilterMDCChapters 10, 18

Solution

A filter sees every request, including those no controller handles. (For metrics, prefer the automatic http.server.requests timer; this is for logs.)

(The ... stands for Spring's own warning about the missing resource.) Tomcat can also write a classic access log file: server.tomcat.accesslog.enabled=true.

Pitfalls

  • Don't log request or response bodies by default — they contain personal data and passwords. If you must, mask fields and limit size.
  • With tracing enabled (Chapter 18), the trace id is in the MDC and appears in each line, linking access logs to traces.

Adjust JSON output (dates, nulls, naming)

The frontend wants snake_case, no null fields and dates without time; one field needs a custom format.

spring.jackson.*Jackson 3Chapters 5, 9

Solution

Global settings as properties; per-field annotations for exceptions:

Jackson 3 writes dates as ISO strings by default (no more WRITE_DATES_AS_TIMESTAMPS to switch off). For anything properties can't express, add a JsonMapperBuilderCustomizer bean (Chapter 5).

Pitfalls

  • Changing naming strategy globally changes every API at once — coordinate with all clients, or apply it per DTO with @JsonNaming.
  • Use Instant/OffsetDateTime for points in time; LocalDateTime has no zone and is ambiguous across systems.

Version the API in the URL path

You need /api/v1/… and /api/v2/… side by side, without copying every controller.

API versioningSpring 7Chapter 9

Solution

Tell Spring which path segment holds the version and declare versions on mappings; unchanged endpoints use a baseline version ("1+") and serve every later version too:

Pitfalls

  • Version only when you must break clients; additive changes (new optional fields, new endpoints) don't need a new version.
  • Announce removals: Spring can add Deprecation/Sunset headers for old versions — and monitor which versions clients still call.
