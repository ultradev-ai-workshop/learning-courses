Chapter 6 · Core Framework

Validation, Conversion & SpEL

Data enters your application as strings and maps — from HTTP requests, configuration, message queues — and must become valid, typed Java objects. Spring's core gives you three tools for that: Bean Validation to check objects, the conversion service to turn strings into types and back, and the Spring Expression Language (SpEL) for small dynamic expressions in annotations and configuration.

You will learn

  • Bean Validation with Hibernate Validator: built-in constraints, messages, nested @Valid, groups.
  • Custom constraints with ConstraintValidator, and class-level (cross-field) rules.
  • Method validation with @Validated: checking parameters and return values of any bean.
  • Type conversion: Converter, Formatter, @DateTimeFormat and the ConversionService.
  • SpEL: property access, operators, collection selection/projection, safe navigation, and why untrusted input needs SimpleEvaluationContext.

Bean Validation

Jakarta Bean Validation is a standard: you put constraint annotations on fields (or record components), and a validator checks an object against them. Spring Boot's spring-boot-starter-validation brings Hibernate Validator, the reference implementation, and auto-configures a Validator bean that you can inject.

Validation doesn't stop at the first problem: you get every violation at once, which is what a form or API client needs. The most-used constraints:

ConstraintChecks
@NotNull, @NotEmpty, @NotBlanknot null / not null and not empty (strings, collections) / not null and has a non-whitespace character
@Size(min, max)length of a string, size of a collection/map/array
@Min, @Max, @Positive, @PositiveOrZero, @DecimalMin, @Digitsnumeric ranges and precision
@Email, @Pattern(regexp)e-mail shape, regular expression
@Past, @Future, @PastOrPresentdates and times relative to now
@AssertTrue, @AssertFalsea boolean (or an isXxx() method — useful for cross-field rules)
@Validnot a constraint: cascade validation into a nested object or collection elements

⚠️ Most constraints accept null. @Size, @Email, @Min and @Pattern all treat null as valid — the idea is that "required" is a separate decision. If a field is required, add @NotNull (or @NotBlank for strings) as well.

Method validation

Put @Validated on a class and Spring wraps the bean in a proxy that validates method parameters and return values annotated with constraints. A violation throws ConstraintViolationException before the method body runs:

The paths use the real parameter names (customer, priority): Spring's validator reads them from the class files, which Boot's build compiles with -parameters. Method validation is a proxy (Chapter 7), so — like @Transactional — it only applies to calls coming from outside the bean.

💡 Where to validate. Validate at the boundaries: incoming HTTP requests (Chapter 10), configuration properties (Chapter 4), messages from queues. Method validation on services is a safety net for invariants that must hold no matter who calls.

Type conversion and formatting

Spring constantly converts strings to types: @Value("${timeout}") Duration, @RequestParam LocalDate date, @PathVariable UUID id. All of that goes through a ConversionService, which you can extend with your own Converter<S, T> (one direction) or Formatter<T> (print and parse, locale-aware).

To use a converter in the application, declare it as a bean. Where it applies:

  • Spring MVC and WebFlux add every Converter, GenericConverter and Formatter bean to their conversion service (request parameters, path variables, headers).
  • @ConfigurationProperties binding uses converter beans that are also annotated with @ConfigurationPropertiesBinding.
  • @Value uses the shared ApplicationConversionService and does not see your converter beans — another reason to bind custom types with @ConfigurationProperties.

The Spring Expression Language (SpEL)

SpEL is a small expression language for querying and manipulating objects at runtime. You've already used it in @Value("#{…}"); it also powers @Cacheable(key = "#id"), @PreAuthorize("hasRole('ADMIN')"), @ConditionalOnExpression and @EventListener(condition = …). You can also evaluate it directly:

Record components are read through their accessor methods (name()), so name works on records as well as on JavaBeans. Note the floating-point result: SpEL uses Java arithmetic, so money calculations should use BigDecimal here too.

⚠️ Never evaluate user input with StandardEvaluationContext. It allows T(java.lang.Runtime).getRuntime().exec(…) — remote code execution. If an expression comes from outside (a filter in a URL, a rule in a database), use SimpleEvaluationContext.forReadOnlyDataBinding(), which only allows property access and simple operators, no types, constructors or bean references.

Recap

  • Bean Validation: annotate, then validator.validate(obj) returns all violations with property paths. Most constraints accept null; add @NotNull/@NotBlank for required fields.
  • @Valid cascades into nested objects and container elements (List<@Valid Line>). Custom rules: annotation + ConstraintValidator; class-level constraints for cross-field rules.
  • @Validated on a bean validates method parameters and return values through a proxy (ConstraintViolationException).
  • ConversionService turns strings into types. Converter/Formatter beans apply to Spring MVC, and to @ConfigurationProperties with @ConfigurationPropertiesBinding — not to @Value. @DateTimeFormat/@NumberFormat per field.
  • SpEL: .?[] selection, .![] projection, ?., ?:, T(), @bean. Never evaluate untrusted input with StandardEvaluationContext.

Exercises

Exercise 1 🟢 easy predict

Which of these values pass @Size(min = 3) String code? null, "", "ab", "abc", " ".

Show solution

null passes (most constraints treat null as valid), "abc" passes, and " " passes (three characters, even if they're spaces). "" and "ab" fail. For "required and meaningful" use @NotBlank @Size(min = 3).

Exercise 2 🟢 easy code

Validate a record Temperature(@DecimalMin("-90.0") @DecimalMax("60.0") double celsius) for 25 and 75, and print the number of violations for each.

Show solution

You don't need Spring to validate: Validation.buildDefaultValidatorFactory() is plain Jakarta Validation. In a Spring app, inject the Validator bean instead.

Exercise 3 🟢 easy code

Use a SpEL projection to turn the inline list {3, 4, 5} into its squares, then sum the result in Java. Print both.

Show solution

SpEL is meant for small expressions; when you need loops and aggregation, do it in Java.

Exercise 4 🟢 easy concept

A @Validated service method save(@Valid Order order) is called from another method of the same class with an invalid order. Is it validated? Why?

Show solution

No. Method validation is applied by a proxy around the bean. A call from inside the class (this.save(…)) doesn't go through the proxy, so no validation happens. The same "self-invocation" rule applies to @Transactional, @Cacheable and @Async (Chapter 7).

Exercise 5 🟡 medium code

Write a @NoProfanity constraint for strings that rejects text containing any word from a fixed list (darn, heck), case-insensitively. Test it on "What the HECK" and "Hello".

Show solution

Outside Spring, Hibernate Validator creates validators reflectively, so the validator must be a public class with a public no-argument constructor (here a public nested class). Inside a Spring application, validators are created by Spring and may be package-private and even have constructor-injected dependencies.

Exercise 6 🟡 medium code

Write a Converter<String, Range> for strings like "10..20" (record Range(int from, int to)), register it as a bean, and bind it in @ConfigurationProperties("app") record AppProperties(@DefaultValue("1..5") Range allowed). Print it with and without --app.allowed=10..20.

Show solution

The @DefaultValue string goes through the same converter as a real property value.

Exercise 7 🟡 medium code

Using SpEL and a list of Employee(String name, String dept, int salary), select the names of employees in eng earning over 100000, and find the first employee in ops (or none with Elvis).

Show solution

When the root object is itself a collection, selection works directly on it: ?[…] without a property in front.

Make a @Validated service Transfers with String transfer(@NotBlank String from, @NotBlank String to, @Positive BigDecimal amount). Call it with ("A", " ", -5) and print the number of violations and their messages, sorted.

Exercise 9 🔴 hard code

Write a safe rule engine: rules are SpEL strings stored as data, each mapped to a tag — total > 100 → FREE_SHIPPING, itemCount >= 3 → BULK, country == 'DE' → EU_VAT. Rules may only read properties (no method calls). Evaluate all rules against a Cart(double total, int itemCount, String country) with SimpleEvaluationContext, print the matching tags, and show that a malicious rule T(java.lang.System).exit(1) is rejected.

Show solution

Property access on records works in read-only data binding (it calls the accessor). For more power without danger, SimpleEvaluationContext.forReadOnlyDataBinding().withInstanceMethods() also allows method calls on the root object's data — but still no types or constructors.

Exercise 10 🔴 hard mini-project · playground

Build a CSV importer that turns lines like Dune;412;1965-08-01 into validated Book(@NotBlank String title, @Positive int pages, @PastOrPresent LocalDate published) records. Convert fields with the ConversionService, validate each record, and print line N: ok or line N: field message for the input lines Dune;412;1965-08-01, ;100;2000-01-01, Future;10;2999-01-01, Bad;x;2000-01-01.

Show solution

Two stages, two kinds of error: conversion errors (the text isn't a number at all) and validation errors (it's a number, but not an acceptable one). Spring MVC reports both the same way through BindingResult — Chapter 10.
