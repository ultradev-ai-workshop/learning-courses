Appendix B

Spring Boot 3 → 4 & Cheat Sheet

Spring Boot 4 (with Spring Framework 7) is a major release: modular auto-configuration, Jackson 3, JSpecify null-safety, new testing defaults and a handful of removals. This appendix is a practical upgrade guide — what changes, in which order to tackle it — followed by a one-page cheat sheet of the annotations, properties and commands used throughout the book.

You will learn

  • A safe upgrade path from Boot 3.x to 4.x.
  • Modular starters and renamed artifacts, and the "classic" starters as a stepping stone.
  • The Jackson 3 move (tools.jackson) and what stays the same.
  • Testing changes: @MockitoBean, @AutoConfigureMockMvc, RestTestClient, per-technology test starters.
  • Removed and renamed features, and a cheat sheet for daily work.

The upgrade path

  1. Upgrade to the latest Boot 3.5.x first and fix every deprecation warning — Boot 4 removes what 3.x deprecated.
  2. Java 17+ (Boot 4's minimum); Java 21 or 25 recommended. Upgrade the JDK separately from Boot if you can.
  3. Switch the parent to 4.x and, if the build breaks badly, temporarily use spring-boot-starter-classic / spring-boot-starter-test-classic (all auto-configuration modules, like Boot 3).
  4. Rename starters (table below), move Jackson code to Jackson 3, fix tests.
  5. Run the properties migrator (spring-boot-properties-migrator, runtime scope) once: it logs renamed/removed properties at startup and temporarily maps them. Remove it afterwards.
  6. Replace "classic" starters with the specific ones you actually use.

💡 OpenRewrite has recipes (org.openrewrite.java.spring.boot4.UpgradeSpringBoot_4_0) that automate many of these mechanical changes — run them on a branch and review the diff.

🧠 Analogy: moving house. Before the move you throw away what you no longer use (fix deprecations on 3.5). On moving day, everything goes into a few big boxes labelled "kitchen stuff" (the classic starters) so you can live in the new place immediately. Then, room by room, you unpack into the right cupboards (specific starters) and throw the big boxes away.

Auto-configuration classes and some annotations moved packages accordingly, e.g. @EntityScan is now in org.springframework.boot.persistence.autoconfigure, HealthIndicator in org.springframework.boot.health.contributor, @WebMvcTest in org.springframework.boot.webmvc.test.autoconfigure, and EnvironmentPostProcessor in org.springframework.boot.

Jackson 3

Boot 4 uses Jackson 3. The group id and Java packages changed from com.fasterxml.jackson to tools.jackson — except the annotations, which stay in com.fasterxml.jackson.annotation. Other notable changes: JsonMapper (built with a builder, immutable) replaces configuring an ObjectMapper in place; exceptions are unchecked; Java time support is built in; dates are written as ISO strings by default.

Boot-side renames: Jackson2ObjectMapperBuilderCustomizer → JsonMapperBuilderCustomizer; @JsonComponent → @JacksonComponent; spring.jackson.read.*/write.* → spring.jackson.json.read.*/json.write.*. If a library still needs Jackson 2, it can coexist (different packages), but Spring MVC uses Jackson 3.

Other notable changes

  • Null safety: Spring's APIs are annotated with JSpecify (org.jspecify.annotations.Nullable) instead of Spring's own @Nullable. Kotlin and tools like NullAway understand them; use them in your own code too.
  • HTTP service clients are auto-configured (@ImportHttpServices, spring.http.serviceclient.*), and HTTP client settings moved to spring.http.clients.* (Chapter 11).
  • Retry and concurrency limits moved into Spring Framework (@Retryable, @ConcurrencyLimit, @EnableResilientMethods); Spring Retry is in maintenance.
  • API versioning is built into Spring MVC/WebFlux (spring.mvc.apiversion.*, Chapter 9).
  • Liveness and readiness health groups are enabled by default; graceful shutdown is the default.
  • Spring Security 7: the lambda DSL only (and() chaining is gone), PathPatternRequestMatcher by default, authorization factors (FACTOR_* authorities) for MFA.
  • Hibernate 7 / JPA 3.2, Jakarta EE 11 (Servlet 6.1, Bean Validation 3.1), Tomcat 11, Jetty 12.1.
  • Executable "fully executable" launch scripts in jars and some deprecated properties are gone; spring-boot-properties-migrator reports the latter.

Recap

  • Path: Boot 3.5 without deprecations → Java 17+ → Boot 4 (classic starters if needed) → rename starters, Jackson 3, tests → properties migrator → specific starters.
  • Starter renames: -web→-webmvc, -aop→-aspectj, security-oauth2-*, explicit -flyway/-liquibase/-restclient, per-technology -test starters; Undertow removed.
  • Jackson 3: tools.jackson packages (annotations unchanged), immutable JsonMapper, unchecked exceptions, JsonMapperBuilderCustomizer, @JacksonComponent.
  • Tests: @MockitoBean/@MockitoSpyBean, @AutoConfigureMockMvc/@AutoConfigureTestRestTemplate explicitly, RestTestClient, JUnit 6.
  • New in Framework 7/Boot 4: JSpecify, HTTP service clients, core retry, API versioning, probes and graceful shutdown on by default.

Exercises

Exercise 1 🟢 easy concept

Why should you upgrade to the latest Boot 3.5.x and remove deprecation warnings before moving to 4.0?

Show solution

Boot 4 removes APIs and properties deprecated in 3.x. On 3.5 the old and new ways coexist, so you can migrate each warning with a compiling, running application and a small diff. Jumping directly turns every deprecation into a compile or startup error at once.

Exercise 2 🟢 easy concept

After upgrading, import com.fasterxml.jackson.databind.ObjectMapper; no longer compiles, but import com.fasterxml.jackson.annotation.JsonIgnore; does. Explain.

Show solution

Jackson 3 moved its core and databind packages to tools.jackson.* (and a new group id), while the annotations module kept com.fasterxml.jackson.annotation so annotated model classes stay compatible with both versions. Replace ObjectMapper usage with tools.jackson.databind.json.JsonMapper (injected from Boot).

Exercise 3 🟢 easy concept

A test class with @SpringBootTest and @Autowired MockMvc mvc fails after the upgrade with "No qualifying bean of type MockMvc". Fix it.

Show solution

Add @AutoConfigureMockMvc to the class (from org.springframework.boot.webmvc.test.autoconfigure) and make sure spring-boot-starter-webmvc-test is a test dependency. Boot 4 no longer configures MockMvc for every @SpringBootTest.

Exercise 4 🟢 easy concept

Your Boot 3 app used flyway-core only, and migrations ran at startup. After upgrading, they don't run and Hibernate's validate fails. Why?

Show solution

Flyway's auto-configuration moved into its own module, brought in by spring-boot-starter-flyway. With just the library, nothing configures and runs Flyway. Replace flyway-core with the starter (keep the database-specific Flyway module, e.g. flyway-database-postgresql).

Exercise 5 🟡 medium code

Migrate this Boot 3 test fragment: @MockBean PriceService prices; with @SpringBootTest(webEnvironment = RANDOM_PORT) and an injected TestRestTemplate. Write the Boot 4 version using RestTestClient.

Show solution

Add spring-boot-resttestclient (test scope). If you prefer to keep TestRestTemplate, add @AutoConfigureTestRestTemplate instead.

Exercise 6 🟡 medium concept

Your application uses Spring Retry's @Retryable(maxAttempts = 3, backoff = @Backoff(delay = 100, multiplier = 2)) with @EnableRetry. Translate it to Spring Framework 7.

Show solution

@EnableResilientMethods on a configuration class, and @Retryable(maxRetries = 2, delay = 100, multiplier = 2) from org.springframework.resilience.annotation. Note the semantics: Spring Retry's maxAttempts = 3 counts the first call; Framework 7's maxRetries = 2 counts only retries — both mean three calls in total. Use includes/excludes for exception filtering; @Recover has no direct equivalent — catch the exception in the caller for a fallback.

Write a JsonMapperBuilderCustomizer that makes the application's mapper write property names in snake_case, and show it on a record.

Exercise 8 🟡 medium concept

Your Boot 3 security configuration ends with .and().httpBasic().and().csrf().disable(). Rewrite it for Spring Security 7.

Show solution

Use the lambda DSL: http.authorizeHttpRequests(a -> a.anyRequest().authenticated()).httpBasic(Customizer.withDefaults()).csrf(c -> c.disable()); — each section is configured in its own lambda, and and() no longer exists. Also replace antMatchers/mvcMatchers (removed earlier) with requestMatchers.

Exercise 9 🔴 hard design

Plan the upgrade of a 40-module Boot 3.2 system with Undertow, Jackson 2 custom serializers, Spring Retry and 600 tests using @MockBean. Order the work into reviewable steps.

Show solution

(1) Upgrade to Boot 3.5.x; fix deprecations module by module. (2) Switch Undertow → Tomcat (or Jetty) on 3.5 — behavioural changes (thread pools, timeouts) are easier to test before the major upgrade. (3) Replace @MockBean with @MockitoBean (available since Framework 6.2 / Boot 3.4) — mechanical, can run via OpenRewrite. (4) Move Spring Retry to Framework 7 later, or keep it temporarily (it still works). (5) Upgrade the JDK if needed. (6) Boot 4 with classic starters; get everything green. (7) Jackson 3: migrate serializers (tools.jackson, ValueSerializer), using @JacksonComponent; contract tests on JSON output catch accidental changes. (8) Fix tests for @AutoConfigureMockMvc etc. (9) Properties migrator, then remove. (10) Replace classic starters with specific ones per module. Each step: separate PR, full test run, staging deployment.

Exercise 10 🔴 hard mini-project · playground

Take a Boot 3 pom.xml with spring-boot-starter-web, -aop, -oauth2-resource-server, flyway-core, spring-boot-starter-test, and rewrite the dependency list for Boot 4 — including test starters for MVC, JPA and security.

Show solution

Each -test starter brings spring-boot-starter-test plus its slice, so a separate spring-boot-starter-test line is no longer necessary.
