Formatted string literals (f-strings)

Put an f before the opening quote, and write any Python expression inside { }. The expression is evaluated and its value inserted. This is the modern, preferred way to build strings.

🟨 JS: f-strings are template literals, `${x}`. ☕ Java: they replace String.format("%d items", n) and + chains.

The format specifier: {value:spec}

After a colon you can add a format specifier that controls how the value looks. The general shape is [fill][align][width][,][.precision][type].

Conversions !r and !s, and the = debugging specifier

!r uses repr() (see below), which shows quotes around strings, and !s uses str(). A trailing = prints the expression text and its value, which is perfect for quick debugging.

💡 Tip: since Python 3.12 you can reuse the same quote type inside an f-string expression: f"{d["key"]}" works. To write a literal brace, double it: f"{{not a field}}".

str() vs repr()

str(x) gives a readable form for humans, and print() uses it. repr(x) gives an unambiguous form for developers, often valid Python, and the REPL uses it to echo values.

Template strings (t-strings)

Python 3.14 added template strings, written with a t prefix (PEP 750). They look like f-strings, but they don't produce a str. They produce a Template object that keeps the text parts and the values separate. Libraries use them to process the values safely, for example to escape HTML or SQL, before joining everything together.

You won't write t-strings often as a beginner, but you'll meet them in web and database libraries. For everyday output, use f-strings.

The str.format() method

Before f-strings (3.6), people used str.format(). It is still useful when the template is stored separately from the values, for example in a config file or a translation table.

Format specs after the colon work exactly as in f-strings.

Manual string formatting

String methods can pad text to a width: rjust(), ljust(), center() and zfill(). They never cut a string that is too long.

Old string formatting (%)

📝 Older syntax you'll still see: the % operator, similar to C's printf. It is common in older code and in the logging module (Chapter 14). Don't use it in new code.

Reading from the keyboard: input()

input(prompt) shows the prompt, waits for the user to press Enter, and returns what they typed as a string, without the newline. Convert it yourself if you need a number.

Reading and writing files

open(filename, mode, encoding=...) returns a file object. Always open files in a with block. It closes the file automatically when the block ends, even if an error happens inside.

Analogy: with is a door that closes itself behind you, whatever way you leave the room.

⚠️ Pitfall: the encoding. Since 3.15, text files default to UTF-8 on every system (PEP 686). Older Pythons used the system's locale encoding, which on Windows was often cp1252, and your code may still run on those versions. Writing encoding="utf-8" explicitly makes your code portable and clear. In binary mode ('rb'), don't pass an encoding at all.

💡 Tip: the pathlib module (Chapter 13) has handy shortcuts: Path("a.txt").read_text(encoding="utf-8") and Path("a.txt").write_text(s, encoding="utf-8").

Saving structured data with json

Writing numbers and lists as text by hand gets messy fast. JSON (JavaScript Object Notation) is the standard text format for data exchange, and the json module converts between Python objects and JSON text.

  • json.dumps(obj) → a JSON string. json.loads(s) → a Python object. (The s stands for string.)
  • json.dump(obj, f) → writes to a file. json.load(f) → reads from a file.
PythonJSONBack to Python
dictobject {}dict
list, tuplearray []list (a tuple comes back as a list!)
strstringstr
int, floatnumberint / float
True / Falsetrue / falseTrue / False
NonenullNone

⚠️ Pitfalls: JSON object keys are always strings, so {1: "a"} comes back as {"1": "a"}. Sets, dates and your own classes can't be serialised directly (you get a TypeError); convert them to lists, strings or dicts first.

❌ Never unpickle untrusted data. The pickle module can save almost any Python object, but loading a pickle can run arbitrary code. Use JSON for data that comes from outside your program.

Recap

  • f-strings use f"{expr:spec}": .2f, width, < > ^, ,, %, !r, and {x=} for debugging.
  • str() is for people and repr() is for developers. str.format suits stored templates; % is legacy. t-strings (3.14) build Template objects for libraries.
  • Use with open(path, mode, encoding="utf-8") as f:. Mode 'w' erases the file, 'a' appends, 'x' refuses to overwrite.
  • Loop over a file to read it line by line. write() doesn't add newlines.
  • json.dump/load work with files and dumps/loads with strings. Tuples become lists and keys become strings. Never unpickle untrusted data.
