Using the Python Playground

The playground/ folder is your workbench: you type every example and exercise there, run it, break it, and fix it. This page shows you how to set it up once and how to work in it every day.

You will learn

  • What the playground is and what it already contains.
  • How to open it in an editor and a terminal, and set up a virtual environment.
  • The everyday loop: create a file, run it, experiment in the REPL, fix it.
  • Which chapter adds which files, and how they grow into the Chapter 16 project.
  • How to run tests, compare with the reference solution, and fix common problems.

What is the playground?

It's a plain folder next to this book. Nothing in it is magic: it's just where your practice files live. Exercises marked playground in each chapter tell you which file to create there.

💡 Rule of thumb: one file per exercise, named exactly as the exercise says. Later chapters import earlier files (for example, Chapter 15's tests import money.py), so matching names matters.

One-time setup (10 minutes)

1. Check Python 3.15

If you see an older version, or "command not found", follow Chapter 1: Installing Python 3.15. With uv you can also run uv python install 3.15 and then use python3.15 wherever this book writes python3.

2. Open the folder in an editor and a terminal

Any editor works. With VS Code:

  • Install the official Python extension (by Microsoft). It gives you syntax checking, autocompletion and a Run button.
  • Open the built-in terminal with Ctrl+`. It starts in the playground folder, which is exactly where you want to run commands.
  • Set the editor to 4 spaces for indentation (VS Code does this for .py files by default).

3. Create a virtual environment (recommended)

You won't need third-party packages until Chapter 15, but making the venv now means every command uses the same Python. (Chapter 15 explains venvs fully.)

In VS Code, run the command Python: Select Interpreter (Ctrl/Cmd+Shift+P) and pick the one in .venv. New terminals then activate it automatically.

⚠️ Activate it in every new terminal (or let VS Code do it). If the prompt doesn't start with (.venv), you're using the system Python.

The everyday loop

Every exercise follows the same four steps.

1. Create the file

2. Run it from the playground folder

3. Experiment in the REPL

When you're unsure what something does, try it in the interactive prompt before writing it in a file. python3 -i file.py runs your file first and then leaves you in the REPL with all its variables, which is perfect for poking at your own code.

4. Compare with the solution, then improve

Open the exercise's Show solution only after you have something running. If yours works differently, that's fine: read the "why it works" sentence and decide which version you prefer.

💡 Read errors from the bottom. The last line of a traceback names the problem. The line above it shows your code (Chapter 1 and Chapter 10).

Running packages and multi-file code

From Chapter 8 on, some files import others. Two rules prevent almost every import problem:

  1. Run commands from the playground/ folder, which is the folder that contains your modules and packages.
  2. Run a package with -m, using dots, not slashes: python3 -m tracker, not python3 tracker/__main__.py.

✅ Works

⚠️ Never name your files after standard modules (random.py, json.py, csv.py, email.py). Python would import your file instead of the real module (Chapter 8). If it happens, rename the file and delete its __pycache__ entry.

Cleaning up

  • __pycache__/ folders are Python's caches (Chapter 8). They're safe to delete at any time: find . -name __pycache__ -prune -exec rm -rf {} +
  • Data files that exercises create (expenses.json, demo.json, *.csv, *.log) can be deleted too; the scripts recreate them.
  • A broken venv? Delete .venv/ and create it again; it's disposable.

Recap

  • playground/ is your workbench; playground/reference/ is the finished project to compare against.
  • Set it up once: Python 3.15, open the folder in your editor, and create and activate .venv.
  • The loop: create the file the exercise names → python3 file.py → experiment with python3 -i → compare with the solution.
  • Always run from playground/, and run packages with python3 -m name.
  • Test with doctest, unittest or pytest, and delete caches and data files freely.
