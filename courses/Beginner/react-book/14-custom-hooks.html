Custom Hooks

When several components need the same stateful logic, package it into your own Hook: a function whose name starts with use.

The naming rule

  • Components start with a capital letter and return JSX: StatusBar.
  • Hooks start with use + a capital letter, and can return anything: useOnlineStatus.

The name use… tells you, and the linter, that the function calls other Hooks, so the Rules of Hooks apply: call it only at the top level of a component or another Hook.

Don't prefix plain functions with use If a function doesn't call any Hooks, it's just a normal function. Name it getSorted(), not useSorted().

Hooks share logic, not state

This is the key point. Every call to a Hook is completely independent:

It's as if you'd written two useState calls yourself. To share state between components, you still lift it up or use context (Chapters 9 and 11).

Passing reactive values to Hooks

The code inside a custom Hook re-runs on every render of the component that uses it, so it always gets the latest props and state:

A useful example: useLocalStorage

Lazy initial state useState(() => ...) runs the function only on the first render. Use it when computing the initial value is expensive, like reading localStorage.

When should you write a custom Hook?

  • When you notice the same Effect or state logic in several components.
  • When an Effect is complicated and a good name would make the component clearer: useChatRoom(roomId) is easier to read than 20 lines of Effect.
  • Keep Hooks focused on one concrete purpose. Avoid generic "lifecycle" Hooks like useMount(fn), because they hide dependencies.
A bonus of custom Hooks Wrapping Effects in Hooks makes it easier to switch later to a better built-in solution or library. You only change the inside of the Hook, not every component.

Recap

  • A custom Hook is a function named useSomething that calls other Hooks.
  • It shares stateful logic. Each call has its own independent state.
  • It re-runs with the component, so it always sees the latest props and state.
  • Extract one when logic repeats, or when a name would make an Effect clearer.
