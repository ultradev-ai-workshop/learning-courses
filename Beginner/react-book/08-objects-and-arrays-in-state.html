Objects & Arrays in State

To update an object or array in state, you don't change it: you create a new copy with the changes and set that.

You will learn
  • What "mutation" is, and why React needs you to avoid it
  • How to copy and update objects with the spread syntax ...
  • How to update nested objects
  • How to add, remove, change, insert and sort array items without mutating

The golden rule: treat state as read-only

Numbers and strings can't be changed in place anyway: you always replace them (setX(5)). Objects and arrays can be changed in place. That's called mutation:

React decides whether to re-render by checking whether you gave it a new object. If you mutate the old one and pass it back, React sees "same object as before" and may skip the update. Mutation also breaks the "snapshot" idea from Chapter 7, because old renders would see the changed data.

The fix: create a new object and pass it to the setter.

Recap

  • Treat objects and arrays in state as read-only. Make a new one and set it.
  • Objects: { ...obj, field: newValue }. Copy each nested level you change.
  • Arrays: add with [...arr, x], remove with filter, change with map, insert with slice, sort with toSorted.
  • Spread is shallow. When you change an item inside an array, copy that item too.
  • For deeply nested state, consider Immer or flattening it.
