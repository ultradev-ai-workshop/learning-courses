Step 1: break the UI into a component hierarchy

Draw boxes around every part of the mockup and give each one a name. A good rule is the single responsibility principle: each component should ideally do one thing.

Step 2: build a static version

First build a version that renders the data but has no interactivity. Use only props, no state yet. Static versions need lots of typing but little thinking; interactivity needs lots of thinking but little typing. Doing them separately makes both easier.

Data flows one way: from the top-level component down through props. This is called one-way data flow.

Step 3: find the minimal but complete state

List every piece of data in the app, then ask three questions about each:

  1. Does it stay the same over time? Then it's not state.
  2. Is it passed in from a parent as a prop? Then it's not state.
  3. Can you calculate it from existing state or props? Then it's definitely not state.
DataIs it state?
The original list of products❌ It's passed in as a prop
The search text the user typed✅ Yes: it changes and can't be calculated
The value of the checkbox✅ Yes: it changes and can't be calculated
The filtered list of products❌ It can be calculated from the products, the search text and the checkbox

So there are only two pieces of state: filterText and inStockOnly.

Step 4: identify where the state should live

For each piece of state:

  1. Find every component that uses it. ProductTable needs it to filter, and SearchBar needs it to show the current values.
  2. Find their closest common parent: FilterableProductTable.
  3. Put the state there.

The inputs are now read-only! If you try typing now, nothing happens. <input value={filterText} /> is controlled by state, and nothing updates that state yet. Step 5 fixes it.

The finished app

The five steps, for any feature

  1. Break the UI into components, one responsibility each.
  2. Build a static version with props only.
  3. Find the minimal state: it changes, isn't passed in, and can't be calculated.
  4. Put the state in the closest common parent of the components that use it.
  5. Add inverse data flow: pass setters or handlers down so children can request changes.
