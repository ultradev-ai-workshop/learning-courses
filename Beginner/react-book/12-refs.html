Chapter 12 · Escape Hatches

Refs

A ref is a "secret pocket" where a component keeps a value that doesn't affect what's on screen. Refs are also how you reach real DOM elements.

You will learn
  • How useRef works, and how it differs from state
  • When to use a ref, for example to store a timer ID
  • How to access DOM elements (focus, scroll)
  • How to pass a ref to your own component
What's an "escape hatch"? Most of the time React handles everything for you. Escape hatches are tools for stepping outside React: talking to the browser directly, or to other systems. Use them only when you need to, because most code shouldn't need them.

Adding a ref

useRef(0) returns an object like { current: 0 }. You can read and change ref.current freely. React keeps the same object between renders, but changing it does not cause a re-render.

Example: a stopwatch

A stopwatch needs both: the times are shown on screen (so they're state), but the interval ID is only needed to stop the timer (so it's a ref).

Rule of thumb If it's shown on screen, use state. If it's just remembered behind the scenes, use a ref.
Don't read or write ref.current during rendering Use refs in event handlers and effects. Reading a ref while rendering makes your component unpredictable, because React doesn't know when it changes. The one exception is lazily setting it once: if (!ref.current) ref.current = new Thing().

Manipulating the DOM with refs

React updates the DOM for you, but sometimes you need the real element: to focus an input, scroll to something, or measure its size.

Focusing an input

  1. Create the ref: useRef(null).
  2. Attach it: <input ref={inputRef} />. React puts the DOM element into inputRef.current after the commit.
  3. Use it in an event handler: inputRef.current.focus().

Recap

  • useRef(initial) gives a { current } box that survives re-renders and doesn't trigger them.
  • Use refs for timer IDs, DOM elements and other "behind the scenes" values. Use state for what's shown on screen.
  • <input ref={myRef} /> gives you the real element in myRef.current.
  • Use refs in event handlers and effects, not during rendering.
