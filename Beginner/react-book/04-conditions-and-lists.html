4. Logical AND && for "this or nothing"

Read it as: "if isPacked, then show ✅, otherwise nothing." React renders nothing for false, null, undefined and true.

Keys: helping React keep track

A key is a unique name for each item in a list. It lets React tell the items apart, even when they're added, removed or reordered.

Think of files on your desktop. If they only had positions ("the 3rd file") and you deleted one, every file after it would be "renamed". Names (keys) let React know that "this is still the same item, it just moved." Without good keys, React can mix up items, for example keeping text typed into the wrong row.

Rules of keys

  • Unique among siblings. Two items in the same list can't share a key. Different lists can reuse keys.
  • Stable. Keys must not change between renders. Never generate them while rendering, as in key={Math.random()}.
  • Where they come from: database IDs are ideal. For data you create in the app, generate an ID when you create the item (for example crypto.randomUUID()), not while rendering.
  • The key goes on the outermost element returned from map().
Avoid using the array index as the key people.map((person, index) => <li key={index}>...) stops the warning, but if items are inserted, removed or reordered, the indexes shift and bugs appear. It's OK only for lists that never change.
Keys aren't props React uses key itself, and your component doesn't receive it. If the component needs the ID, pass it separately: <Profile key={id} userId={id} />.

Recap

  • Conditional rendering is plain JavaScript: if, ? :, &&, or null.
  • Keep a number from appearing by making the left side of && a true/false value.
  • Render lists with array.map(), and narrow them down with array.filter().
  • Every list item needs a unique, stable key, ideally an ID from your data.
