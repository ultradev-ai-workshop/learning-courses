What is React?

React is a JavaScript library for building user interfaces (the buttons, lists and forms you see on a web page) out of small, reusable pieces called components.

Think of a web page as a Lego model. Without React, you build the whole model by hand, and every time something changes you find the right brick and swap it yourself. With React, you describe what the model should look like right now, and React works out which bricks to change.

The old way vs the React way

Say you want a counter that goes up when a button is clicked. In plain JavaScript you tell the browser every step (this is called imperative code):

In React you describe what the screen should show for a given value, and React updates the page for you (this is called declarative code):

For one counter the difference is small. For an app with hundreds of moving parts, the React way stays much easier to reason about. The core idea is:

UI = f(data)The screen is the output of a function of your data. Change the data, and React redraws the screen to match.

What you need first

  • Basic HTML, CSS and JavaScript. You especially need functions, arrays, objects, arrow functions (() => {}), and import/export.
  • Node.js installed. Check it in a terminal with node -v. Node runs the development tools; your React code itself runs in the browser.
  • A code editor. VS Code is the most popular choice.

Step 2. main.jsx runs. It tells React to take over that box and draw <App /> inside it:

Step 3. React calls your App function, takes the UI it returns, and puts it into the real page.

Two packages, two jobs react knows about components, state and hooks. react-dom knows how to put them into a web page (the DOM). React Native uses the same react package to draw on phones instead.
What is StrictMode? A development-only helper. It shows nothing on the page. It deliberately runs some of your code twice to catch mistakes early. If a console.log prints twice in development, this is why. It does not happen in the production build.

Useful scripts

CommandWhat it does
npm run devStarts the dev server with instant updates. Use it while coding.
npm run buildCreates an optimised production version in dist/. It also shows errors that the dev server might hide.
npm run previewServes the built dist/ folder locally so you can check it.
npm run lintChecks your code for common mistakes.

Tools worth installing

  • React Developer Tools (a browser extension for Chrome, Firefox or Edge). It adds a "Components" tab where you can see your component tree and each component's props and state live.
  • Prettier (a VS Code extension). It formats your code automatically. Turn on "Format on Save".
  • ESLint (or oxlint, which your project uses). It warns about bugs such as breaking the Rules of Hooks.
A word about the React Compiler The docs also describe the React Compiler, a build-time tool that automatically optimises your components. You don't need it to learn React. Write normal, clean React code, and the compiler can be added later.

Common beginner mistakes

  • Running npm run dev in the wrong folder → "Missing script: dev". Run cd into the folder that contains package.json first.
  • Forgetting npm install after cloning or creating a project → "vite: command not found".
  • Opening index.html by double-clicking → a blank page. A React project must be opened through the dev server URL.
  • Editing files in node_modules. Your changes are lost on the next install. Only edit src/.

Recap

  • React builds UIs out of components, and you describe what to show, not how to change the page.
  • Create a learning project with npm create vite@latest. For full apps, the docs recommend a framework.
  • index.html → main.jsx → App.jsx is how every Vite React app starts.
  • react = components and hooks; react-dom = putting them on a web page.

7. Break it on purpose 🟡 medium

Make each of these mistakes one at a time, save, and read the error. Then undo it.

  1. Delete a closing </h1>.
  2. Rename App to app in main.jsx only.
  3. Import a file that doesn't exist: import X from './Nope'.
Show what you should see
  1. "Unterminated JSX contents" or "Expected corresponding JSX closing tag".
  2. "app is not defined", or a blank page with a console error.
  3. "Failed to resolve import './Nope'".

Learning to recognise these messages will save you hours.

8. Build for production 🟡 medium

Run npm run build, then look inside the dist/ folder. What files are there? Then run npm run preview and open the URL.

Show answer

dist/index.html plus dist/assets/ with one bundled .js file, one .css file and your images, each with a hash in its name (like index-CENbLOPi.js). This is everything a web server needs. Vite has combined and minified all your files.
