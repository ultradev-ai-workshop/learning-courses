Chapter 3 · Describing the UI

Props

Props are how a parent component passes information to its children, just like arguments to a function.

You will learn
  • How to pass props to a component
  • How to read props, with destructuring
  • How to set default values
  • How to pass JSX as children
  • Why props are read-only

What are props?

You already use props with HTML tags. In <img src="..." alt="..." />, src and alt are information you pass into the image. Your own components can take props too, and any JavaScript value can be a prop: strings, numbers, objects, arrays, even functions.

Step 1: pass props to the child

The rule from Chapter 2 applies: strings go in quotes (name="Lin"), and everything else goes in braces (size={100}, person={{ ... }}).

Don't forget the braces function Avatar({ person, size }) ✅ destructures the props object.
function Avatar(person, size) ❌ is wrong: person would be the whole props object, and size would be undefined.

Reuse: same component, different props

Think of a component as a template and props as the blanks you fill in. You can change Avatar without touching Profile, and the other way round.

Use this sparingly. If you spread props everywhere, it becomes hard to see which component receives what.

Passing JSX as children

With HTML you can put tags inside other tags: <div><img /></div>. Your components can do the same. Whatever you put between the opening and closing tags arrives as a special prop called children:

Think of Card as a picture frame: it doesn't need to know what's inside, it just draws the border around it. Panels, modals, layouts and grids are commonly built this way.

Props are read-only

A component receives props but must never change them:

Props can still change over time: the parent can re-render with different props, and the child then shows the new values. But it's always the parent that changes them. If a component needs its own changing data (for example, in response to a click), that's state, covered in Chapter 7.

Data flows one way Parent → child, through props. A child can't reach up and change its parent's data directly. You'll learn the proper way (passing a function as a prop) in Chapter 6.

Recap

  • Pass props like HTML attributes: <Avatar person={p} size={100} />.
  • Read them with destructuring: function Avatar({ person, size }).
  • Defaults: { size = 100 }. Forward everything: {...props}.
  • Nested JSX arrives as children.
  • Props are read-only snapshots. Use state for data that changes.
