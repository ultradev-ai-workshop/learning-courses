The problem: prop drilling

Props are great, but when a value is needed deep in the tree, you have to pass it through every component in between, even those that don't use it:

This is called prop drilling. Context lets a parent make data available to everything below it, however deep.

Older syntax Before React 19 you wrote <ThemeContext.Provider value={theme}>. You'll still see it in tutorials, and it still works. React 19 lets you use <ThemeContext value={...}> directly.

Now any component inside <ThemeContext value="dark">, at any depth, gets "dark" from useContext(ThemeContext). When theme state changes, every component that reads it re-renders automatically.

The closest provider wins

Context works like CSS inheritance: a value flows down until something closer overrides it.

Before you use context

Context is tempting, but it makes data flow harder to follow. Try these first:

  1. Just pass props. Ten props through three levels is fine, because it's explicit and clear.
  2. Use children. If a middle component only passes data along, let it take JSX as children instead:

Good uses for context: theme (dark/light), the current logged-in user, language, routing, and app-wide state managed with a reducer (next section).

Recap

  • Context solves prop drilling: createContext → <Ctx value={...}> → useContext(Ctx).
  • A component reads the value from the closest provider above it.
  • Try plain props or children before reaching for context.
  • Reducer + context (wrapped in a provider component and custom hooks) is a simple way to manage app-wide state.
