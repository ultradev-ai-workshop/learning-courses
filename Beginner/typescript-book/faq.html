1. Why do I need to learn TypeScript if I already know JavaScript?

Because TypeScript is JavaScript, plus a checker that reads your code before it runs. You don't throw away anything you know; you add one skill on top. What you get for it:

  • Bugs found while you type, not in production. Typos in property names, a missing await, a forgotten null check, a wrong argument order. The capstone (Chapter 19) shows a JavaScript app with passing tests in which the compiler found three real bugs in a few seconds.
  • An editor that knows your code. Accurate autocomplete, "go to definition", and renames across hundreds of files that you can trust.
  • Documentation that can't go stale. A signature like borrow(bookId: BookId, memberId: MemberId): Result<Loan> tells the next reader (and you, in six months) what goes in, what comes out, and that it can fail, and the compiler keeps it true.
  • Safe refactoring. Change a type and the compiler lists every place that must follow. In plain JavaScript, you search and hope.
  • The job market and the ecosystem. Most new JavaScript projects, frameworks and libraries are written in TypeScript, and many job descriptions list it. Even if you write plain JavaScript, your editor uses TypeScript's type information from libraries to help you.

In JavaScript, this missing await becomes "title.toUpperCase is not a function" at runtime, maybe on a code path your tests don't cover. TypeScript catches it at the line where it happens.

💡 The cost is real but small: you write types at the edges (function parameters, data shapes) and learn to read compiler errors. Chapters 1–4 are enough to start using TypeScript productively.

Roughly in this order. The first five give you 80% of everyday TypeScript:

🧠 Analogy: learning to drive in a new car. You already know how to drive (JavaScript). First learn the dashboard warnings (errors), the mirrors (types on parameters) and the brakes (null checks). The sport mode buttons (type-level programming) can wait until you need them.

3. Does TypeScript make my code faster, or check it at runtime?

Neither. The emitted JavaScript is your code without the types, so it runs at the same speed, and no checks are added. If you need runtime validation (for API input, files, forms), write type guards or use a validation library (Chapter 4). The one indirect speed benefit: TypeScript makes it safer to refactor towards faster code.

4. Is TypeScript object-oriented, like Java or C#?

It supports OOP well (classes, interfaces, access modifiers, abstract classes, generics), and its syntax was designed to feel familiar to Java and C# developers. But it doesn't force OOP: functions, plain objects and unions are just as idiomatic, and the type system is structural, not nominal. See Chapter 7 and Appendix A, which maps every Java and C# concept to TypeScript.

5. Should I use interface or type?

For object shapes, both work and the difference rarely matters. The Handbook suggests interface until you need a feature only type has (unions, tuples, mapped and conditional types). Interfaces can be merged and extended with extends; type aliases can name any type. Pick one style for object shapes and be consistent (Chapter 3).

6. When is any OK, and why is unknown better?

any turns checking off for a value and everything it touches. It's acceptable as a temporary step during a migration, or deep inside a small, well-tested helper. unknown also accepts any value but forces you to check it before use, so it's the right type for "I don't know yet": parsed JSON, catch variables, untyped inputs (Chapter 4). typescript-eslint can flag accidental any (Appendix B).

7. Can Node.js run .ts files directly now?

Yes: since Node 22.18 and 23.6, node app.ts works by stripping the types. It doesn't type-check, doesn't read tsconfig.json, and supports only erasable syntax (no enums, namespaces or parameter properties). Use it for scripts and quick runs, and keep tsc --noEmit in your editor and CI (Appendix B).

8. What changed in TypeScript 7?

The compiler was ported to Go: about 10× faster with the same language rules. strict is on by default, several old options were removed, and tools that use the compiler's JavaScript API (like typescript-eslint) keep using TypeScript 6 until the new API is ready. For learning, nothing changes: everything in the Handbook applies (Chapter 1, Appendix B).

9. How do I add TypeScript to an existing JavaScript project?

Gradually, the way the official guide describes: add a tsconfig.json with allowJs and checkJs, fix what it finds, add JSDoc or rename files to .ts one at a time, then turn on strict step by step. Your app keeps running throughout, because TypeScript always emits JavaScript. Chapter 19 walks through all of it on a real project.

10. Should I learn TypeScript before React (or Node, or Angular)?

You need solid JavaScript first. After that, learning TypeScript before (or alongside) a framework pays off: React and Node documentation now show TypeScript examples, Angular requires TypeScript, and typed props and API responses remove a whole class of framework bugs. Chapters 1–8 cover what you need to read typed framework code. The React Beginner Book and the Node.js Study Book are good next steps.

11. If an AI assistant writes much of my code, do types still matter?

More than before. Types are a precise, machine-checked description of what code should do, which helps in both directions: assistants generate better code when the surrounding types tell them the shapes, and the compiler immediately rejects generated code that doesn't fit (wrong property names, missing cases in a switch, ignored null). You still need to read TypeScript fluently to review what was generated, and types make that review much faster.

12. How long does it take to learn TypeScript?

If you know JavaScript well, a few days gets you productive (Chapters 1–7), and a few weeks of real use makes generics and narrowing feel natural (Chapters 8–14). Type-level programming (Chapters 10–11) is a separate, optional skill you can grow into. Doing the playground exercises and the capstone is the fastest route: reading types is learned by writing them.
