Chapter 7 · Functions, Objects & Classes

Classes

TypeScript adds types and a few keywords to JavaScript's class syntax. If you know Java or C#, most of this chapter will feel familiar, and the differences are what matter: access modifiers are checked only at compile time, implements is optional, and classes are compared by shape. This chapter follows the Handbook's Classes page and the official TS for Java/C# Programmers guide.

You will learn

  • Typed fields, strictPropertyInitialization and the definite-assignment !.
  • Constructors, methods, getters/setters and parameter properties.
  • implements and extends, and the override keyword.
  • public, protected, private vs JavaScript's #private.
  • static members, abstract classes and generic classes.
  • Why two unrelated classes with the same shape are interchangeable.

Methods, getters and setters

A getter without a setter makes the property read-only to the checker. The return type this means "the type of the current instance", which stays correct in subclasses.

implements

class C implements I asks the compiler to check that the class fits interface I. That's all it does. It doesn't change the class's type, and it isn't needed for an instance to be used as an I:

☕ Java / C#: in Java, Laptop could never go into a List<Lendable> without implements Lendable. In TypeScript it can, because typing is structural. Use implements anyway on classes that are meant to fit an interface: the error then points at the class, where the mistake is, instead of at some distant call site.

extends and override

Inheritance works as in JavaScript: extends, and super(...) must be called before using this in a subclass constructor. Mark overriding methods with override. With noImplicitOverride on (recommended), forgetting it is an error, and override on a method that doesn't exist in the base class is always an error, which catches renames:

☕ Java / C#: override is Java's @Override, made a keyword like in C#. Unlike C#, every method is "virtual": there's no virtual/sealed, and no final methods. Like Java, a class can extend only one class but implement many interfaces.

Member visibility

ModifierAccessible fromEnforced
public (default)anywhere—
protectedthe class and its subclassescompile time only
privatethe class onlycompile time only ("soft private")
#name (JavaScript)the class onlyat runtime ("hard private")

After compilation, private pin is an ordinary property, visible to console.log(card), JSON.stringify and any JavaScript code. #secret really can't be read from outside the class, not even with as any. Use # when privacy must hold at runtime (security, library internals); private is fine for keeping your own code tidy.

🧠 Analogy: a "Staff only" sign versus a locked door. private is the sign: everyone who reads the rules (the type checker) stays out, but nothing physically stops them. #private is the lock.

Static members

Static members belong to the class object itself. They can't use the class's type parameters (each instance may have a different T, but there's only one class).

Generic classes

Classes are structural too

The type of a class instance is its shape, so two unrelated classes with the same public members are interchangeable. Even an empty class accepts anything:

The exception: a class with a private/protected or # member is only compatible with itself and its subclasses. That's a common trick to get nominal behaviour when you need it.

☕ Java / C#: this is the biggest mental shift. In Java, Point p = new Pixel() is impossible unless Pixel extends Point. In TypeScript a class is "a constructor function plus an interface for its instances", and the interface is matched by shape. Also note: no method overloading by signature (Chapter 5), no final/sealed, and no runtime generics (new T() doesn't work, because T is erased).

Recap

  • Fields need types or initializers; strict mode requires them to be assigned (or use ? / !).
  • Parameter properties (constructor(private x: T)) declare and assign in one step, but they emit code.
  • implements only checks; any value with the right shape fits an interface.
  • extends + super; mark overrides with override and enable noImplicitOverride.
  • private/protected are compile-time only; #private is enforced at runtime.
  • abstract classes can't be new-ed; generic classes take type parameters; statics can't use them.
  • Instances are compared structurally, unless the class has private members.

Exercise 9 🔴 hard explain

A Java developer writes class Repo<T> { create(): T { return new T(); } }. Why can't this work in TypeScript, and what is the usual fix?

Show solution

T is erased, so at runtime there's nothing to call new on. Pass the constructor in as a value, typed with a construct signature (new () => T), just as you'd pass a Class<T> or Supplier<T> in Java.

Show solution

The #cents member makes Money nominal. A private constructor forces callers to use Money.of. Values are immutable: add returns a new instance, like Java's BigDecimal.
