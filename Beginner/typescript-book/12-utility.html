Utility Types

TypeScript ships a set of global generic types for the most common transformations. You've already built several of them yourself in Chapters 10 and 11. This chapter follows the Utility Types reference page: what each one does, and the everyday situations where it saves you from writing a type twice.

You will learn

  • Object transformers: Partial, Required, Readonly, Pick, Omit, Record.
  • Union filters: Exclude, Extract, NonNullable.
  • Function and class helpers: Parameters, ReturnType, ConstructorParameters, InstanceType, Awaited.
  • The this helpers and NoInfer.
  • How to combine them into DTO types (create / update / view) from one model.

Transforming object types

Partial and Required

Readonly

It's shallow, like Object.freeze (which is typed as returning Readonly<T>).

Record

With a union of literal keys, Record forces you to cover every key: a quiet exhaustiveness check. Add "vip" to MemberType and this object fails to compile until you add its limit.

Pick and Omit

⚠️ Omit's key parameter is K extends keyof any, not keyof T, so Omit<Member, "passwrdHash"> (a typo) compiles and omits nothing. Double-check Omit keys, or write a stricter type StrictOmit<T, K extends keyof T> = Omit<T, K>.

this helpers

ThisType<T> is a marker used in object literals to say what this will be inside their methods (used by some libraries' "options object" APIs). It requires noImplicitThis, which strict includes.

Putting them together: one model, many shapes

A common real-world use: define the full model once, and derive the request and response types for an API from it. If the model changes, all of them follow.

☕ Java / C#: in Java or C# you'd write separate CreateBookRequest, UpdateBookRequest and BookSummaryDto classes (or records), and keep them in sync by hand or with a mapper library (MapStruct, AutoMapper). In TypeScript they're one line each, derived from the model, and the compiler keeps them in sync. You still write the mapping functions, because types don't exist at runtime.

🧠 Analogy: photo filters. The model is the original photo. Pick crops it, Omit blurs out a part, Partial makes parts transparent, Readonly laminates it. You never re-take the photo.

Recap

  • Partial/Required/Readonly change modifiers; Pick/Omit select keys; Record builds dictionaries (and forces every literal key).
  • Exclude/Extract/NonNullable filter unions.
  • Parameters, ReturnType, ConstructorParameters, InstanceType and Awaited reuse the types of existing functions and classes.
  • Derive DTOs (create, update, summary, view) from one model instead of writing them by hand.
  • Beware: Omit doesn't check that the keys exist.
