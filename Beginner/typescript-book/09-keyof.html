Chapter 9 · Type Manipulation

keyof, typeof & Indexed Access

Three small operators let you derive types from other types, and from values. Instead of writing the same list of names twice (once as data, once as a type), you write it once and let TypeScript compute the rest. This chapter covers the Handbook pages Keyof Type Operator, Typeof Type Operator and Indexed Access Types.

You will learn

  • The idea of type-level code: operators that work on types instead of values.
  • keyof T: the union of a type's property names.
  • typeof value in a type position: the type of a variable.
  • T["prop"] and T[number]: indexed access types.
  • The "single source of truth" pattern with as const.

Creating types from types

So far you've written types by hand. TypeScript's type system is also a small language of its own: you can take a type, apply an operator, and get a new type. The Handbook's Creating Types from Types section lists the tools: generics (Chapter 8), keyof, typeof and indexed access (this chapter), conditional types (Chapter 10), and mapped and template literal types (Chapter 11).

🧠 Analogy: spreadsheet formulas. Instead of typing a total by hand, you write =SUM(A1:A9), and it updates when the data changes. Derived types are formulas: change the source type and every type computed from it follows.

☕ Java / C#: there's no equivalent in Java's or C#'s type systems. The closest is reflection (Book.class.getDeclaredFields()), but that happens at runtime and gives you strings, not checked types. It's like having nameof(Book.Title) from C#, built into the types.

Recap

  • Types can be computed from other types; change the source and derived types follow.
  • keyof T → union of T's keys (index signatures give string | number or number).
  • typeof x in a type position → the type of a value; use ReturnType<typeof fn> for results.
  • T["k"], T["a" | "b"], T[keyof T], T[number] look up property and element types.
  • as const + typeof + [number]/keyof = one source of truth for values and types.

Exercise 9 🔴 hard explain

Why does TypeScript type Object.keys(book) as string[] instead of (keyof Book)[]? When is the keysOf helper from this chapter unsafe?

Show solution

Because of structural typing, a value of type Book may have extra properties at runtime (it might be a subclass, or an object with more fields). keysOf would claim those extra keys are keyof Book, and indexing with them could give values of unexpected types. It's safe for objects you created yourself with exactly those keys, such as as const configuration objects.

Exercise 10 🔴 hard design

Write updateField<T, K extends keyof T>(obj: T, key: K, value: T[K]): T returning a copy. Show that updateField(book, "year", "1965") is an error, and print a valid update.

Show solution

The value's type depends on the key: T[K] is number when K is "year".
