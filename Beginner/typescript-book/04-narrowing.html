Chapter 4 · Getting Started

Narrowing

A union says "one of these". Narrowing is how you find out which one, using ordinary JavaScript checks that TypeScript understands. This chapter follows the Handbook's Narrowing page, from typeof to discriminated unions and exhaustiveness checks. It also shows the right way to handle data you don't trust: unknown plus a type guard.

You will learn

  • How control flow analysis narrows types after if, return and assignments.
  • The built-in guards: typeof, truthiness, ===, in and instanceof.
  • Writing your own guards with type predicates (x is T) and assertion functions.
  • Discriminated unions, the pattern behind most well-typed TypeScript code.
  • never and exhaustiveness checking.
  • unknown: safely validating JSON and other runtime data.

typeof guards

typeof returns one of "string", "number", "bigint", "boolean", "symbol", "undefined", "object" or "function". TypeScript narrows on each. Watch the classic JavaScript quirk: typeof null is "object", and TypeScript knows it.

Inside the first branch, strs is string[] | null, because null also has typeof "object". The checker just saved you from a crash.

Truthiness narrowing

In if (x), falsy values (0, NaN, "", null, undefined, false, 0n) take the else branch. TypeScript removes null and undefined in the true branch:

⚠️ Don't wrap the whole body in if (strs) to "handle null": that also skips the empty string "", which is a valid value. For numbers, if (count) skips 0. Check !== null or !== undefined when that's what you mean.

Equality narrowing

===, !==, == and != narrow too. If two values are equal, they must share a type. x != null removes both null and undefined (loose equality treats them as equal).

For classes (anything created with new), x instanceof C narrows to C. It's how you check errors in a catch, because the caught value is unknown in strict mode: JavaScript lets you throw anything.

Control flow analysis

TypeScript follows every path through your code: ifs, early returns, throws, loops and assignments. The type of a variable can be different at each point. This is control flow analysis.

🧠 Analogy: a detective's notebook. At each line TypeScript writes down what it has proved about each variable. "Passed the typeof check, so it's a number." "Returned in that branch, so from here on it can't be a number." When you assign a new value, the old notes are crossed out.

Discriminated unions

Give each member of a union a common property with a different literal value, the discriminant (often called kind or type). Checking it narrows to exactly one member. A switch on it reads very cleanly:

Notice the function has no return after the switch, and TypeScript doesn't complain: it knows every case returns.

☕ Java / C#: this is the TypeScript version of Java's sealed interfaces + records + pattern-matching switch (Java 21), or C#'s records with switch expressions. In Java the compiler knows the permitted subclasses; in TypeScript it knows the members of the union. There are no classes involved: the members are plain objects.

🧠 Analogy: a checklist that must be fully ticked. Each case ticks a box. never in default asserts "no boxes are left". Add a new box to the list, and every checklist that hasn't ticked it gets flagged.

Recap

  • Narrowing turns a wide type into a specific one using normal runtime checks; control flow analysis tracks the type at every line.
  • Built-in guards: typeof (remember typeof null === "object"), truthiness, ===/!= null, in, instanceof, Array.isArray.
  • Custom guards return x is T; assertion functions return asserts x is T. TS 5.5+ infers simple predicates.
  • unknown + a guard is the safe way to handle JSON and other runtime data.
  • Discriminated unions: members share a literal kind; switch on it.
  • never means "impossible"; assign to it in default for exhaustiveness checking.
