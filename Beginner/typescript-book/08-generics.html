Generics

Part III of the Handbook is called Type Manipulation: building new types from existing ones. Generics come first, because every other tool in this part uses them. A generic is a type (or function, or class) with a type parameter, a placeholder that is filled in when it's used.

You will learn

  • Why T beats any: generics keep the link between input and output types.
  • Generic functions, interfaces, type aliases and classes.
  • Constraints with extends, including K extends keyof T.
  • Default type parameters, const type parameters and NoInfer.
  • How TypeScript generics compare with Java's and C#'s.

Notice the order in the message: "ebook" | "paperback", not the order you wrote. TypeScript 7 prints union members in a fixed, stable order (the stableTypeOrdering behaviour), so error messages are the same on every machine and every run. Without NoInfer, T would be inferred as "paperback" | "ebook" | "audiobook", and the typo would be accepted.

☕ Java / C#: the syntax is the same idea as Java's <T extends Comparable<T>> or C#'s where T : IComparable<T>. Differences: TypeScript generics are fully erased (like Java, unlike C#, so no typeof(T) or new T()); any type works as an argument, including number and unions (no boxing, no Integer); there are no wildcards (? extends), because structural typing and unions cover those cases; and inference is much stronger, so you rarely write type arguments at all.

A rule of thumb: push type parameters down

The Handbook's guidelines: use as few type parameters as possible, constrain them as little as necessary, and if one appears only once, replace it with its constraint.

Recap

  • A type parameter <T> links types across a signature; any throws that link away.
  • Functions, interfaces, aliases and classes can be generic; type arguments are usually inferred.
  • Constraints (T extends X) say what T must have; K extends keyof T + T[K] is a key pattern.
  • Defaults (<T = string>), const T (literal inference) and NoInfer<T> fine-tune inference.
  • Generics are erased: pass constructors as values when you need to create instances.

Exercise 9 🔴 hard explain

Why does function first<T extends any[]>(arr: T) { return arr[0]; } give a worse return type than function first<T>(arr: T[]) { return arr[0]; }?

Show solution

In the first, T is the whole array type and arr[0] is typed through the constraint, so it's any. In the second, T is the element type, so arr[0] is T (e.g. number). The Handbook's rule: when possible, use the type parameter itself rather than constraining it.

Exercise 10 🔴 hard design

Write pipe for two and three functions with overloads, so pipe(trim, upper, exclaim)(" dune ") is fully typed. Each function's output must match the next one's input.

Show solution

Each overload chains type parameters (A → B → C → D), so a function whose input doesn't match the previous output is a compile error.
