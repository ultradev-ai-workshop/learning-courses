More on Functions

Functions are the main building block of any JavaScript program, so TypeScript has many ways to describe them. Following the Handbook's More on Functions page, this chapter covers function types, optional and rest parameters, overloads, typing this, and the special types void, unknown and never as they apply to functions.

Function type expressions

The simplest way to describe a function is a function type expression. It looks like an arrow function: (a: string) => void means "a function with one string parameter that returns nothing useful". The parameter name is required, but only the type matters.

⚠️ (string) => void doesn't mean what you think: it's a function with one parameter named string, of type any. Always write a name: (s: string) => void.

Call signatures: functions with properties

In JavaScript a function is an object and can have properties. To describe both, write a call signature inside an object type: the parameter list, then : (not =>) and the return type.

Function overloads

Some functions accept different argument combinations. Overloads list the allowed call shapes (the overload signatures), followed by one implementation signature with a body. Callers only see the overloads.

The implementation signature (yOrTs, month?, day?) is not callable from outside, which is why makeDate(2026, 11) fails even though the implementation would accept it.

💡 Prefer unions over overloads when you can. len(x: string | any[]) is simpler than two overloads, and it also accepts a value whose type is already string | any[], which overloads can't.

☕ Java / C#: in Java and C#, overloads are separate methods with separate bodies, and the compiler picks one. In TypeScript there is only one body at runtime (JavaScript has no overloading); the overload signatures are just a typed list of the ways to call it. Your one implementation must check the arguments itself.

The emitted JavaScript still ran the bad call, and crashed exactly as the checker predicted: in a module, a plain call gets this === undefined. With strict, using this in a plain function without declaring it is an error (noImplicitThis). Arrow functions don't have their own this, so they can't declare one.

void, unknown, never and Function

TypeAs a return type it means
voidThe function's return value isn't meant to be used. (At runtime it's undefined.)
undefinedThe function really returns undefined, and callers may rely on it.
unknownIt returns something; callers must check it before use.
neverIt never returns normally: it always throws, or loops forever.
Function"Some function". Calls on it return any. Avoid it; write () => void instead.

Recap

  • Describe functions with (a: A) => R; use a call signature { (a: A): R; prop: P } when the function has properties, and new (…) => T for constructors.
  • Generic functions relate input and output types; constraints (T extends …) say what T must have.
  • x? and defaults make parameters optional; ...rest: T[] collects the rest. Type destructured parameters after the pattern.
  • Overloads list call shapes over one implementation. Prefer a union parameter when it works.
  • Declare this as a first parameter. void means "ignore the result"; never means "doesn't return".

Exercise 9 🔴 hard explain

Why does TypeScript accept [1, 2].forEach((n) => arr.push(n)) even though forEach's callback returns void, while function f(): void { return 1; } is an error?

Show solution

A function type with a void return means "the caller will ignore the result", so any function can be assigned to it; this keeps common code such as push inside forEach legal. A function declaration with an explicit : void annotation is a promise about the body itself, so returning a value breaks it.

Exercise 10 🔴 hard design

Write a typed debounce<A extends unknown[]>(fn: (...args: A) => void, ms: number): (...args: A) => void. Call the debounced function three times quickly with different titles; only the last should print.

Show solution

A extends unknown[] captures the whole parameter list as a tuple, so the returned function has exactly the same parameters as fn, with names and types.
