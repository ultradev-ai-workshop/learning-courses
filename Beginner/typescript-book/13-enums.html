Enums, Literal Unions & Symbols

Part IV covers the Handbook's Reference pages. First: how to model a fixed set of values. TypeScript has enum, one of its few features that isn't just JavaScript plus types, and modern TypeScript code often prefers literal unions and as const objects instead. This chapter shows both, then covers symbols and the types of iterators and generators.

Numeric enums

An enum defines a set of named constants. Without initializers, members are numbered from 0:

The last line shows that an enum is a real object at runtime. Numeric enums also get a reverse mapping (Direction[2] is "Left"). This is generated code: tsc emits an object, unlike interfaces or type aliases, which vanish.

⚠️ Numeric enums are loose: any number is assignable to a numeric enum type in many places, and the reverse mapping makes Object.keys return twice as many keys as you expect. If you use enums, prefer string enums.

String enums

Each member of a string enum must be initialised with a string. There's no reverse mapping, and values are readable when logged or stored:

Note the last line: string enums are nominal. The string "OVERDUE" isn't accepted, even though it's the same value. You must write LoanStatus.Overdue. That's stricter than everything else in TypeScript, and it surprises people who receive values from JSON.

const enums and erasable syntax

A const enum is removed at compile time: every use is replaced by its value. It saves the runtime object, but it needs whole-program compilation, so tools that compile one file at a time (esbuild, Babel, isolatedModules) can't fully support it.

No Shelf object is emitted: the value is pasted in, with a comment saying where it came from.

Enums (like namespaces and parameter properties) are not erasable: you can't just delete the TypeScript parts and get valid JavaScript. That matters more and more:

  • Node's built-in type stripping (node file.ts) only removes types; it rejects enums unless you use the slower --experimental-transform-types flag.

Symbols

A symbol is a unique, primitive value often used as a property key that can't clash with any string key. TypeScript types them as symbol, or, for a const declaration, as a unique symbol: a type that matches only that one symbol.

Symbol keys don't show up in Object.keys or JSON, which makes them handy for metadata. JavaScript's well-known symbols, such as Symbol.iterator, let your objects plug into language features.

Recap

  • Enums generate a runtime object; numeric enums have reverse mappings, string enums don't.
  • String enums are nominal: a matching plain string isn't accepted.
  • const enum inlines values but needs whole-program compilation; enums aren't erasable (erasableSyntaxOnly, Node type stripping).
  • Prefer literal unions, or an as const object plus a derived type, for most code.
  • TypeScript enums have no methods; model Java-style enums with classes or unions.
  • unique symbol types one symbol; Iterable<T> and Generator<Y, R, N> type iteration.

Exercise 9 🔴 hard explain

Why do tools that compile one file at a time (esbuild, Babel, Node's type stripping) struggle with const enums imported from another file?

Show solution

To inline Shelf.B as "B", the compiler must read the other file where the enum is declared. A single-file transpiler doesn't look at other files, so it doesn't know the value. It would have to keep Shelf.B, but no Shelf object exists at runtime, so the code breaks. That's why isolatedModules restricts const enums.
