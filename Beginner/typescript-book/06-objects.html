Object Types

In JavaScript, data travels in objects. This chapter follows the Handbook's Object Types page and goes deeper than Chapter 3: property modifiers, index signatures, the excess property check, extending and intersecting types, generic object types, and tuples.

You will learn

  • readonly and optional properties, and exactOptionalPropertyTypes.
  • Index signatures for dictionaries, and noUncheckedIndexedAccess.
  • The excess property check: why extra properties sometimes fail.
  • extends vs intersections (&).
  • Generic object types such as Box<T> and ReadonlyArray<T>.
  • Tuples: fixed-length arrays with a type per position.

readonly properties

readonly forbids assignment to a property through that type. It's a compile-time check only; it doesn't freeze the object.

☕ Java / C#: readonly is like a final field (Java) or a readonly/init property (C#): the reference can't change, but the object it points to can. And because typing is structural, a readonly object type can be assigned to a mutable one with the same properties. It protects your code from accidents, not from other code.

Optional properties, exactly

An optional property note?: string may be missing. By default you may also set it to undefined explicitly. The stricter option exactOptionalPropertyTypes separates "missing" from "present but undefined", which matters for code that checks "note" in obj or uses Object.keys:

tsc --init turns this option on in new projects. If you really want to allow undefined, write it: theme?: "light" | "dark" | undefined.

Index signatures

When you don't know the property names in advance, but you know the types, use an index signature: [key: string]: T. It describes a dictionary.

Look closely: stock.b99 has type number, but it's undefined at runtime. The option noUncheckedIndexedAccess (also set by tsc --init) adds | undefined to every index access, including arrays:

Record<string, number> is a built-in shorthand for { [key: string]: number } (Chapter 12). For a real dictionary, a Map is often better: map.get(k) always returns T | undefined.

Tuples

A tuple is an array with a known length and a known type at each position. React's useState returns one: [value, setter].

Mark tuples readonly when they shouldn't change: readonly [number, number]. as const on an array literal produces a readonly tuple.

☕ Java / C#: tuples are like C#'s (string BookId, int Copies) value tuples. Java has no built-in tuple; you'd write a small record Entry(String bookId, int copies). In TypeScript, prefer an object with named properties once a tuple has more than two or three elements.

Recap

  • readonly blocks assignment through a type (shallowly, at compile time only).
  • ? marks optional properties; exactOptionalPropertyTypes separates "missing" from "undefined".
  • Index signatures ([k: string]: T, or Record<string, T>) describe dictionaries; noUncheckedIndexedAccess makes lookups honest.
  • Fresh object literals get an excess property check; variables don't.
  • extends reports conflicts; & turns them into never.
  • Generic types (Box<T>) are type templates. readonly T[] has no mutating methods.
  • Tuples have fixed positions; they can have labels, optional and rest elements.

Exercise 9 🔴 hard explain

Why does TypeScript check excess properties only for fresh object literals? Give an example where checking variables too would be annoying.

Show solution

Structural typing means "has at least these properties". A variable usually exists for another purpose and legitimately has more properties, e.g. a full Member passed to function sendEmail(to: { email: string }). Rejecting that would force copies everywhere. A fresh literal, however, exists only for this call, so an unknown property is almost certainly a typo.
