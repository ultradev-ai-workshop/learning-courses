Chapter 5 · Control Flow & Functions

Functions in Depth

Python functions are flexible: default values, keyword arguments, any number of arguments, and markers that control how callers may pass them.

You will learn

  • How to define functions, return values, and write docstrings.
  • Default argument values, and the mutable-default trap.
  • Keyword arguments, and the / and * parameter markers.
  • *args, **kwargs, and unpacking with * and ** at the call site.
  • Lambdas, type annotations, and the PEP 8 coding style.

Defining functions

def creates a function. The body is indented. A docstring (a string on the first line) documents what the function does.

Words to know:

  • A parameter is the name in the definition (n). An argument is the value you pass in the call (100).
  • Variables assigned inside a function are local: they only exist during the call. To assign to a module-level variable from inside a function, you must declare it global (Chapter 11 explains scopes).
  • Arguments are passed by object reference. The function gets the same object, not a copy. If you change a list that was passed in, the caller sees the change.

Returning values

return value sends a result back. A function without a return, or with a bare return, returns None, Python's "no value" object.

Default argument values

A parameter can have a default, so callers may leave it out.

Default values are evaluated once, when the def line runs, not on each call:

Keyword arguments

Callers can name arguments: name=value. Keyword arguments can come in any order, but they must come after all positional ones.

Invalid calls:

CallError
parrot()required argument voltage missing
parrot(voltage=5.0, 'dead')positional argument after a keyword argument (a SyntaxError)
parrot(110, voltage=220)got multiple values for voltage
parrot(actor='John Cleese')unexpected keyword argument actor

💡 Tip: keyword arguments make calls self-documenting. resize(img, 200, 100, True) is a puzzle. resize(img, width=200, height=100, keep_ratio=True) explains itself.

Special parameters: / and *

By default, any parameter can be passed either by position or by keyword. Two markers in the parameter list restrict that:

  • Everything before / is positional-only: callers cannot use its name.
  • Everything after * is keyword-only: callers must use its name.
Use…When…
positional-only (/)the name has no meaning for callers, or you may want to rename it later (len(obj), abs(x))
keyword-only (*)the meaning would be unclear without a name, especially boolean flags (sorted(xs, reverse=True))
neithermost everyday functions

Arbitrary argument lists: *args and **kwargs

  • *args collects any extra positional arguments into a tuple.
  • **kwargs collects any extra keyword arguments into a dict.

The names args and kwargs are only a convention. The stars are what matter.

Unpacking argument lists

The opposite direction: you already have a list or a dict, and you want to spread it into separate arguments. Use * for sequences and ** for dicts at the call site.

Lambda expressions

A lambda is a tiny anonymous function written as one expression: lambda params: expression. It is mostly used where a short function is passed as an argument, like a sort key.

❌ Don't name a lambda

✅ Use def for named functions

A def function gets a real name in tracebacks and can have a docstring. The PEP 8 style guide says not to assign lambdas to names.

☕ Java / 🟨 JS: like x -> x + n or x => x + n, but the body must be a single expression: no statements and no blocks.

Documentation strings

The conventions are: the first line is a short summary that starts with a capital letter and ends with a period. If there is more, leave a blank line and then the details.

help(my_function) shows the docstring with the indentation cleaned up.

Function annotations (type hints)

You can add optional type hints to parameters (name: type) and to the return value (-> type). Python itself does not check them at run time. Editors and tools like mypy or pyright use them to catch mistakes before you run the code.

Common hints: int, float, str, bool, list[str], dict[str, float], tuple[int, int], int | None ("an int or None").

📝 Changed in 3.14: annotations are now evaluated lazily (PEP 649), only when something asks for them. So a hint can name a class that is defined further down the file, without the quotes older code needed (-> "Node"). You'll still see those quotes, and from __future__ import annotations, in older code.

Intermezzo: coding style (PEP 8)

Python has an official style guide, PEP 8. Most projects follow it, and tools like ruff and black apply it for you. The key points:

  • Indent with 4 spaces, never tabs.
  • Keep lines to 79 characters (many teams allow 88–100).
  • Use blank lines to separate functions and classes (two blank lines at the top level).
  • Put comments on their own line when possible. Use docstrings.
  • Put spaces around operators and after commas: a = f(1, 2) + g(3, 4).
  • Name things snake_case for functions and variables, CamelCase for classes, and UPPER_CASE for constants. Always call the first method parameter self (Chapter 11).
  • Use UTF-8, and plain ASCII identifiers in code that is shared internationally.

Recap

  • def name(params): plus an indented body. Without return, a function returns None. Functions are objects.
  • Defaults are evaluated once. Never use a mutable default; use None and create the object inside.
  • Keyword arguments come after positional ones. / marks positional-only parameters and * marks keyword-only ones.
  • *args is a tuple of extras and **kwargs is a dict of extras. At the call site, * and ** unpack.
  • A lambda is a one-expression function, ideal for key=. Annotations are hints, not checks. Follow PEP 8.

Exercise 9 🔴 hard predict the output

What does this print, and why?

Show solution

[2, 2, 2]. Each lambda looks up i when it is called, and by then the loop has finished with i == 2. To capture the current value, use a default argument, which is evaluated at definition time: lambda i=i: i gives [0, 1, 2]. JS behaves the same way with var.

Exercise 10 🔴 hard explain why

Why does def f(**kwargs, *args): fail, while def f(a, /, b, *args, c, **kwargs): is valid? Write down the rule for the order of parameters.

Show solution

The order must be: positional-only → / → normal → *args (or a bare *) → keyword-only → **kwargs. **kwargs must always be last, because it collects whatever is left. Putting *args after it is a SyntaxError.
