Working with binary data record layouts

Binary files and network protocols store numbers as raw bytes, not as text. struct converts between Python values and packed bytes, according to a format string: < means little-endian (lowest byte first), H is a 2-byte unsigned int, I a 4-byte unsigned int, and f a 4-byte float.

Multi-threading

Threads let several tasks run at the same time. That is useful when a program spends time waiting: for the network, the disk or the user. Start a Thread with a target function, and join() it to wait for it to finish.

⚠️ Pitfalls: threads share memory, so protect shared data with a Lock, or better, pass data through a queue.Queue. In the standard ("GIL") build of CPython, only one thread runs Python code at a time, so threads speed up waiting, not calculating. For CPU-heavy work, use multiprocessing or concurrent.futures.ProcessPoolExecutor. Python 3.13+ also offers an optional free-threaded build without the GIL.

💡 Tip: concurrent.futures.ThreadPoolExecutor is the easy, high-level way to do this: list(pool.map(fetch, urls)).

Weak references

Python frees an object's memory when no references to it are left (this is reference counting, plus a garbage collector for reference cycles). A weak reference points to an object without keeping it alive. That is useful for caches, which shouldn't stop unused objects from being freed.

(A REPL detail: echoing d['primary'] stored the object in _, which is a strong reference. The next echoed value, True, replaced it, so nothing kept the object alive any more.)

Tools for working with lists

array: compact lists of numbers

An array stores numbers of one type as compact raw values. A list of a million numbers holds a million full Python objects; an array holds just the raw bytes.

bisect: keeping a list sorted

heapq: always get the smallest item first

A heap is a list arranged so that the smallest item is always at index 0. Pushing and popping are fast (O(log n)). It is the standard way to build a priority queue.

Together with collections.deque (Chapter 6), these cover most "special list" needs.

Decimal floating-point arithmetic

decimal.Decimal does arithmetic in base 10, exactly like you do on paper. Use it for money, and for any calculation where the results must match human or legal rounding rules.

Enums: named constants

An enum is a fixed set of named values. It replaces magic strings like "food" that can be mistyped, and its members are dotted names, so they work as value patterns in match (Chapter 4).

Recap

  • reprlib, pprint and textwrap make output readable. string.Template is for user-edited $name templates.
  • struct.pack/unpack convert values to and from raw bytes using a format string.
  • Threads help with waiting: use join(), a Lock or Queue, or a ThreadPoolExecutor. logging has levels, handlers and named loggers.
  • weakref doesn't keep objects alive. array is compact, bisect keeps a list sorted, and heapq gives a priority queue.
  • Use Decimal("…") (from strings!) for money. Enum/StrEnum name your constants.

Exercise 4 🟢 easy explain why

Why does Decimal(0.1) show a long string of digits, while Decimal("0.1") doesn't?

Show solution

The float 0.1 is already an inexact binary approximation before Decimal sees it, and Decimal faithfully converts that approximation, all of its digits. A string carries the exact decimal digits you meant.

Exercise 5 🟡 medium build it

Use bisect to turn exam scores into grades: below 60 is F, 60–69 is D, 70–79 is C, 80–89 is B, and 90 or more is A. Grade [33, 99, 77, 70, 89, 90, 100].

Show solution

bisect returns how many breakpoints are ≤ the score, which is exactly the index of the grade. (The default list is never modified here, so the mutable default is harmless.)

Exercise 9 🔴 hard explain why

A teammate uses 8 threads to speed up a pure-Python prime-number search. It gets no faster. Why, and what should they use instead?

Show solution

In the standard CPython build, the Global Interpreter Lock (GIL) lets only one thread execute Python bytecode at a time, so CPU-bound threads take turns instead of running in parallel. Use multiprocessing or ProcessPoolExecutor (separate processes, each with its own interpreter), or the free-threaded build. Threads are still great for I/O-bound work, because waiting releases the GIL.
