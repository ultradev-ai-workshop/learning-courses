Pattern Matching with match

match looks like a switch, but it does much more: it checks the shape of data and pulls values out of it in one step.

You will learn

  • Literal patterns, the wildcard _, and | alternatives.
  • Capture patterns, and the famous "bare name captures everything" pitfall.
  • Sequence patterns like [x, y] and ["add", *rest].
  • Mapping patterns for dictionaries and class patterns for objects.
  • Guards (if in a case) and as bindings.

The basic form

A match statement takes a value (the subject) and compares it against case patterns, top to bottom. The first pattern that fits runs its block, and then the whole match ends. There is no fall-through and no break.

  • case 404: is a literal pattern. It matches if status == 404.
  • case _: is the wildcard. It always matches, so it acts as the "default".
  • If no case matches and there is no wildcard, nothing happens. That is not an error.

Python catches the obvious case above as a SyntaxError, but only when another case follows. Names with a dot (Keys.QUIT, Color.RED) are treated as value patterns and compared with ==. Enums (Chapter 14) are the usual source of dotted constants.

Sequence patterns

List and tuple patterns match any sequence (a list, a tuple, a range…) of the right length. A starred name *rest soaks up any number of remaining items, just like in unpacking.

📝 Note: strings, bytes and bytearrays are not treated as sequences by match. case [a, b]: will not match the string "hi". This stops many surprises.

Guards

A guard is an if after the pattern. The case only wins if the pattern fits and the guard is true. If the guard is false, matching moves on to the next case.

Mapping patterns (dictionaries)

A pattern written with { } matches a dictionary (Chapter 7) that has at least those keys. Extra keys are ignored. **rest collects them if you want them. This is ideal for JSON-like data.

Class patterns

You can match objects by their class (Chapter 11) and check or capture their attributes. Point(x=0, y=y) means "an instance of Point whose x equals 0; capture its y".

Dataclasses also allow positional class patterns, because they set a special attribute called __match_args__. So case Point(0, y): works too. Built-in types work the same way: case int(n):, case str(s):.

⚠️ Pitfall: case int: (no parentheses) is a capture named int. It matches everything and hides the built-in name. Always write case int(): to check the type.

Naming a sub-pattern with as

pattern as name matches the pattern and also stores what it matched under name. It is useful with alternatives.

Recap

  • match subject: tries each case in order. The first match wins, with no fall-through. case _: is the default.
  • Literals compare. Bare names capture (they never compare!). Dotted names compare.
  • [a, *rest] matches sequences (not strings), and {"k": v} matches dicts that have at least those keys.
  • Cls(attr=pattern) checks the type and its attributes. Write int(), not int.
  • | gives alternatives, as names a sub-match, and if adds a guard.

Exercise 3 🟢 easy explain why

Why does case [a, b]: not match the string "hi", even though a string is a sequence of characters?

Show solution

Sequence patterns deliberately exclude str, bytes and bytearray. Otherwise a command like "go" would accidentally match a two-item pattern. Use case str(s): or split the string first.

Exercise 4 🟢 easy fix the bug

This always prints "stop!". Why? Fix it.

Show solution

case STOP: is a capture pattern: it assigns key to a new variable STOP and always matches. Use a literal, or a dotted name such as Keys.STOP.

Exercise 5 🟡 medium predict the output

Show solution
