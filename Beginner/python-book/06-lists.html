Sorting with key and reverse

key is a function that is applied to each item to get the value to sort by. The sort is stable: items with equal keys keep their original order.

Not all values can be compared with each other. [None, 'hello', 10] cannot be sorted, because an integer can't be compared with a string:

☕ Java: key= replaces writing a Comparator. Python asks "what do I sort by?" instead of "how do I compare two items?". 🟨 JS: unlike Array.prototype.sort(), Python sorts numbers numerically by default, so [10, 9, 1] becomes [1, 9, 10].

Lists as stacks

A stack is "last in, first out" (LIFO), like a pile of plates. append() pushes and pop() pops. Both are fast.

Lists as queues? Use deque

A queue is "first in, first out" (FIFO), like a line at a shop. A list can do it, but pop(0) and insert(0, x) are slow: every other item has to shift over by one. Use collections.deque (a "double-ended queue"), which is fast at both ends.

List comprehensions

A list comprehension builds a new list from an iterable in one readable expression. The shape is [expression for item in iterable if condition].

Read it like English: "give me x squared, for each x in range(10)".

Loop version

Comprehension

Unlike the loop, the comprehension doesn't leave a leftover x variable behind afterwards.

💡 Where does the if go? A filter goes at the end: [x for x in xs if x > 0], which drops items. A conditional expression goes at the start: [x if x > 0 else 0 for x in xs], which keeps every item and picks a value for each.

Unpacking in lists and comprehensions

Inside a list display, *expr spreads the items of expr into the new list, like JS's spread ...x.

📝 New in 3.15 (PEP 798): * also works inside a comprehension, which makes flattening a list of lists a one-liner.

📝 Older syntax you'll still see: before 3.15 you flattened with a double for, [item for sub in x for item in sub], or with itertools.chain.from_iterable(x). Both still work.

The del statement

del removes items by index or slice (unlike pop, it returns nothing). It can also delete a whole variable name.

The list-of-lists trap

[x] * 3 repeats the same object three times. With a list inside, all three "rows" are one and the same list.

The same thing happens with copies: lst.copy() and lst[:] are shallow. They copy the outer list, but the inner lists are still shared. Use copy.deepcopy() for a full copy of nested data.

Recap

  • Mutating methods (sort, append, reverse…) return None. sorted() returns a new list. Sort with key= and reverse=.
  • Use a list as a stack (append/pop), and use deque for queues (popleft).
  • [expr for x in xs if cond]: a filter goes at the end, a conditional value goes at the start, and several fors nest left to right.
  • [0, *xs] spreads; [*sub for sub in xss] flattens (3.15); first, *rest = xs unpacks.
  • del lst[i:j] removes by position. [[0]*3]*3 shares rows; use a comprehension instead.
