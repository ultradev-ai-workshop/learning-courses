Tuples and sequences

A tuple is an immutable sequence: a fixed group of values, written with commas and usually wrapped in parentheses.

Empty and one-item tuples need special syntax:

Packing and unpacking

t = 1, 2, 3 is tuple packing. x, y, z = t is sequence unpacking, and it works with any iterable that has the right number of items. This is how functions "return several values": they return one tuple.

☕ Java: a tuple is like a tiny anonymous record whose fields are accessed by position. For named fields, use collections.namedtuple or a dataclass (Chapter 11).

Sets

A set is an unordered collection with no duplicates. It is great for "have I seen this?" checks and for removing duplicates. Membership tests are fast (O(1) on average), however big the set.

⚠️ Pitfall: {} is an empty dict, not an empty set. Write set() for an empty set.

Set methods: s.add(x), s.remove(x) (KeyError if x is missing), s.discard(x) (no error), and s.update(iterable). Set comprehensions use braces: {c for c in 'abracadabra' if c not in 'abc'}. A frozenset is an immutable set, so it can itself go inside sets or be a dict key.

Removing duplicates: keep order or not?

What can go in a set (or be a dict key)?

Items must be hashable: they must have a hash value that never changes. In practice that means immutable built-ins: numbers, strings, tuples of hashables, and frozenset. Lists, dicts and sets are not hashable.

Dictionaries

A dictionary (dict) maps keys to values, like a real dictionary maps words to definitions. It's like Java's HashMap or a JS object or Map. Keys must be hashable. Since Python 3.7, dicts remember insertion order.

Building dicts

Useful dict methods

d1 | d2a new merged dict (values from d2 win)

🟨 JS: keys are not automatically strings. d[1] and d["1"] are different keys. There is no dot access: write d["name"], not d.name. ☕ Java: d[k] on a missing key raises KeyError; it doesn't return null. Use .get() for that behaviour.

📝 New in 3.15 (PEP 814): frozendict is a built-in immutable dict. Because it is hashable, it can be a dict key or a set member, and it is safe to share as a constant.

⚠️ Pitfall: zip() stops at the shortest input without any warning. Pass strict=True to get an error when the lengths differ.

Never add or remove dict keys while looping over the dict. That raises RuntimeError: dictionary changed size during iteration. Build a new dict instead: {k: v for k, v in d.items() if v > 0}.

More on conditions

  • in / not in test membership in any container.
  • is / is not test identity (the same object). Use them for None: if x is None. Use == for values.
  • Comparisons can be chained: a < b == c means a < b and b == c, and 0 <= x < 10 reads like maths.
  • not binds tightest, then and, then or. So A and not B or C means (A and (not B)) or C.

and / or return one of their operands

and and or are short-circuit operators: they stop as soon as the answer is known. They return the last value they looked at, not necessarily True/False.

⚠️ Pitfall: name = user_input or "anonymous" also replaces 0 and "", not just None. When 0 is a valid value, write x if x is not None else default.

The walrus operator :=

:= assigns inside an expression. It is named for its look, like a walrus's eyes and tusks. It is useful when you want to test a value and keep it at the same time.

☕ Java / C: in Python, a plain = inside an if is a SyntaxError. That prevents the classic if (x = 0) bug. You must write := on purpose.

Comparing sequences and other types

Sequences of the same type compare lexicographically, like words in a dictionary: compare the first items; if they are equal, compare the second; and so on. If one sequence runs out first, the shorter one is smaller.

Strings compare by Unicode code point, so every uppercase letter comes before every lowercase letter: 'Z' < 'a'. Comparing unrelated types with < (like 1 < "a") raises TypeError. With == they are simply not equal.

Recap

  • Tuples are immutable records. (x,) is a one-item tuple. Unpacking (a, b = pair) needs the right count.
  • Sets have no duplicates and no order. They support | & - ^. set() is empty; {} is an empty dict.
  • Dicts keep insertion order. d[k] raises KeyError and d.get(k, default) doesn't. d1 | d2 merges. frozendict is new in 3.15.
  • Loop with items(), enumerate(), zip(strict=True), reversed() and sorted().
  • and/or return an operand. Chains like 0 <= x < 10 work. := assigns in an expression. Sequences compare item by item.

Exercise 9 🔴 hard explain why

Why does {["food"]: 1} fail, while {("food",): 1} works? What would go wrong if lists were allowed as keys?

Show solution

A dict stores each key in a slot chosen by its hash. If you could mutate a list key after inserting it, its hash would change, and the dict would look in the wrong slot and "lose" the entry. So mutable built-ins are unhashable. Tuples are immutable, so they are hashable, as long as their items are hashable too.
