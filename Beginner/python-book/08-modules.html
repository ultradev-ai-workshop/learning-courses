What is a module?

A module is simply a .py file. Its name is the file name without .py. Everything defined at the top level of the file (functions, classes, variables) becomes an attribute of the module.

Analogy: a module is a toolbox with a label on it. import fibo brings the whole box onto your desk, and you take tools out with fibo.fib.

Each module has its own namespace (its own set of names). A variable called total inside fibo never clashes with your total. Inside a module, __name__ holds the module's name.

☕ Java: import in Python runs the module's code the first time (like a static initialiser). There is no classpath: Python searches a list of folders (see sys.path below). 🟨 JS: from fibo import fib is like import { fib } from './fibo.js'. Python has no export keyword: every top-level name is importable.

A module's top-level code runs only once per process, the first time it is imported. Later imports reuse the cached module object stored in sys.modules. When you edit a module during a REPL session, either restart the REPL or use importlib.reload(fibo).

The module search path

When you import spam, Python first checks for a built-in module with that name. Then it searches the folders listed in sys.path, in order:

  1. The folder containing the script you ran (or the current folder in the REPL).
  2. The folders in the PYTHONPATH environment variable, if it is set.
  3. The installation defaults: the standard library, then site-packages (where pip installs packages).

⚠️ The shadowing pitfall. The script's own folder comes first. If you name your file random.py, json.py or email.py, then import random loads your file instead of the standard library's, and you get confusing errors like AttributeError: module 'random' has no attribute 'randint'. Never name your files after standard modules.

"Compiled" Python files

To speed up loading, Python caches a compiled version of each imported module in a __pycache__ folder, with names like fibo.cpython-315.pyc. The .pyc file holds bytecode: a lower-level form of your code that the interpreter runs.

  • Python checks the source file's modification time and recompiles automatically when the file changes. You never manage these files yourself.
  • A .pyc file loads faster, but it doesn't run any faster.
  • The script you run directly is not cached; only imported modules are.
  • Add __pycache__/ to .gitignore.

📝 Changed in 3.15: the old module.__cached__ attribute is no longer set. Use module.__spec__.cached if you ever need the .pyc path.

Standard modules and dir()

Python ships with a large standard library of modules (Chapters 13–14). Some, like sys, are built into the interpreter itself.

The built-in dir() lists the names a module defines. With no argument, it lists the names you have defined in the current scope.

Notice fib2 is still listed, even though the second version of fibo.py removed it. This REPL session imported the first version, and a module is loaded only once. Even importlib.reload() re-runs the file into the same module object, so old names stay behind. When in doubt, restart the REPL.

Packages

A package is a folder of modules, which gives you dotted names like sound.effects.echo. Mark a folder as a package by putting an __init__.py file in it. The file can be empty; its code runs when the package is first imported.

  • Run a module that lives in a package with python3 -m shop.cart, from the folder that contains shop/. Running python3 shop/cart.py directly fails, because the file then isn't part of any package, so the relative import has nothing to be relative to.

__all__ and import * from a package

from package import * does not scan the folder for submodules. It imports exactly the names listed in the package's __all__. Without __all__, it only imports the names already defined in __init__.py. Inside a plain module, __all__ limits what import * exports in the same way.

📝 Namespace packages: a folder without __init__.py can still be imported, as a "namespace package", which is used for splitting one package across several locations. Beginners should always add __init__.py; it avoids surprises.

Lazy imports (new in 3.15)

Large programs import many modules at start-up, even ones that are rarely used, and that slows down command-line tools. PEP 810 adds the soft keyword lazy. A lazy import binds the name immediately, but loads the module only the first time the name is used.

  • lazy is only allowed at the module's top level. Inside a function it is a SyntaxError (an import inside a function is already lazy).
  • lazy from module import * is not allowed.
  • It is a soft keyword, so old code that uses lazy as a variable name still works.
  • Errors from a lazy import (such as a missing module) appear at first use, not at the import line.

📝 Older pattern you'll still see: before 3.15, people delayed imports by putting the import statement inside the function that needed it. That still works and is still fine for one-off cases.

Recap

  • A module is a .py file. Prefer import module or from module import name, and avoid import *.
  • A module's code runs once, at its first import. if __name__ == "__main__": guards script-only code.
  • sys.path starts with the script's folder, so don't name files after standard modules.
  • A package is a folder with __init__.py. Inside it, use relative imports (from . import x), and run its modules with python3 -m pkg.mod.
  • lazy import x (3.15) delays loading until first use, and only works at the top level.

Your file is called random.py and does import random; print(random.randint(1, 6)). It fails with AttributeError. Why?

import random finds your random.py first, because the script's folder comes first in sys.path. Your file doesn't define randint. Rename the file and delete the __pycache__ entry for it.

Exercise 8 🟡 medium explain why

Why is lazy import json inside a function a SyntaxError? What would you write instead?

Show solution

A plain import inside a function already runs only when the function is called, so it is lazy already. The lazy keyword exists to delay top-level imports, which normally run at start-up. Inside a function, just write import json.
