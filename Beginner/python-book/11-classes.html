A word about names and objects

Objects have identity, and several names can be bound to the same object. This is called aliasing. It doesn't matter for immutable objects (numbers, strings, tuples), but it matters a lot for mutable ones. You saw it with lists in Chapter 2; it is the same for your own objects.

The upside: passing an object to a function is cheap, because only a reference is passed. And if the function modifies the object, the caller sees the change.

Scopes and namespaces

A namespace is a mapping from names to objects. Examples are the built-in names (len, print), a module's global names, and a function call's local names. Names in different namespaces never clash: fibo.total and report.total can coexist.

A scope is a region of code where a namespace is directly reachable. When Python looks up a bare name, it searches in the LEGB order:

LetterScopeExample
Localthe current functiona variable assigned inside the function
Enclosingany outer functions (for nested functions)rate in make_tax from Chapter 5
Globalthe module's top levelconstants and functions defined in the file
Built-inPython's built-inslen, print, ValueError

The key rule: assigning to a name inside a function makes it local to that function, unless you declare it global (module level) or nonlocal (the enclosing function).

  • do_local creates its own local spam, so the outer one is untouched.
  • do_nonlocal rebinds scope_test's spam.
  • do_global rebinds the module-level spam. scope_test's local spam is unchanged, which is why the third line still shows nonlocal spam.

What is self?

self is the instance the method was called on. Python passes it automatically: lunch.with_tax() is shorthand for Expense.with_tax(lunch). It is Java's this, except that Python makes it an explicit first parameter. The name self is only a convention, but always use it.

☕ Java: there is no field declaration list. Attributes come into existence when they are assigned, normally in __init__. You can even add attributes to an instance later (lunch.note = "x"), though good style keeps them all in __init__. There is no method overloading and no new keyword.

Class and instance variables

Instance variables (self.name = …) belong to one object. Class variables (assigned in the class body) are shared by all instances, like Java static fields. When you read obj.attr, Python looks on the instance first, then on the class.

⚠️ The shared-mutable trap: a mutable class variable, such as a list, is shared by every instance. This is the same bug as the mutable default argument in Chapter 5.

Special ("dunder") methods

Methods with double underscores on both sides, called dunder methods (like __init__), let your objects work with Python's built-in syntax. The three you'll write most often:

toString()__str__ (and __repr__)
equals() / hashCode()__eq__ / __hash__

⚠️ Pitfall: if you define __eq__ but not __hash__, Python sets __hash__ to None, and your objects can no longer go into sets or be dict keys. Dataclasses (below) can handle this for you with frozen=True.

Properties, class methods and static methods

Python doesn't use getters and setters by default: just use plain attributes. If you later need logic, such as validation, turn the attribute into a property. Callers keep writing obj.amount, unchanged.

(@property is a decorator: a function that wraps the function defined on the next line. You'll use decorators like this long before you need to write your own.)

Inheritance

Put the base class in parentheses. A derived class inherits everything from it, and can override methods. super() calls the parent's version.

  • Every class ultimately inherits from object.
  • All methods are "virtual": self.describe() inside a base method calls the subclass override.
  • Use isinstance(obj, Cls) for type checks, not type(obj) == Cls, so that subclasses are accepted too.

Multiple inheritance and the MRO

A class can have several bases: class C(A, B):. Python looks up attributes using the Method Resolution Order (MRO), which is roughly: the class itself, then its bases left to right, with each class appearing only once and always before its parents.

Notice that super() in Left called Right, not Base. super() means "the next class in the MRO of the actual object". In practice, multiple inheritance is mostly used for small mixins: classes that add one feature, like JsonMixin or ReprMixin.

☕ Java: there are no interfaces. Python relies on duck typing ("if it walks like a duck…"): any object with the right methods works. For formal contracts, there are abc.ABC abstract base classes and typing.Protocol (Appendix A).

Private variables

Python has no private keyword. Instead, there are conventions:

  • _name (one underscore): "internal, please don't touch". Nothing enforces it, but everyone respects it, and tools warn about it.
  • __name (two underscores, at most one trailing): name mangling. Python renames it to _ClassName__name, so that subclasses don't clash with it by accident. It is meant to avoid accidents, not to provide security.

Odds and ends: dataclasses

Many classes are just a bundle of named fields. @dataclass generates __init__, __repr__ and __eq__ from type-annotated fields, like Java's record.

💡 When to use what: use a dict for loose, JSON-like data; a tuple or namedtuple for small fixed records; a @dataclass for named records with defaults; and a regular class when there is real behaviour or invariants to protect.

Recap

  • Names are looked up in LEGB order. Assigning inside a function makes a name local; global and nonlocal override that.
  • class C: plus __init__(self, …). obj.m() means C.m(obj). State lives on self.
  • Class variables are shared, so never use a mutable one for per-object data.
  • class Sub(Base): with super() and isinstance(). Multiple inheritance follows the MRO.
  • _x means internal and __x is mangled. Add __repr__/__eq__, use @property for computed or validated attributes, and @dataclass for records.

Show solution

In Python you can start with a plain attribute (e.amount) and later swap in a @property without changing any caller. Java needs getters up front because changing a field to a method later breaks every caller. Python doesn't have that problem.
