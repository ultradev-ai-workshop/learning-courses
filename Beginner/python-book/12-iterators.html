How the for loop really works

Behind the scenes, for x in thing: does three things:

  1. It calls iter(thing) to get an iterator: an object that remembers where it is.
  2. It calls next(iterator) repeatedly, and each call returns the next item.
  3. When there are no more items, next() raises StopIteration, and the loop ends quietly.

Analogy: an iterable is a book, and an iterator is a bookmark in it. You can have many bookmarks in one book. A bookmark only moves forward, and once it reaches the end, it stays there.

Generators

A generator function looks like a normal function, but it uses yield instead of return to hand back values. Calling it doesn't run the body. Instead it returns a generator object, which is an iterator. Each next() runs the body until the next yield, then pauses there and keeps every local variable as it was.

Python creates __iter__ and __next__ for you, saves the state between calls, and raises StopIteration when the function ends. Here is the pausing made visible:

The third call resumed after the last yield, finished the loop, printed done, and reached the end of the function. That means "no more items", so next() returned the default. Without a default it would raise StopIteration.

Why generators matter: laziness

A generator produces items on demand. It never builds the whole sequence in memory, so it can handle huge files, or even infinite sequences.

yield from

yield from iterable yields every item of another iterable. It is handy for delegating to sub-generators, or for walking recursive structures.

Generator expressions

A generator expression is a comprehension written with parentheses instead of brackets. It produces items lazily instead of building a list. When it is the only argument of a function, you can drop the extra parentheses.

📝 New in 3.15: generator expressions accept * unpacking too (PEP 798), so sum(*row for row in matrix) sums every number in a list of lists.

⚠️ Pitfall: any() and all() short-circuit. With a generator, they stop consuming items as soon as the answer is known, and the items they consumed are gone. That is efficient, but surprising if you reuse the generator afterwards.

Lazy pipelines

Generators chain together like a factory line. Each stage pulls one item at a time from the stage before, so even a multi-gigabyte log file uses almost no memory.

Recap

  • for calls iter(), then next() until StopIteration.
  • An iterable can be looped over many times. An iterator is single-use, so convert it with list() if you need it twice.
  • An iterator class needs __iter__ (returning self) and __next__. A generator function with yield does all of that for you.
  • (expr for x in xs) is lazy, which is perfect for sum, any, all, max and join. 3.15 adds * unpacking.
  • Chain generators into memory-light pipelines. Use itertools for counting, slicing, chaining, grouping and batching.
