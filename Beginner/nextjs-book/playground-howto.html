Using the Playground

The playground is the project you build throughout the book: a fresh create-next-app app that the exercises marked playground turn into the Reading List, step by step. Its reference/ folder holds the finished capstone from Chapter 19. This page shows how to get it, the everyday loop of editing, running and building, and what to do when something goes wrong.

You will learn

  • What's in the nextjs-playground repository.
  • The one-time setup: Node.js, cloning, installing.
  • The everyday loop: npm run dev, edit, and regularly npm run build + npm start.
  • How to run the reference solution and its tests.
  • Fixes for the problems beginners hit most often.

What is the playground?

The starter is exactly what npx create-next-app@latest --yes produced with Next.js 16.4.5 when this book was written, so it matches Chapter 2's tour. The only change: tsconfig.json and eslint.config.mjs ignore reference/, which is a separate app.

One-time setup

  1. Install Node.js 20.9 or newer (the LTS version from nodejs.org, or with a version manager such as nvm). Check it:
  1. Clone the repository and install its dependencies:
  1. Open the folder in your editor. In VS Code, choose TypeScript: Select TypeScript Version → Use Workspace Version to activate the Next.js TypeScript plugin, and optionally add the tab labels from Chapter 2.

📝 Prefer to start from scratch? npx create-next-app@latest nextjs-playground --yes gives you the same starter (with whatever Next.js version is current). The reference solution is the part you'd miss, so clone the repo anyway.

The everyday loop

StepCommandWhy
1. Developnpm run devOpens localhost:3000. Edits appear immediately (Fast Refresh). Errors appear in an overlay in the browser and in the terminal.
2. Buildnpm run buildType-checks, prerenders and prints the route table (○ ◐ ƒ). Many problems (type errors, Cache Components rules) only appear here.
3. Run the buildnpm startServes the production build: real caching, prefetching and streaming. Stop npm run dev first, or use another port: npm start -- -p 4000.
4. Lintnpm run lintESLint with the Next.js rules (not run by next build since version 16).
5. Testnpm run test (after Chapter 17)Vitest unit tests; Playwright for end-to-end tests.

💡 Make build often a habit: after every chapter, run npm run build. The book's examples show many errors (missing <Suspense>, Date.now() during prerendering, dynamicParams with Cache Components) that development mode doesn't report.

Running the reference solution

Log in at /login as ada@example.com / correct horse (admin) or ben@example.com / battery staple (reader). Run the tests with npm run test:run (Vitest) and, while npm start is running, npm run test:e2e (Playwright, using your installed Chrome). Adding books changes data/books.json; restore it with git checkout data/books.json.

Troubleshooting

SymptomCause and fix
next: command not foundRun npm install first; use the npm scripts (npm run dev) or npx next ….
Port 3000 is in useAnother server is running (often an old npm run dev). Stop it, or use npm run dev -- -p 3001.
"Next.js encountered uncached or runtime data during prerendering"A component reads params, searchParams, cookies(), headers() or slow data outside <Suspense>. Wrap it, cache it with "use cache", or use generateStaticParams (Chapters 4, 6, 8).
"…encountered the unstable value new Date()" (or Math.random())Call await connection() first inside <Suspense>, or cache the value (Chapter 8).
"You're importing a module that depends on useState into a React Server Component"Add "use client" to that file, or move the interactive part into its own Client Component (Chapter 5).
"Route segment config "dynamicParams" is not compatible with nextConfig.cacheComponents"Remove old route segment options (dynamicParams, dynamic, revalidate); use notFound() and cacheLife instead (Chapters 4, 8).
My change doesn't show up after a Server ActionThe data is cached: call updateTag/revalidateTag/revalidatePath in the action (Chapter 9).
Works in npm run dev, fails in npm run build with a Type errornext dev doesn't type-check. Fix the error (your editor shows it with the workspace TypeScript).
Styles missing after adding proxy.tsAdd a matcher that skips _next/static and _next/image (Chapter 15).
An environment variable is undefined in the browserOnly NEXT_PUBLIC_ variables reach the browser, and they're fixed at build time: rebuild after changing them (Chapter 16).
reference/ shows type errors in the starterMake sure tsconfig.json excludes "reference" (it does in the repo); open reference/ as its own folder to work on it.
The reference folder doesn't existYou downloaded only part of the repository: clone nextjs-playground again.

Recap

  • Clone coderhop-learning/nextjs-playground, run npm install, then npm run dev.
  • The root is a create-next-app starter; reference/ is the finished capstone.
  • Develop with npm run dev, but build and start often to see production behaviour and errors.
  • The troubleshooting table maps the common error messages to the chapter that explains them.
