Installation & Project Structure

This chapter follows the docs' Installation and Project Structure pages. You'll create an app with create-next-app, learn the three scripts you use every day, and take a tour of every file the generator writes. By the end, you'll know which files are Next.js conventions and which are just your code.

You will learn

  • The system requirements, and how to create an app with create-next-app.
  • What the recommended defaults switch on: TypeScript, Tailwind CSS, ESLint, App Router, Turbopack, Cache Components.
  • next dev, next build and next start: when to use each.
  • What each generated file is for, and which top-level files and folders Next.js recognises.
  • The @/* import alias, the optional src folder, and editor setup.

System requirements

  • Node.js 20.9 or newer. Check with node --version. This book used Node 22.
  • macOS, Windows (including WSL) or Linux.
  • A modern browser: Chrome/Edge/Firefox 111+ or Safari 16.4+.

A tour of the generated project

next.config.ts

  • cacheComponents: true turns on the Cache Components model: data is dynamic unless you cache it with "use cache", and Next.js prerenders a static shell for every page (Chapter 8).
  • partialPrefetching: true lets <Link> prefetch the static part of the next page ahead of time (Chapter 4).
  • The turbopack.rules entry runs every CSS file through Tailwind's Turbopack loader.

The file is TypeScript, and the NextConfig type gives autocomplete for every option.

tsconfig.json and next-env.d.ts

Three lines matter most. "strict": true turns on strict type checking. "noEmit": true means TypeScript only checks, and Next.js compiles. "paths" defines the @/ alias. The next plugin teaches your editor Next.js rules, and the .next/types include adds the types Next.js generates from your routes, such as PageProps and LayoutProps.

app/layout.tsx: the root layout

The root layout wraps every page. It's required, and it must render <html> and <body>. The generated one also loads two fonts with next/font (Chapter 12) and sets metadata (Chapter 13):

public/

Files in public/ are served at the site root, unchanged: public/next.svg is /next.svg. Use it for files that need a fixed URL, such as robots.txt or downloadable PDFs.

⚠️ Don't put secrets in public/: everything there is downloadable by anyone. And don't give a file the same path as a route: the public file wins, and the page can't be reached.

Which files and folders are Next.js conventions?

The docs' Project Structure page lists every convention. You'll meet each one in this book; here is the map.

Top-level folders and files:

NamePurposeChapter
app/The App Router: routes, layouts, pages3
pages/The older Pages RouterApp. B
public/Static files served as-is2
src/Optional folder that holds app/ and your code2
next.config.tsNext.js configuration2, 18
proxy.tsCode that runs before requests are routed (formerly middleware.ts)15
instrumentation.tsMonitoring and OpenTelemetry setup18
.env, .env.local, .env.development, .env.productionEnvironment variables (keep out of git)16
next-env.d.tsGenerated TypeScript declarations (keep out of git)2

Routing files inside app/ (each can be .js, .jsx or .tsx; route is .js or .ts):

FilePurposeChapter
layoutShared UI that wraps a segment and its children3
pageThe UI of a route; makes it public3
loadingLoading UI (a Suspense boundary)6
error / global-errorError UI (an error boundary)10
not-found"Not found" UI10
routeAn API endpoint14
templateA layout that re-mounts on navigation3
defaultFallback for a parallel route slot4

Folder name patterns: [slug] (dynamic segment), [...slug] (catch-all), [[...slug]] (optional catch-all), (group) (route group, not in the URL), _folder (private, never routed), @slot (parallel route) and (.)folder (intercepting route). Chapters 3 and 4 cover them.

Metadata files: favicon.ico, icon, apple-icon, opengraph-image, twitter-image, robots, sitemap and manifest, in Chapter 13.

🧠 Analogy: the app/ folder is a building's floor plan. Folders are corridors (URL segments). A page file is a door that opens to the public: without one, the corridor exists but nobody can enter. A layout is the wallpaper and lighting shared by everything down that corridor. Any other file you leave in a corridor is furniture: it's there for you, not for visitors.

The @/ import alias

Deeply nested files lead to imports like ../../../lib/format. The paths entry in tsconfig.json lets you write @/lib/format from anywhere:

lib/ isn't special to Next.js: it's a common name for shared code. Next.js only cares about app/ and the files listed above.

The optional src folder

Some teams prefer to keep code apart from configuration files. Move app/ (and lib/, components/…) into src/. Config files (package.json, next.config.ts, tsconfig.json, .env*) and public/ stay at the root. If you use the alias, point it at ./src/*. Pick one layout and use it everywhere. This book uses the default: no src/.

Set up your editor

  • Use the workspace TypeScript. In VS Code, open the command palette and run TypeScript: Select TypeScript Version → Use Workspace Version. That activates Next.js's TypeScript plugin, which warns about mistakes such as an invalid config export in a page.

The CLI. The next command has a few more subcommands worth knowing:

  • next typegen generates the route types (PageProps, LayoutProps) without a full build. It's handy in CI before running tsc.
  • next info prints your system and package versions. Paste its output into bug reports.
  • next upgrade updates Next.js and React to the latest version (Chapter 18).
  • next dev -p 4000 or next start -p 4000 uses another port.

The error has the format file(line,column): error TScode: message. next dev would still show the page (it doesn't type-check), but next build refuses to produce a build with type errors. That's one more reason to build often.

Recap

  • You need Node.js 20.9+. npx create-next-app@latest my-app --yes creates an app with TypeScript, Tailwind, ESLint, the App Router, Turbopack and Cache Components.
  • next dev is for writing code; next build compiles, type-checks and prerenders; next start serves the build.
  • app/layout.tsx (with <html> and <body>) and app/page.tsx are the only files an app needs.
  • public/ files are served at the root; next.config.ts configures Next.js; next-env.d.ts is generated.
  • @/ imports from the project root; src/ is optional.
  • Your version's docs are in node_modules/next/dist/docs/.

Exercises

Exercise 1 🟢 easy recall

Which two files must every App Router app have? What must the first one contain?

Show solution

app/layout.tsx (the root layout) and at least one page file, usually app/page.tsx. The root layout must render the <html> and <body> tags.

Exercise 2 🟢 easy match

Which script would you run (a) while editing code, (b) to check that the app compiles and type-checks, (c) on the production server, (d) to find unused variables?

Show solution

(a) npm run dev, (b) npm run build, (c) npm start (after a build), (d) npm run lint.

Exercise 3 🟢 easy where does it go?

Where do these belong: (a) logo.png referenced as /logo.png, (b) the "about us" page, (c) a helper slugify(), (d) the setting cacheComponents?

Show solution

(a) public/logo.png. (b) app/about/page.tsx. (c) Anywhere you like, typically lib/slugify.ts, imported as @/lib/slugify. (d) next.config.ts.

Exercise 4 🟢 easy true or false

True or false? (1) next build runs ESLint. (2) next dev type-checks every file. (3) next-env.d.ts should be committed and edited by hand. (4) The lib folder name has special meaning.

Show solution

All false. (1) Since Next.js 16, run the linter yourself. (2) Only next build (or your editor, or tsc) type-checks. (3) It's generated; keep it out of git. (4) It's just a common convention.

Exercise 6 🟡 medium investigate

Run npm run build in the playground, then look inside .next/. Find the prerendered HTML of the home page. Does it contain your book count?

Show solution

The file is .next/server/app/index.html. Search it with grep "books to read" .next/server/app/index.html: the text is there, because the page was prerendered at build time. That's also why changing lib/books.ts needs a new build in production. Chapters 8 and 9 show how to refresh content without rebuilding.

Exercise 7 🟡 medium public folder

Add public/about.txt containing "Reading List v1". Which URL serves it? What happens if you also create app/about.txt/page.tsx?

Show solution

It's served at /about.txt. If you also add the page, the build succeeds and lists a route /about.txt, but requests for /about.txt still return the public file. The page can never be reached, and nothing warns you (tested with Next.js 16.4.5). Public files and routes share one URL space, so give them different names.

Exercise 8 🟡 medium fix the build

A teammate's page works in npm run dev but npm run build fails with Type error: Property 'titel' does not exist on type 'Book'. Why didn't dev catch it, and how do you fix it?

Show solution

next dev compiles TypeScript by removing types, without checking them, to stay fast. next build runs the type checker. The fix is to correct the typo (book.title). To catch this earlier, use the workspace TypeScript in your editor, or run npx tsc --noEmit in CI.

Exercise 9 🔴 hard src folder

Convert the playground to use a src/ folder. List every file you move, every file you leave, and the one config change you need.

Show solution

Move app/ and lib/ into src/. Leave public/, package.json, next.config.ts, tsconfig.json, eslint.config.mjs, next-env.d.ts and any .env* files at the root. Change the alias in tsconfig.json to "@/*": ["./src/*"]. (If you add proxy.ts or instrumentation.ts later, they go in src/ too.) Run npm run build to confirm.

Exercise 10 🔴 hard explain

Explain why the docs recommend building and starting your app locally before deploying, using what you learned about next dev versus next build. Give two kinds of problems that only show up in the build.

Show solution

next dev renders every page on each request and skips type checking, so it hides problems that production has. Only the build shows: (1) type errors, which fail the build; (2) prerendering errors, for example the Cache Components rule that request data must be inside <Suspense> (you'll meet it in Chapter 4), which only runs when the build prerenders pages. Caching behaviour is also only realistic with next start.
