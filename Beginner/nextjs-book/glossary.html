Reference

Glossary

The Next.js terms used in this book, in plain words, each with the chapter where it's explained. The docs have their own glossary too.

App Router
The router based on the app/ folder, with Server Components, layouts and streaming. The one this book teaches. Ch. 1
App Shell
The reusable static shell of a dynamic route whose params aren't known at build time; served instantly while the rest streams in. Ch. 8
Build
next build: compiles, type-checks, prerenders and prints the route table. Ch. 2
Cache Components
The caching model enabled with cacheComponents: true: everything is dynamic unless cached with "use cache", and every route gets a static shell. Ch. 8
Cache key
What identifies a cached result: the function, its arguments and captured values, and the build ID. Ch. 8
cacheLife
Sets a cache entry's stale, revalidate and expire times, by profile (hours, max…) or object. Ch. 8
cacheTag
Labels cache entries so they can be invalidated on demand. Ch. 9
Client Component
A component in a file marked "use client" (or imported by one): prerendered to HTML, then hydrated so it can use state, effects and events. Ch. 5
Client-side transition
Navigating with <Link> without a full page reload, keeping shared layouts. Ch. 4
Codemod
A script that rewrites your code for an API change, e.g. middleware-to-proxy. Ch. 18
Colocation
Keeping components and helpers next to the routes that use them; safe because only page/route files are public. Ch. 3
connection()
From next/server: marks that the following code must run at request time (for random values, the current time…). Ch. 8
Data access layer (DAL)
A server-only module that all data reads go through, with auth checks (verifySession) in one place. Ch. 16
Digest
A hash attached to server errors in production; the server log shows the real error with the same digest. Ch. 10
Data transfer object (DTO)
An object with only the fields a caller may see, returned by the DAL instead of a whole database record. Ch. 16
Dynamic rendering
Rendering at request time, because the content depends on the request or uncached data. Marked ƒ or streamed parts of ◐. Ch. 4
Dynamic segment
A folder name in brackets ([id], [...slug], [[...slug]]) that matches part of the URL and becomes params. Ch. 4
Error boundary
A component that catches rendering errors below it and shows a fallback: error.tsx, global-error.tsx, catchError. Ch. 10
Fast Refresh
Instant updates in the browser while you edit, keeping component state, in next dev. Ch. 2
generateStaticParams
Returns the param values to prerender for a dynamic route at build time. Ch. 4
Hydration
React attaching event handlers to server-rendered HTML in the browser, making Client Components interactive. Ch. 5
ImageResponse
From next/og: turns JSX into a PNG, for Open Graph images and icons. Ch. 13
Interleaving
Passing Server Components to Client Components as children or other props. Ch. 5
ISR (Incremental Static Regeneration)
Older name for refreshing prerendered pages after a time or an event; with Cache Components, cached data with cacheLife and tags. Ch. 1
Layout
Shared UI that wraps a route segment and its children, and keeps its state on navigation. Ch. 3
Metadata API
metadata and generateMetadata exports that produce <head> tags. Ch. 13
NEXT_PUBLIC_
Prefix for environment variables that are inlined into browser JavaScript at build time. Ch. 16
Page
A page.tsx file: the UI of a route, which makes the route public. Ch. 3
Pages Router
The original router, based on the pages/ folder, with getStaticProps and getServerSideProps. App. B
Partial Prefetching
partialPrefetching: true: <Link> prefetches each route's static shell ahead of the click. Ch. 4
Partial Prerendering (PPR)
A page made of a prerendered static shell with dynamic parts streamed in; the default with Cache Components. Marked ◐. Ch. 8
Prefetching
Loading a route in the background when its <Link> comes into view, so navigation feels instant. Production only. Ch. 4
Prerendering
Rendering at build time (or during revalidation) and storing the result. Ch. 1
Private folder
A folder starting with _ that's never routed. Ch. 3
Progressive enhancement
Forms with Server Actions work before (or without) JavaScript, as plain HTML forms. Ch. 7
Proxy
proxy.ts (formerly Middleware): code that runs before routes, to redirect, rewrite or change headers. Ch. 15
Revalidation
Refreshing cached data: time-based with cacheLife, or on demand with updateTag, revalidateTag, revalidatePath. Ch. 9
Route group
A folder in parentheses, (name), that organises routes without appearing in the URL. Ch. 3
Route Handler
A route.ts file that answers HTTP requests with the web Request/Response APIs. Ch. 14
Route segment
One folder of a route; /blog/authors has the root, blog and authors segments. Ch. 3
RSC Payload
The serialized result of rendering Server Components: rendered output, Client Component references and their props. Ch. 5
Runtime data
Data that depends on the request: cookies(), headers(), searchParams, unknown params. Must be read inside <Suspense>. Ch. 4
Server Action
A Server Function used for a mutation, typically passed to a form's action. Ch. 7
Server Component
The default kind of component in app/: runs on the server or at build time, can be async, and ships no JavaScript. Ch. 5
Server Function
An async function marked "use server" that the client can call over the network (a POST). Ch. 7
Session (stateless)
Login state stored in a signed or encrypted cookie, verified on each request. Ch. 16
Standalone output
output: "standalone": a minimal server.js with only the files the app needs, for small Docker images. Ch. 18
Static export
output: "export": HTML files in out/ for any static host; no server features. Ch. 18
Static shell
The prerendered part of a page, including Suspense fallbacks, sent immediately. Ch. 6
Streaming
Sending a page in chunks in one response: the shell first, then each Suspense boundary's content as it's ready. Ch. 6
Stale-while-revalidate (SWR)
Serving the old cached value immediately while refreshing it in the background. Ch. 9
Template
A template.tsx file: like a layout, but re-mounted on every navigation. Ch. 3
Turbopack
The default bundler for next dev and next build. Ch. 2
Uncached data
I/O that doesn't finish during prerendering (database queries, fetch, async file reads): stream it or cache it. Ch. 6
"use cache"
Directive that caches the return value of an async function or component. Ch. 8
"use client"
Directive that marks a file as the entry to the client bundle. Ch. 5
"use server"
Directive that marks a function, or every export of a file, as a Server Function. Ch. 7
updateTag / revalidateTag
Expire tagged cache entries now (Server Actions only) / mark them stale for a background refresh (also Route Handlers). Ch. 9
