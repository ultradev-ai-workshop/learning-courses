React & TypeScript for Next.js

The docs assume you know HTML, CSS, JavaScript and React. This appendix is a compact refresher of the React and TypeScript you need for this book: components and JSX, props and their types, state, events, effects, lists, forms, context, refs and custom hooks. Every example is a Client Component in a real Next.js app, checked in a browser. For the full story, see the React Beginner Book and the TypeScript Study Book.

  • The TypeScript features you'll meet most: unions, optional props, type vs interface.

Components, JSX and props

A component is a function that returns JSX. Its name starts with a capital letter. JSX looks like HTML with a few differences: className instead of class, htmlFor instead of for, every tag must be closed, a component returns one root element (or a fragment <>…</>), and { } embeds any JavaScript expression.

Props are the component's arguments, passed like HTML attributes. In TypeScript, describe them with a type:

These two are Server Components (no "use client"): plain components without state can run on either side (Chapter 5).

State and events

useState keeps a value between renders; calling its setter re-renders the component. Event handlers receive typed event objects. Hooks only work in Client Components, and only at the top level of a component (not inside conditions or loops).

setCount((c) => c + 1) uses the updater form, which is correct even when several updates happen before the next render. The input is controlled: its value always comes from state.

"Dune" was marked read, then the filter hid both read books. {cond && <X />} renders X only when cond is true; use a ternary {cond ? <A /> : <B />} to choose between two. Watch out: {count && …} renders "0" when count is 0, so compare explicitly (count > 0 && …).

Effects and cleanup

useEffect runs code after rendering, to synchronize with something outside React: timers, subscriptions, browser APIs. Return a cleanup function to undo it. The dependency array lists the values the effect reads; it re-runs when they change.

💡 In Next.js, you need far fewer effects than in a single-page app: don't fetch data in effects when a Server Component can load it (Chapter 6). Effects are for browser-only work: reading window, localStorage, subscribing to events.

Custom hooks

A custom hook is a function whose name starts with use and that calls other hooks. It shares logic, not state: each component that calls it gets its own state.

Recap

  • Components are capitalised functions returning JSX; props are typed with a type or interface; React.ReactNode types children.
  • useState + event handlers make Client Components interactive; never mutate state, create new objects and arrays.
  • Lists need stable keys; render conditionally with && and ternaries.
  • useEffect is for syncing with the outside world, with cleanup; don't fetch data in effects when a Server Component can.
  • Context shares values deeply; refs hold DOM nodes or mutable values; custom hooks share logic.

class → className; for → htmlFor; <input /> and <img /> must be closed (and the image needs alt, or use <Image>); two root elements need a fragment <>…</> around them.

Exercise 3 🟢 easy predict

What does {items.length && <p>{items.length} items</p>} render when items is empty? How do you fix it?

Show solution

It renders 0, because 0 && … evaluates to 0, which React renders as text. Use {items.length > 0 && …}.

Exercise 4 🟢 easy keys

Why is key={index} a problem in a list where items can be deleted or reordered?

Show solution

Keys tell React which item is which between renders. With indexes, deleting the first item makes every other item "become" the one before it, so state inside list items (an open menu, typed text) moves to the wrong item. Use a stable ID from the data.

Exercise 6 🟡 medium effect

Write a useLocalStorage(key, initial) hook that reads the stored value after mounting and saves changes. Why must the read happen in an effect in Next.js?

Show solution

Client Components are also prerendered on the server, where localStorage doesn't exist. Effects only run in the browser, after hydration, and the first render matches the server's HTML.

Exercise 7 🟡 medium lifting state

Two sibling components, Filter (a text input) and BookList, must share the filter text. Where does the state live, and how do they get it?

Show solution

In their closest common parent, a Client Component holding const [filter, setFilter] = useState(""). It passes value={filter} and onChange={setFilter} to Filter, and filter={filter} to BookList. In Next.js, consider putting it in the URL (?q=, Chapter 4) instead: then it survives reloads and can be shared, and a Server Component can filter.

Exercise 8 🟡 medium TypeScript

Type an onSubmit handler for a form, and an onChange for a <select>.

Show solution

function onSubmit(e: React.FormEvent<HTMLFormElement>) { e.preventDefault(); … } and function onChange(e: React.ChangeEvent<HTMLSelectElement>) { setGenre(e.target.value); }. In Next.js, forms often use a Server Action with action instead (Chapter 7), and then you don't need onSubmit at all.

Exercise 9 🔴 hard debug

This effect causes an endless loop. Why, and how do you fix it?

Show solution

The effect depends on options, and sets options to a new object every time, which changes the dependency and runs the effect again, forever. Remove the pointless setOptions. Better still, don't store derived data in state at all: compute const books = sortBooks(allBooks, options) during render (wrap it in useMemo only if it's expensive).

Exercise 10 🔴 hard server or client

You're porting a React SPA component that fetches books in useEffect, shows a spinner, stores them in state and renders a filter input. Rewrite its structure the Next.js way.

Show solution

Split it. A Server Component page awaits getBooks() (cached or inside <Suspense> with a skeleton fallback, which replaces the spinner) and renders a small Client Component <BookFilter books={books} /> that holds only the filter text in state and filters the received array. The effect, the loading state and the fetch code disappear; the book data is in the first HTML response. If the list is large, filter on the server with searchParams instead (Chapter 4).
