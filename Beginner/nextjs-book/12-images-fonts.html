Images & Fonts

Images and fonts are usually the heaviest things on a page, and the most common cause of content jumping around while it loads. Next.js has two built-in tools for them: the <Image> component and next/font. This chapter follows the docs' Image Optimization and Font Optimization pages and checks, with real requests, what each one does.

You will learn

  • What <Image> adds to <img>: sizes, formats, lazy loading and no layout shift.
  • Local images, statically imported images, and remote images with remotePatterns.
  • width, height, fill, sizes, loading/fetchPriority and placeholder.
  • Self-hosted Google Fonts and local fonts with next/font.
  • Applying fonts with className or CSS variables, and with Tailwind.

The Image component

<Image> (from next/image) extends the HTML <img> element with:

  • Size optimization: it serves an image resized for each device, in a modern format such as WebP.
  • Visual stability: it reserves the image's space before it loads, so content doesn't jump (no layout shift).
  • Faster page loads: images load only when they come into view (native lazy loading), optionally with a blurred placeholder.
  • Asset flexibility: images are resized on demand, including images on remote servers.

Remote images

For an image on another server, give the full URL. Next.js can't read remote files during the build, so you must provide width and height. And to stop anyone using your optimizer for arbitrary sites, you must allow the host in next.config.ts with images.remotePatterns. Be as specific as possible:

Sizing props

PropUse
width, heightThe intrinsic size in pixels (for the aspect ratio), not necessarily the displayed size. Style the displayed size with CSS.
fillFill the parent element instead (the parent must be position: relative, fixed or absolute). Use with object-fit in CSS.
sizesHow wide the image is at different screen widths, e.g. "(max-width: 640px) 100vw, 33vw". It lets the browser pick a smaller file. Important with fill.
loading="eager", fetchPriority="high"For the main image above the fold (the "Largest Contentful Paint" image): don't lazy-load it, and download it first. (preload also adds a preload link; priority is deprecated since Next.js 16.)
placeholder"blur" (with static imports or blurDataURL) or "empty".
quality1–100; the allowed values are set by images.qualities in the config (default 75).

⚠️ alt is required. Describe the image for people who can't see it ("Cover of Dune"), or use alt="" for purely decorative images.

Fonts with next/font

next/font loads web fonts with no layout shift and no requests to a third party. It self-hosts every font: the font files are downloaded at build time and served from your own domain, so a visitor's browser never contacts Google. It also generates a size-adjusted fallback font, so text doesn't jump when the web font arrives.

CSS variables and Tailwind

Instead of className, the variable option exposes the font as a CSS variable. This is how create-next-app does it (Chapter 2): the layout adds geistSans.variable to <html>, and globals.css maps it into Tailwind's theme with --font-sans: var(--font-geist-sans), so the font-sans utility uses Geist. Use this when you need several fonts (one for headings, one for code).

Recap

  • <Image> serves resized, modern-format images through /_next/image, lazy-loads them and reserves their space.
  • Local string paths need width/height; static imports provide them and a blur placeholder.
  • Remote images need width/height and an allow-list in images.remotePatterns; other hosts get a 400.
  • Use fill + sizes for responsive boxes, and loading="eager"/fetchPriority="high" for the main image above the fold. Always write alt.
  • next/font self-hosts Google and local fonts, adds a fallback to avoid layout shift, and never contacts Google from the browser.
  • Apply fonts with className, or with variable + CSS/Tailwind for several fonts.

Exercises

Exercise 1 🟢 easy recall

Name four things <Image> does that a plain <img> doesn't.

Show solution

Serves correctly sized images per device (via srcset), converts to modern formats like WebP, prevents layout shift by reserving space, lazy-loads by default (with optional blur placeholders), and resizes remote images on demand.

Exercise 2 🟢 easy which props?

Which props are required for (a) src="/logo.png", (b) src={logo} from import logo from "./logo.png", (c) src="https://cdn.example.com/a.jpg"?

Show solution

All need alt. (a) width and height (or fill). (b) Nothing else: the size comes from the import. (c) width and height (or fill), plus a matching remotePatterns entry in the config.

Exercise 3 🟢 easy true or false

True or false? (1) With next/font/google, visitors' browsers download the font from Google. (2) width sets the displayed width. (3) Images are lazy-loaded by default. (4) Any remote host can be used with <Image>.

Show solution

(1) False: fonts are self-hosted. (2) False: it's the intrinsic size for the aspect ratio; CSS sets the displayed size. (3) True. (4) False: only hosts in remotePatterns.

Exercise 4 🟢 easy alt text

Write good alt text for: (a) a book cover on its detail page, (b) a decorative background swirl, (c) a chart showing books read per month.

Show solution

(a) "Cover of Dune by Frank Herbert". (b) "" (decorative, so screen readers skip it). (c) A short summary of what the chart shows, e.g. "Bar chart: 3 books read in January, 5 in February, 2 in March", or describe it in nearby text.

Exercise 5 🟡 medium playground

Give each book in the playground a cover field (a path in public/covers/), and show it on the detail page with <Image> (200 px wide, fetchPriority="high") and as a 64 px thumbnail in the list. Use the book title in the alt text.

Show solution

In the list, use width={600} height={900} style={{ width: 64, height: "auto" }} and leave the default lazy loading.

Exercise 6 🟡 medium config

Your covers come from https://images.openlibrary.example/covers/* and avatars from https://avatars.example.com/u/*. Write the images.remotePatterns config, as specific as possible.

Show solution

Both forms are accepted. Avoid patterns like { hostname: "**" }, which would let anyone use your server to optimize any image on the internet.

Exercise 7 🟡 medium fonts

Use two Google fonts in the playground: Geist for text and Geist_Mono for ISBN numbers. Expose both as CSS variables and use Tailwind's font-mono for ISBNs.

Show solution

That's exactly the create-next-app setup from Chapter 2: call Geist({ variable: "--font-geist-sans", subsets: ["latin"] }) and Geist_Mono({ variable: "--font-geist-mono", subsets: ["latin"] }), add both .variable class names to <html>, and in globals.css map --font-sans: var(--font-geist-sans) and --font-mono: var(--font-geist-mono) inside @theme inline. Then write <span className="font-mono">{book.isbn}</span>.

Exercise 8 🟡 medium investigate

Open the playground's book list in Chrome DevTools, Network tab, filtered to "Img", and scroll slowly. When are covers downloaded? What format and size are they?

Show solution

Only covers near the viewport are downloaded at first; others load as you scroll (lazy loading). Each request goes to /_next/image?url=…&w=…&q=75, and the response type is image/webp (or AVIF if enabled). The w depends on the displayed size and your screen's pixel density.

Exercise 9 🔴 hard explain

Why does Next.js refuse /_next/image requests for hosts not in remotePatterns, and widths not in its configuration? What could an attacker do otherwise?

Show solution

Image optimization costs CPU, memory and storage. Without an allow-list, anyone could use your server as a free image-resizing service for any site (costing you money), and as a proxy to fetch arbitrary URLs from your server's network. Without fixed widths, an attacker could request thousands of unique sizes to fill your image cache and exhaust resources.

Exercise 10 🔴 hard layout shift

A page shows a grid of covers with plain <img src> tags and a font from a <link> to Google Fonts. Users complain that "everything jumps" while loading. Explain both causes and how <Image> and next/font fix them.

Show solution

Images without dimensions take no space until they load, then push content down. <Image> always has a width and height (or fill in a sized box), so the space is reserved. The web font arrives after the text is drawn in a fallback font with different metrics, so lines re-wrap. next/font preloads the self-hosted file and generates a fallback font adjusted to the same size, so the swap barely moves anything.
