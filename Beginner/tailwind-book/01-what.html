What Tailwind CSS Is

Tailwind CSS is a CSS framework made of thousands of small classes, such as flex, pt-4, text-center and rotate-90. You style a page by putting these classes on your HTML elements instead of writing CSS rules in a separate file. A build tool scans your files, finds the class names you used, and writes a stylesheet that contains only those. This chapter shows what that looks like, what really ends up in the CSS file, and how this differs from writing regular CSS.

You will learn

  • What "utility-first" means, with a first example.
  • How Tailwind turns class names in your HTML into a CSS file, and why the file stays small.
  • What a utility class really contains: theme variables, layers, and plain CSS.
  • The main differences between Tailwind and hand-written CSS, and where each one fits.
  • How the examples in this book are built and checked.

How it works: scan, generate, done

Tailwind is not a big stylesheet you download. It is a build step:

  1. It scans your source files (HTML, JavaScript, templates…) for anything that looks like a class name.
  2. For every name that matches a Tailwind utility, it generates the CSS rule.
  3. It writes all of them, plus a small reset called Preflight, to one CSS file.

🧠 Analogy: a hand-written stylesheet is a made-to-measure suit: every rule is cut for one element, and you keep adding new suits. Tailwind is a wardrobe of standard pieces (a blue shirt, a grey jacket, size 4 shoes) that you combine on each person. The wardrobe is huge, but the build step only packs the pieces someone actually wears into your suitcase.

What is in the whole file?

The generated output.css has a fixed structure. The CSS @layer rule names layers and fixes their order; later layers win over earlier ones, whatever the selectors:

LayerWhat's in it
themeThe design tokens you used, as CSS variables on :root: colours, spacing, font sizes…
basePreflight, a reset that removes browser default margins, heading sizes and list bullets so every browser starts from the same place. Your own base styles go here too.
componentsEmpty by default; for your own reusable classes like .card (Chapter 10).
utilitiesOne rule per class you used. Last layer, so a utility always beats base and component styles.
propertiesFallback values for internal variables like --tw-font-weight, for browsers without @property.

Because only used classes are generated, the file stays small. This tiny page produces about 6 KB, most of it Preflight. A real site usually ends up between 10 and 30 KB, and much less after compression.

Tailwind vs writing regular CSS

Here is the same button written both ways. First, regular CSS: you invent a class name, then write its rules in a stylesheet.

Now with Tailwind: no name, no separate file. The hover: prefix applies a class only on hover (Chapter 5).

Where styles liveA separate .css file, linked by a class name you inventIn the markup, next to the element
NamingYou name everything (.card__title--large)No names needed for most things

⚠️ Tailwind is still CSS. flex is display: flex; justify-between is justify-content: space-between. If you don't know what flexbox does, the class names won't save you. This book explains the CSS behind each utility as it goes.

Isn't this just inline styles?

It looks similar, but utility classes can do things the style attribute can't:

  • States: hover:bg-sky-600, focus:outline-2. Inline styles have no hover.
  • Responsive design: md:flex applies from a screen width up. Inline styles can't use media queries.
  • A design system: p-4 comes from a spacing scale; style="padding: 17px" comes from nowhere.
  • Size: a class is defined once in the CSS file and reused everywhere it appears.

The colours come back as oklch(…) because Tailwind v4's palette is defined in the OKLCH colour space (Chapter 8). The browser reports the colour the way it was written.

Versions: this book uses Tailwind CSS v4.3

Tailwind changed a lot in version 4 (January 2025). The biggest differences from v2 and v3:

  • Configuration is in CSS. You write @import "tailwindcss"; and customise with @theme in the same file. The tailwind.config.js file is optional and only for older projects.
  • No content or purge list. Tailwind finds your source files automatically.
  • A new engine that builds much faster, and modern CSS everywhere: cascade layers, @property, color-mix(), OKLCH colours, container queries.

Many tutorials online still show v2 or v3 code. If you see @tailwind base; or a tailwind.config.js with purge: [...], it's old. Appendix A maps old code to new. v4 needs a modern browser: Safari 16.4+, Chrome 111+, Firefox 128+.

Recap

  • Tailwind is a utility-first CSS framework: you style elements with small single-purpose classes in the markup.
  • It's a build step: it scans your files and generates CSS only for the classes you used.
  • The output has layers: theme (variables), base (Preflight), components, utilities. Utilities come last and win.
  • Utilities point to theme variables like --text-3xl and --spacing.
  • Unlike inline styles, utilities support states, breakpoints and a consistent scale.
  • This book uses Tailwind v4.3: configuration in CSS, automatic source detection, a modern-browser baseline.

Exercises

Exercise 1 🟢 easy read

Say in plain words what each class does: p-6, rounded-xl, text-slate-500, font-medium, shadow-lg.

Show solution

p-6: padding on all sides (6 × 0.25 rem = 1.5 rem). rounded-xl: rounded corners (0.75 rem radius). text-slate-500: text colour, a mid grey from the slate palette. font-medium: font weight 500. shadow-lg: a large box shadow.

Exercise 2 🟢 easy concept

You use the class bg-red-500 in one HTML file, and nowhere else. Then you delete that element. What happens to the rule for .bg-red-500 in the next build?

Show solution

It disappears. Tailwind only generates rules for class names it finds when it scans your files. No other file mentions bg-red-500, so the rule (and the --color-red-500 variable) are not in the output.

Exercise 3 🟢 easy layers

Which layer of the generated CSS contains: (a) --spacing: 0.25rem, (b) the reset that removes h1 margins, (c) .underline?

Show solution

(a) theme; (b) base (Preflight); (c) utilities.

Exercise 4 🟢 easy spot the old code

A tutorial starts with @tailwind base; @tailwind components; @tailwind utilities;. Is that Tailwind v4 syntax? What do you write instead?

Show solution

No, that's v2/v3. In v4 you write one line: @import "tailwindcss"; (Appendix A).

Exercise 5 🟡 medium translate

Rewrite this rule as Tailwind classes on a <div>: display: flex; align-items: center; gap: 1rem; padding: 1rem; background: white; border-radius: 0.5rem;

Show solution

<div class="flex items-center gap-4 p-4 bg-white rounded-lg">. 1 rem is 4 steps of the 0.25 rem spacing unit; rounded-lg is 0.5 rem.

Exercise 6 🟡 medium inline vs utility

Give two things class="..." utilities can do that style="..." cannot, with an example class for each.

Show solution

Any two of: states (hover:bg-sky-600, focus:outline-2), breakpoints (md:flex), dark mode (dark:bg-black), pseudo-elements (before:content-['*']), reusing one CSS rule across the whole page instead of repeating declarations.

Exercise 7 🟡 medium debug

A teammate wrote class="text-blu-600 font-semibold" and the text is not blue. No error appeared anywhere. Why, and how could the mistake have been caught?

Show solution

text-blu-600 is not a Tailwind utility, so Tailwind silently generates nothing for it (the "More examples" typo example shows this). The Tailwind CSS IntelliSense editor extension (Chapter 4) would have shown no colour preview and no completion for it; a linter or checking the computed colour in DevTools also reveals it.

Exercise 8 🟡 medium playground

In the playground (set it up first), open chapters/01/index.html, add the Reading List card from this chapter, and build. Open output.css and find the rule for shadow-lg. Does it point to a theme variable the way text-3xl does? What does it set instead?

Show solution

No. With the default theme, the shadow values are written into the rule: it sets an internal variable --tw-shadow: 0 10px 15px -3px var(--tw-shadow-color, rgb(0 0 0 / 0.1)), …, then box-shadow combines --tw-inset-shadow, the ring variables and --tw-shadow. That composition is what lets shadow-lg work together with ring-2 or shadow-sky-500/50 on the same element.

Exercise 9 🔴 hard explain

Your HTML puts class="underline" on a link, and a stylesheet loaded after Tailwind has a { text-decoration: none; } without a layer. Which one wins, and why? What if the a rule were inside @layer base?

Show solution

The unlayered a rule wins. In the cascade, styles that are not in any layer beat all layered styles, whatever their specificity or order. If you put it in @layer base, the utilities layer is declared later in @layer theme, base, components, utilities;, so underline wins. This is why custom base styles belong in @layer base (Chapter 11).

Exercise 10 🔴 hard judgement

Describe one project where you would choose Tailwind and one where you would choose plain CSS. Give two reasons for each.

Show solution

Tailwind: a product UI built from components (React, Vue, templates) by a team. Reasons: consistent spacing and colours from the theme; no naming or dead CSS; styles live with the component, so changes stay local. Plain CSS: a long-form document or a CMS where authors write content without classes; or a tiny static page with one stylesheet. Reasons: you can't put classes on generated markup; there's no build step to maintain; element selectors express the design more simply. (The Typography plugin in Appendix B covers the "content you can't add classes to" case for Tailwind projects.)
