Chapter 10 · Core Concepts

Reusing Styles

"Won't I repeat the same classes everywhere?" is the first objection everyone has to Tailwind. The docs' answer is a ladder of techniques: leave small repetition alone, use loops, extract components in your template language, and only then write a custom CSS class with @apply. This chapter climbs that ladder, shows exactly how @apply and the components layer behave, and covers @reference for component frameworks with their own <style> blocks.

You will learn

  • The order to reach for reuse techniques, and why components come before @apply.
  • How to write a component class in @layer components with @apply.
  • Why a utility on the element always beats a component class.
  • How to use @apply with variants and in Vue/Svelte/CSS-module style blocks (@reference).
  • What not to abstract.

The ladder

StepTechniqueUse when
1Do nothing; use multi-cursor editingThe repetition is in one file, in a few nearby places
2A loopThe repeated elements come from a list of data
3A component or partial (React, Vue, Svelte, Blade, Jinja, Thymeleaf…)A piece of UI is reused across files
4A custom CSS class (@apply or plain CSS)You can't share markup: Markdown, CMS content, third-party HTML, or very small things like .btn

Steps 2 and 3 keep the markup and its styles together. A component isn't just classes; it's the HTML structure, the accessibility attributes, the icon, the behaviour. A CSS class can only share the styles.

🧠 Analogy: a CSS class is a recipe for the sauce; a component is the whole frozen meal: sauce, pasta, portion size, packaging. If every kitchen needs the whole meal, ship the meal (a component). Ship only the sauce recipe (@apply) when other cooks make their own pasta (content you can't control).

@apply copies the declarations of utilities into your own CSS rule. Put component classes in the components layer, so utilities can still override them:

Button b is red: bg-red-600 is in the utilities layer, which comes after components, so it wins even though .btn-primary appears later in the class attribute and in the file. That's the reason to use @layer components: a component class is a default you can tweak with utilities.

📝 Classes in @layer components are always output, even if unused, and they can't take variants: hover:btn doesn't exist. If you want variants on your own class, define it with @utility instead (Chapter 11).

Using @apply in separate stylesheets: @reference

Vue and Svelte <style> blocks, CSS modules and Astro components are compiled separately from your main CSS file, so they don't know your theme. @apply text-brand there fails with "unknown utility". What not to abstract

  • Don't make a class for every element (.sidebar-header-title). That's regular CSS with extra steps: you're back to naming things and growing a stylesheet.
  • Don't abstract too early. Two similar cards aren't a component yet; wait until the third, when you know what's really shared.
  • Don't @apply everything to "clean up the HTML". Short-term tidier, long-term you lose the "change one element without breaking others" benefit.

⚠️ Tailwind's creator has said he'd remove @apply if he could, because people overuse it. Treat it as a tool for the few cases where markup can't be shared.

Recap

  • Reuse ladder: leave it → loop → component/partial → custom class.
  • Components share markup and styles; prefer them over CSS classes.
  • List complete class names in components (a lookup object), never build them from pieces.
  • @apply copies utilities into a rule; put shared classes in @layer components so utilities can override them.
  • @reference "./main.css"; lets separately compiled style blocks use your theme with @apply, without duplicating CSS.
  • Don't name every element or @apply everything; abstract on the third repetition.

Exercises

Exercise 1 🟢 easy ladder

Which technique fits best: (a) a navigation bar used on every page of a Django site, (b) twenty rows of a product table, (c) blog posts written in Markdown?

Show solution

(a) a template partial ({% include "nav.html" %}); (b) a loop; (c) component classes or the Typography plugin, since you can't add classes to Markdown output.

Exercise 2 🟢 easy write

Write a .badge class with @apply: small rounded pill, light green background, dark green text, small font.

Show solution

@layer components { .badge { @apply inline-flex rounded-full bg-green-100 px-2 py-0.5 text-xs font-medium text-green-800; } }

Exercise 3 🟢 easy override

With .badge in @layer components, what colour is <span class="badge bg-red-100">? Why?

Show solution

Red-100. bg-red-100 is in the utilities layer, which comes after components, so it wins.

Exercise 4 🟢 easy error

In a Svelte component's <style> block, @apply bg-brand fails with "Cannot apply unknown utility class". Your main CSS defines --color-brand. What do you add?

Show solution

@reference "../app.css"; (the path to the main stylesheet) at the top of the style block.

Exercise 5 🟡 medium component

Extend the button() function with a size argument (sm, md, lg) without building class names from pieces.

Show solution

const SIZES = { sm: "px-2.5 py-1.5 text-xs", md: "px-3.5 py-2 text-sm", lg: "px-5 py-3 text-base" }; and use ${SIZES[size]} instead of the fixed padding and font size.

Exercise 6 🟡 medium layers

You define .card { @apply p-6; } outside any layer, then write <div class="card p-2">. What padding does it get, and how do you fix it?

Show solution

24 px (p-6): unlayered styles beat all layered ones, including utilities. Wrap the rule in @layer components { … } and p-2 wins.

Exercise 7 🟡 medium playground

In chapters/10/, the page has six buttons with copy-pasted classes. Refactor it twice: once with the button() function, once with .btn classes. Which version is easier to give an icon to every button?

Show solution

The function: you add the icon markup in one place and every button gets it. With .btn you'd still edit six places in the HTML, because CSS classes can't add markup.

Exercise 8 🟡 medium reference

Why does @reference exist instead of just writing @import "../main.css" in every component's style block?

Show solution

@import would output all of the main CSS (Preflight, theme, utilities) again in every component's styles, duplicating it many times. @reference only makes the theme and utilities known for @apply and theme functions; nothing is output.

Exercise 9 🔴 hard review

A teammate converted every element of a page to semantic classes with @apply (.hero-title, .hero-subtitle, .hero-cta…), 40 classes in total, "to keep the HTML clean". Give three concrete downsides.

Show solution

(1) Naming and finding things again: every change means jumping between files. (2) The CSS grows with every new class and dead classes are hard to spot, as with regular CSS. (3) Classes get reused in places they weren't meant for, so changing .hero-title can break another page. Also: @layer components classes can't take variants, and you lose co-location.

Exercise 10 🔴 hard read the CSS

Compare the generated CSS for .btn-primary (with hover:bg-sky-700 inside @apply) with the utility hover:bg-sky-700 from Chapter 5. What's the same, what's different?

Show solution

Same: the declaration background-color: var(--color-sky-700), the :hover condition and the @media (hover: hover) guard. Different: in @apply it's nested inside .btn-primary (&:hover { @media (hover: hover) { … } }) in the components layer; the utility has its own selector .hover\:bg-sky-700:hover in the utilities layer.
