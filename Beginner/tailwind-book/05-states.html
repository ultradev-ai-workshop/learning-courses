Chapter 5 · Core Concepts

Hover, Focus & Other States

In CSS you style states with pseudo-classes like :hover and :focus. In Tailwind you add a variant in front of a utility: hover:bg-sky-700 means "bg-sky-700, but only on hover". This chapter covers the variants you'll use every day: interaction states, structural ones like first: and odd:, styling based on a parent (group) or a sibling (peer), has-, pseudo-elements, form states, ARIA and data attributes. The screenshots were taken with the mouse really over the element or the field really focused.

You will learn

  • How a variant turns into CSS, and how to stack variants.
  • Interaction states: hover, focus, focus-visible, active, disabled.
  • Structural variants: first, last, odd, even, *.
  • Styling from a parent with group, from a sibling with peer, and from children with has-.
  • Pseudo-elements: before, after, placeholder, file, marker, selection.
  • Form, ARIA, data-attribute and media variants.

💡 Accessibility: for buttons and links, prefer focus-visible: for the focus ring. Keyboard users get a clear outline; mouse users don't see a ring every time they click. Never remove the outline without replacing it.

Stacking variants

Variants combine: md:hover:bg-sky-700 means "on medium screens and up, on hover". In v4, stacked variants apply left to right, like nested CSS:

For most variants the order doesn't change the result. It matters for variants that select other elements, like *: or group-, which you'll meet below.

🧠 Analogy: a variant is an "only if" sticker on a utility. bg-sky-700 is a can of paint; hover:bg-sky-700 is the same can with a sticker "only while someone points at it". Stack stickers and every condition must be true: "only in dark mode, only on wide screens, only while pointed at".

First, last, odd, even

Structural variants style an element based on its position among its siblings. They save you from adding special classes in a loop:

Every <li> has the same classes (as it would in a loop); CSS decides which ones apply. Also available: only:, first-of-type:, last-of-type:, empty:, and nth-3: or nth-[3n+1]: for any :nth-child() formula.

Styling based on a parent: group

To change a child when the parent is hovered, mark the parent with the class group and use group-hover: on the child:

Read the selector as "an element with this class that is inside a hovered .group". The :where() around .group adds no specificity, so the rule is exactly as strong as a plain hover: utility. Every state works: group-focus:, group-active:, group-odd:, group-has-[…]:… When groups are nested, name them with group/name and group-hover/name:, so a child reacts to the right ancestor:

Styling based on a sibling: peer

To style an element based on a previous sibling, mark the sibling with peer and use peer-*:. The classic use is showing an error message for an invalid field. Here we type an invalid email:

user-invalid: (the CSS :user-invalid pseudo-class, added in v4.1) only matches after the user has interacted with the field, so the form doesn't start covered in errors the way plain invalid: would. peer works with the CSS sibling combinator ~, so it only affects siblings after the peer; that's a CSS limit, not a Tailwind one. Peers can be named too: peer/email and peer-checked/email:.

Styling based on children: has-

The CSS :has() pseudo-class styles an element based on what it contains. Tailwind writes it as has-[selector]: or with a built-in state, such as has-checked::

Before :has(), this needed JavaScript. group-has-* and peer-has-* also exist, and not-* negates any variant: not-first:border-t, not-has-checked:opacity-60.

ARIA and data attributes

Components often expose their state as attributes: aria-expanded="true", aria-selected, data-state="open". Style them directly:

Boolean ARIA attributes (aria-checked, aria-disabled, aria-expanded, aria-hidden, aria-pressed, aria-readonly, aria-required, aria-selected) have built-in variants that match ="true". For others use brackets: aria-[sort=ascending]:. data-active: matches the attribute being present.

Recap

  • A variant (hover:, focus:…) applies a utility only in a state; it compiles to a pseudo-class, attribute selector or media query.
  • Variants stack and apply left to right: md:hover:bg-sky-700.
  • hover: only applies on devices that can hover; use focus-visible: for keyboard focus rings.
  • first:, last:, odd:, even:, nth-*: style by position.
  • group + group-hover: styles children from a parent; peer + peer-*: styles later siblings; has-*: styles a parent from its children. Name them with /name.
  • before:, after:, placeholder:, marker:, selection:, file: style pseudo-elements.
  • Form (user-invalid:, disabled:), ARIA (aria-pressed:), data (data-[state=open]:) and media variants cover the rest.

Exercises

Exercise 1 🟢 easy write

A link should be grey, turn black on hover, and show an underline when focused with the keyboard. Write its classes.

Show solution

text-slate-500 hover:text-black focus-visible:underline

Exercise 2 🟢 easy zebra

Give every even row of a table a light grey background without adding classes to specific rows.

Show solution

Put even:bg-slate-50 on every <tr> (the same class on all rows, as a loop would), or once on the table body with *:even:bg-slate-50.

Exercise 3 🟢 easy read

What does md:disabled:opacity-50 do?

Show solution

On screens 48 rem (768 px) and wider, a disabled element gets 50% opacity.

Exercise 4 🟢 easy pseudo-element

Add a red asterisk after a label's text using only classes.

Show solution

<span class="after:ml-0.5 after:text-red-500 after:content-['*']">Email</span>

Exercise 5 🟡 medium group

A product card contains an image and a title. On card hover, the image should get slightly smaller opacity and the title should turn sky-blue. Write the markup.

Show solution

<a class="group block"><img class="group-hover:opacity-75" …><h3 class="group-hover:text-sky-600">…</h3></a>

Exercise 6 🟡 medium peer

Why does this not work, and how do you fix it? <p class="peer-invalid:visible invisible">Error</p><input class="peer" required>

Show solution

peer-* compiles to .peer:invalid ~ p, and the CSS ~ combinator only selects siblings that come after the peer. Move the <p> after the <input>. Use peer-user-invalid: so it doesn't show before the user types.

Exercise 7 🟡 medium has

A form row should get a red left border when the input inside it is invalid after the user has typed. Use has-.

Show solution

<div class="border-l-4 border-transparent has-user-invalid:border-red-500"><input type="email"></div>

Exercise 8 🟡 medium playground

In chapters/05/index.html build the toggle switch from "More examples", then change it to use sky instead of emerald and add motion-reduce:transition-none to both transitions. Why add the last part?

Show solution

Replace the three emerald-500 classes. motion-reduce:transition-none turns the animation off for users who set "reduce motion" in their system settings (some people get dizzy from movement).

Exercise 9 🔴 hard named groups

A sidebar menu item (a group) contains a "more" button (also a group) with an icon. The icon should appear when the item is hovered, and turn blue when the button is hovered. Write the classes.

Show solution

Item: group/item. Button: group/more invisible group-hover/item:visible. Icon: text-slate-400 group-hover/more:text-sky-600. Without names, group-hover: reacts to any .group ancestor being hovered, so hovering the item would also turn the icon blue.

Exercise 10 🔴 hard read the CSS

Predict the selector Tailwind generates for group-hover:underline and for peer-checked:bg-sky-500, then check with the CLI.

Show solution

:is(:where(.group):hover .group-hover\:underline) inside @media (hover: hover), and :is(:where(.peer):checked ~ .peer-checked\:bg-sky-500). :where() adds zero specificity, so each has the specificity of one class plus one pseudo-class, the same as .hover\:bg-sky-700:hover. (Print them with npx @tailwindcss/cli -i input.css; older 4.x versions wrote them in a different but equivalent form.)
