Editor Setup & Class Order

You'll type thousands of class names, so a good editor setup pays off on day one. This chapter follows the docs' Editor setup page: the official IntelliSense extension that completes, previews and checks classes; the Prettier plugin that sorts them into a standard order; and the CLI's canonicalize command that rewrites classes into their simplest form. It ends with habits that keep long class lists readable.

You will learn

  • What the Tailwind CSS IntelliSense extension does and how to configure it.
  • How to make your editor understand Tailwind's CSS directives.
  • How prettier-plugin-tailwindcss sorts classes, and the order it uses.
  • How tailwindcss canonicalize simplifies class names.
  • Habits for long class lists.

Tailwind CSS IntelliSense

The official Tailwind CSS IntelliSense extension for VS Code (and editors that use the same extension format, such as Cursor and VSCodium) gives you:

  • Autocomplete: suggestions for every utility, including your own theme colours and custom utilities, as you type in a class attribute.
  • Hover previews: hover a class to see the CSS it generates, such as .p-4 { padding: calc(var(--spacing) * 4); /* 1rem = 16px */ }.
  • Colour swatches next to colour classes.
  • Linting: warnings for conflicting classes (flex grid) and mistakes in your CSS file.
  • Suggestions to simplify: for example it offers to replace w-12 h-12 with size-12.

Install it from the Extensions view (search "Tailwind CSS IntelliSense", publisher Tailwind Labs). It finds your CSS file with @import "tailwindcss" automatically. JetBrains IDEs (WebStorm, IntelliJ), Zed and Neovim (through the Tailwind language server) have the same features built in or as plugins.

Two settings worth adding

Without the first setting, the built-in CSS checker doesn't know Tailwind's at-rules and underlines @theme and @utility as unknown. The extension provides a "Tailwind CSS" language mode for CSS files that understands them.

🧠 Analogy: IntelliSense is a spell-checker with a dictionary of every utility. Without it, a typo like txt-red-500 silently does nothing, like a misspelled word in a letter nobody proofreads. With it, you see suggestions as you type and a red squiggle when something is off.

Sorting classes with Prettier

Prettier is a code formatter. The official plugin prettier-plugin-tailwindcss adds one thing: it sorts the classes in every class and className attribute into a standard order. Everyone on a team then writes the same element the same way, and diffs stay small.

tailwindStylesheet points to your main CSS file, so the plugin knows your theme and custom utilities. Here is a button with its classes in random order:

The order follows the generated CSS:

  1. Classes Tailwind doesn't know (your own, like my-btn, or other libraries') go first, so they stand out.
  2. Then utilities in the order they appear in the stylesheet: layout and box model (rounded-lg, bg-, px-, py-) before typography and colour (text-white).
  3. Classes with variants go last, after the plain ones: hover: before responsive ones like sm:, which are ordered from the smallest breakpoint up.

Because the order matches the CSS, a sorted list also tells you which class "wins" when two conflict: the later one. Run npx prettier --write . to sort a whole project, or enable "format on save" in your editor.

💡 Sorting also works inside JavaScript strings passed to functions such as clsx or cn when you list them in the plugin's tailwindFunctions option: "tailwindFunctions": ["clsx", "cn"].

Simplifying classes: tailwindcss canonicalize

The CLI can rewrite classes into their canonical (simplest standard) form. It's useful after an upgrade, when cleaning up code written by many people, or to check what the "official" spelling of something is:

  • w-12 h-12 becomes the shorthand size-12 (width and height together).
  • Arbitrary values that equal a theme value become the theme utility: p-[1rem] is p-4; bg-[#fff] is bg-white.
  • [var(--brand)] becomes the v4 shorthand (--brand), and the v3-style leading ! moves to the end.

Habits for long class lists

  • Let the formatter wrap lines. Prettier breaks long attributes for you; don't fight it.
  • Read in the sorted order: layout → box → typography → colour → states → breakpoints. After a week it becomes automatic.
  • Extract when it hurts, not before. If you copy the same 15 classes a third time, make a component (Chapter 10).
  • Use DevTools. In the browser's Elements panel, the "Computed" tab shows the final value of every property and which rule set it.

Recap

  • Install Tailwind CSS IntelliSense: completion, hover CSS previews, colour swatches, linting.
  • Associate *.css with the "tailwindcss" language so @theme and friends aren't flagged.
  • prettier-plugin-tailwindcss sorts classes in the order of the generated CSS: unknown classes first, variants last.
  • tailwindcss canonicalize rewrites classes into their simplest form (w-12 h-12 → size-12).
  • Let the formatter wrap long lists; extract components when repetition really hurts.

Exercises

Exercise 1 🟢 easy setup

Install Tailwind CSS IntelliSense in your editor and open the playground. Hover rounded-lg in any file. What does the tooltip show?

Show solution

The generated CSS: .rounded-lg { border-radius: var(--radius-lg); /* 0.5rem (8px) */ }, the value of the theme variable in a comment.

Exercise 2 🟢 easy settings

VS Code underlines @theme in your CSS with "Unknown at rule". Which setting fixes it?

Show solution

"files.associations": { "*.css": "tailwindcss" }, which uses the extension's Tailwind CSS language mode for CSS files.

Exercise 3 🟢 easy sort by hand

Without running Prettier, put these in the plugin's order: hover:bg-sky-600 p-4 my-card bg-sky-500 md:p-6.

Show solution

my-card bg-sky-500 p-4 hover:bg-sky-600 md:p-6: unknown class first, then plain utilities, then hover:, then breakpoints.

Exercise 4 🟢 easy canonical

What is the canonical form of h-8 w-8, p-[0.5rem] and text-[#000]?

Show solution

size-8, p-2 (0.5 rem = 2 × 0.25 rem) and text-black. Check with npx tailwindcss canonicalize "h-8 w-8" "p-[0.5rem]" "text-[#000]".

Exercise 5 🟡 medium playground

The playground already has Prettier and the plugin. Scramble the classes of three elements in chapters/04/index.html, run npm run format, and compare with what you expected.

Show solution

The plugin restores the same order every time, whatever the starting order. If your guess differed, look at where each utility appears in the generated CSS; that is the order.

Exercise 6 🟡 medium why

Why does the plugin put classes it doesn't recognise first rather than last?

Show solution

They usually carry meaning (a component class like card, a JavaScript hook, another library's class) and would get lost at the end of a long list. At the front you see them at a glance.

Exercise 7 🟡 medium canonical px

Why does canonicalize turn p-[1rem] into p-4 but leave mt-[16px] alone?

Show solution

p-4 is calc(var(--spacing) * 4) = 1 rem exactly, so the two are always equal. 16 px equals 1 rem only if the root font size is 16 px, which the user or the page can change; the tool doesn't assume it.

Exercise 8 🟡 medium functions

Your React code uses a helper cn("px-4", isActive && "bg-sky-600"). Which two settings make autocomplete and sorting work inside cn(...)?

Show solution

IntelliSense: "tailwindCSS.classFunctions": ["cn"] in VS Code settings. Prettier: "tailwindFunctions": ["cn"] in .prettierrc.

Exercise 9 🔴 hard conflicts

After sorting, an element reads class="flex … grid" with grid later. What does this tell you about which display value applies, and what should you do?

Show solution

The sorted order follows the CSS, so the later class (grid) wins. Two classes for the same property is almost always a mistake: remove one, or make one conditional (flex md:grid). IntelliSense also flags it as a conflict.

Exercise 10 🔴 hard team setup

Write the files a team should commit so every developer gets the same Tailwind editing experience, and the CI fails when classes aren't sorted.

Show solution

.vscode/extensions.json recommending bradlc.vscode-tailwindcss and esbenp.prettier-vscode; .vscode/settings.json with the file association and "editor.formatOnSave": true; .prettierrc with the plugin and tailwindStylesheet; a package.json script "format:check": "prettier --check ." that CI runs. prettier --check exits with an error when any file would change.
