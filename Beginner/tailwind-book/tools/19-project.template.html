Capstone: Tailwind in Next.js

Time to put everything together. You'll install Tailwind CSS in a Next.js app the official way, following the Tailwind docs' Next.js guide, and build Orbit: a landing page and a dashboard for a fictional habit tracker. It uses a custom theme, semantic colours with a dark-mode toggle that never flashes, reusable components, responsive and container-query layouts, subgrid, gradients and Prettier class sorting. Every file below is the real code from playground/reference/, and every screenshot was taken from a production build of it.

You will learn

  • How to add Tailwind to a Next.js app with @tailwindcss/postcss, step by step.
  • How to organise a real theme: brand tokens, semantic colours, a custom utility.
  • How to build typed React components with variant lookups and a cn() helper.
  • How to combine the techniques from every chapter in one app, and check the result.

Step 2: the theme

All design decisions live in one CSS file. Read it top to bottom; each block uses a chapter's technique:

  • @custom-variant dark switches dark: to a class on <html> (Chapter 7).
  • @theme adds a brand palette, a display font and a fade-up animation with its keyframes (Chapter 8). Each creates utilities: bg-brand-600, font-display, animate-fade-up.
  • Semantic colours: --surface, --ink, --muted, --line change value under .dark, and @theme inline turns them into bg-surface, text-ink, border-line… The components never need dark: for their basic colours.
  • @layer base sets the page colours and native control scheme (Chapter 11).
  • @utility container-page is the page container, with responsive padding written with @variant (Chapter 11). Because it's a utility, it would also work with variants.

Step 3: the root layout and dark mode

The inline script runs in <head> before the page is painted, so dark-mode users never see a white flash (Chapter 7). suppressHydrationWarning tells React that the class on <html> may differ from the server HTML, which is expected here. The toggle is a small Client Component:

Its icon switches with dark:hidden and hidden dark:inline, and the button has an sr-only label (Chapter 12).

Step 4: components

A tiny helper joins class names and skips false values, so conditions read naturally:

The button keeps complete class names in lookup objects, so Tailwind finds every one of them when it scans the file (Chapters 3 and 10). Variants and sizes are typed: variant="tertiary" is a TypeScript error.

The header is sticky with a translucent bg-surface/80 and backdrop-blur-md: content blurs as it scrolls underneath (Chapters 12 and 16). The navigation links are hidden md:flex.

Step 5: the landing page

Things to notice: gradient text with bg-clip-text, text-balance and text-pretty; an entry animation only for motion-safe users; buttons that stack on phones and sit side by side from sm; a feature grid that becomes three columns at md; pricing cards on a subgrid so prices line up even though the blurbs have different lengths; the featured card made taller with negative margins; and an FAQ built from <details> with a group-open:rotate-45 icon.

Step 6: dark mode in action

Clicking the moon button adds dark to <html>. Every semantic colour switches at once:

The choice survives a reload, and the class is already there when the page first paints. (The colour is slate-950. It's reported in lab() because Next.js runs its CSS through an optimiser that rewrites oklch() colours, with the same result on screen.)

Step 7: the dashboard

  • The sidebar is hidden md:flex; the current link is styled with aria-[current=page]: variants, so the markup and the accessibility attribute can't drift apart (Chapter 5).
  • The stat cards use a container query (@container + @lg:grid-cols-3): they follow the width of the main column, which is narrower when the sidebar is shown (Chapter 18).
  • The table scrolls sideways on small screens (overflow-x-auto + min-w-xl), has divide-y rows and a hover colour.
  • Progress bars get their width from data through a CSS variable: w-(--done) with style={{ "--done": "86%" }} (Chapter 3).

At 780 px the screen is wider than md, but after the 224 px sidebar and 64 px of padding the stats container is only 492 px wide, below the @lg container size (32 rem = 512 px). A viewport breakpoint would have squeezed three cards into it.

Make it yours

Ideas for extending Orbit, each practising a chapter:

  • A three-way theme switch (light, dark, system) instead of a toggle (Chapter 7).
  • A Card component with padding and tone variants, used by the features and stats (Chapter 10).
  • A mobile menu in the header with <details> or a popover and starting: animation (Chapters 5 and 17).
  • An "Insights" page with a bento grid (Chapter 13) and animate-pulse skeletons while data loads (Chapter 17).

Recap

  • Official Next.js setup: npm install tailwindcss @tailwindcss/postcss postcss, a postcss.config.mjs, and @import "tailwindcss"; in app/globals.css.
  • Keep the design system in CSS: @theme tokens, semantic variables with @theme inline, @layer base, @utility.
  • Class-based dark mode with an inline head script avoids flashes; semantic colours avoid dark: everywhere.
  • Components hold complete class names in lookups; cn() joins conditional classes.
  • Container queries, subgrid, CSS-variable widths and ARIA variants solve real layout problems with no extra JavaScript.

Exercises

Exercise 1 🟢 easy setup

List the three things you add to a fresh Next.js app to install Tailwind with PostCSS.

Show solution

The packages (tailwindcss @tailwindcss/postcss postcss), a postcss.config.mjs with the plugin, and @import "tailwindcss"; in the global CSS file imported by the root layout.

Exercise 2 🟢 easy brand

Change Orbit's brand colour from violet to teal by editing only globals.css.

Show solution

Change the hue of the --color-brand-* values (285 → about 185), e.g. --color-brand-600: oklch(0.52 0.1 185), or point them at the palette: --color-brand-600: var(--color-teal-600). No component changes, because they all use brand-*.

Exercise 3 🟢 easy button

Add a danger variant to ButtonLink.

Show solution

Add danger: "bg-red-600 text-white shadow-sm hover:bg-red-700" to the variants object. The type keyof typeof variants picks it up automatically.

Exercise 4 🟢 easy semantic

Add a semantic colour accent-soft (brand-50 in light mode, brand-700 at 30% in dark mode) and use it for the feature icons instead of bg-brand-50 dark:bg-brand-700/30.

Show solution

:root { --accent-soft: var(--color-brand-50); }, .dark { --accent-soft: --alpha(var(--color-brand-700) / 30%); }, @theme inline { --color-accent-soft: var(--accent-soft); }, then bg-accent-soft.

Exercise 5 🟡 medium mobile menu

The header hides the navigation below md. Add a mobile menu with <details> that shows the links in a dropdown panel.

Show solution

<details className="relative md:hidden"><summary className="list-none rounded-lg p-2 ring-1 ring-line">☰</summary><nav className="absolute right-0 mt-2 flex w-48 flex-col rounded-lg bg-surface p-2 shadow-lg ring-1 ring-line">…links…</nav></details>

Exercise 6 🟡 medium three-way

Replace ThemeToggle with a three-way switch (light, dark, system) using the logic from Chapter 7.

Show solution

Three buttons in a role="group"; light and dark set localStorage.theme, system calls localStorage.removeItem("theme"); each then runs the same expression as the layout's themeScript to set the class. Highlight the active one with aria-pressed and aria-pressed:bg-surface-muted.

Exercise 7 🟡 medium container

Make each stat card itself a container and show a small trend line ("+4%") next to the value only when the card is at least 16 rem wide.

Show solution

Card: add @container. Trend: <span className="hidden text-sm text-emerald-600 @3xs:inline">+4%</span> (@3xs = 16 rem).

Exercise 8 🟡 medium loading

Add a app/dashboard/loading.tsx that shows a skeleton of the stat cards while the page loads.

Show solution

Return three <div className="h-24 animate-pulse rounded-xl bg-surface-muted ring-1 ring-line" /> in the same grid gap-4 @lg:grid-cols-3 inside an @container.

Exercise 9 🔴 hard tw-merge

<ButtonLink className="px-8"> ends up with both px-4 and px-8. Which wins, and why is that fragile? How would you make className reliably override the defaults?

Show solution

The one generated later in the CSS, which here happens to be px-8, but that depends on Tailwind's internal order, not on the order in the attribute (Chapter 3). Use a merge helper such as the tailwind-merge package inside cn(): it removes conflicting earlier classes, so cn("px-4", "px-8") returns "px-8" (Appendix C).

Exercise 10 🔴 hard your own

Design and build an "Insights" page: a bento grid of four tiles (a big chart tile, three small stat tiles), each adapting with container queries, in both themes.

Show solution

One approach: grid gap-4 md:grid-cols-4 md:grid-rows-2; chart tile md:col-span-2 md:row-span-2 @container; small tiles @container with @xs:flex-row layouts; all with bg-surface ring-1 ring-line so dark mode works without extra classes. Check it at 390, 800 and 1100 px.
