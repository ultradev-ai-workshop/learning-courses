Appendix C

Tailwind with React Components

Tailwind and component frameworks fit together naturally: the component holds the markup and the classes in one place, so reuse is solved by the framework, not by CSS. This appendix shows the patterns React developers use every day: a Vite + React setup, conditional classes with clsx, variant lookups, letting callers override classes safely with tailwind-merge, and styling state through data-* and aria-* attributes. The same ideas apply to Vue, Svelte and others.

You will learn

  • How to set up Tailwind in a Vite + React project.
  • className, conditional classes, and the clsx helper.
  • Variant lookups for component props, and why they beat string building.
  • How tailwind-merge resolves conflicts when a caller passes className.
  • Styling component state with data-* and aria-* variants.

Setup: Vite + React

In JSX, the attribute is className; everything else is the same as in HTML. Now the component.

A component with variants

Look at the Delete button: the caller passed className="px-6", and twMerge removed the conflicting px-2.5 from the size. Without it, both px-2.5 and px-6 would be on the element, and the winner would depend on Tailwind's CSS order, not on your intent (Chapter 3).

🧠 Analogy: clsx is a packing list: write down everything, cross out what doesn't apply (isActive && "…"). tailwind-merge is the person checking the suitcase: if you packed two jackets for the same weather (px-2.5 and px-6), it takes out the first one.

More tips

  • Never build class names from props: `bg-${color}-500` isn't detected (Chapter 11). Use lookup objects as above.
  • Runtime values go through CSS variables: style={{ "--progress": `${p}%` }} with w-(--progress).
  • Editor support: add "tailwindCSS.classFunctions": ["cn", "clsx"] and Prettier's "tailwindFunctions": ["cn"] (Chapter 4).
  • Many variants? Libraries such as class-variance-authority (cva) or tailwind-variants formalise the lookup pattern with typed variants, compound variants and defaults.
  • Vue and Svelte work the same: :class bindings or class:active={…}; style blocks that use @apply need @reference (Chapter 10).

Recap

  • Vite + React: @tailwindcss/vite next to @vitejs/plugin-react; @import "tailwindcss" in the entry CSS.
  • Components hold markup and classes together; variants live in lookup objects with complete class names.
  • clsx joins conditional classes; tailwind-merge drops earlier conflicting ones, so className overrides work.
  • Prefer aria-*/data-* attributes + variants over computing classes from state.
  • Runtime values via CSS variables; tell your editor and Prettier about cn.

Exercises

Exercise 1 🟢 easy JSX

Convert to JSX: <label for="email" class="text-sm font-medium">Email</label>

Show solution

<label htmlFor="email" className="text-sm font-medium">Email</label>

Exercise 2 🟢 easy clsx

Add opacity-50 cursor-not-allowed only when a disabled prop is true, with clsx.

Show solution

clsx("rounded-md px-3 py-2", disabled && "cursor-not-allowed opacity-50") (or use the disabled: variant on a real <button disabled>).

Exercise 3 🟢 easy merge

What does twMerge("p-4 rounded-lg", "rounded-none") return?

Show solution

"p-4 rounded-none"

Exercise 4 🟢 easy bug

Why doesn't <div className={`text-${size}`}> work, and how do you fix it?

Show solution

Tailwind never sees the full class names in the source. Use a lookup: { sm: "text-sm", lg: "text-lg" }[size].

Exercise 5 🟡 medium component

Write a Card component with a padding prop ("sm" | "lg") that accepts a className to override anything.

Show solution

const pads = { sm: "p-4", lg: "p-8" }; and <div className={cn("rounded-xl bg-white shadow-sm ring-1 ring-slate-900/5", pads[padding], className)} {...props} />

Exercise 6 🟡 medium state

An accordion item has open state. Style its chevron to rotate when open using a data-state attribute.

Show solution

<div data-state={open ? "open" : "closed"} className="group"> and on the icon transition-transform group-data-[state=open]:rotate-180.

Exercise 7 🟡 medium playground

Create a React version of the playground in chapters/appendix-c/ with npm create vite, and port the Button from this appendix. Add a loading prop that shows a spinner.

Show solution

Add loading?: boolean to the props; render {loading && <svg className="size-4 animate-spin" …/>} before children, set disabled={loading || props.disabled}, and add inline-flex items-center gap-2 to the base classes.

Exercise 8 🟡 medium why

When does a component not need tailwind-merge?

Show solution

When it doesn't accept className (or other class props) from callers, or when its own variant classes never conflict. Plain clsx is enough then.

Exercise 9 🔴 hard compound

The Button should have a special style when variant="secondary" and size="sm": no shadow. Implement it without a third lookup table for every combination.

Show solution

Add a list of compound rules: const compound = [{ variant: "secondary", size: "sm", className: "shadow-none" }]; and append the matching ones: compound.filter((c) => c.variant === variant && c.size === size).map((c) => c.className). twMerge then removes the base shadow-xs. (This is what cva's compoundVariants does.)

Exercise 10 🔴 hard custom theme

Your theme adds --text-display (a font size) and --color-brand. twMerge("text-brand", "text-display") drops text-brand. Why, and how do you fix it?

Show solution

tailwind-merge doesn't read your CSS theme, so it doesn't know whether text-brand and text-display are sizes or colours, and treats both as the same group. Configure it with extendTailwindMerge({ extend: { theme: { text: ["display"], color: ["brand"] } } }) so it knows display is a font size and brand a colour.
