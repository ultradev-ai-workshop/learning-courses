Responsive Design

A responsive page adapts its layout to the screen it's on. In Tailwind, every utility can take a breakpoint variant: md:flex means "flex from medium screens up". This chapter explains the mobile-first approach, the five default breakpoints, how to target a range, how to add your own breakpoints, and the difference between viewport and container breakpoints. The same page is shown at different widths, rendered by Chrome at that width.

You will learn

  • The viewport meta tag and why responsive design needs it.
  • The default breakpoints and what md: compiles to.
  • Mobile-first thinking: unprefixed classes are for every size.
  • How to target one range with md:max-lg:, and use max-* variants.
  • How to add, change and remove breakpoints, and use one-off values like min-[900px]:.
  • The container class and a first look at container queries.

Breakpoints

There are five default breakpoints, inspired by common device widths. Each is a theme variable:

PrefixMinimum widthCSS
sm:40rem (640 px)@media (width >= 40rem) { … }
md:48rem (768 px)@media (width >= 48rem) { … }
lg:64rem (1024 px)@media (width >= 64rem) { … }
xl:80rem (1280 px)@media (width >= 80rem) { … }
2xl:96rem (1536 px)@media (width >= 96rem) { … }

Every md: class lives inside @media (width >= 48rem), and Tailwind groups them into one block. That's all a breakpoint is.

Mobile first

Tailwind is mobile-first: a class without a prefix applies at every width, and a prefixed class applies at that width and wider. So you style for small screens first, then add overrides for bigger ones.

At 390 px (a phone), sm:text-center does nothing. This is the most common beginner mistake with breakpoints.

🧠 Analogy: breakpoints are height marks at an amusement park: "you must be at least this tall to ride". md:flex is a ride for everyone 768 px and taller. Unprefixed classes are rides with no height limit. There's no "maximum height" sign unless you add one with max-*.

Targeting a range

Each breakpoint also has a max-* variant that applies below it. Combine them to target a range:

Sky below 640 px, amber between 768 and 1023 px, nothing elsewhere. To target exactly one breakpoint's range, stack it with the next one's max-: md:max-lg: is "md only".

Custom breakpoints

Breakpoints are theme variables named --breakpoint-*, so you change them in CSS with @theme (Chapter 8):

Tailwind sorts breakpoints by size, so xs (new, 30 rem) comes first and 3xl last. To remove a default, set it to initial: --breakpoint-2xl: initial;. To start from nothing, --breakpoint-*: initial; removes them all, then define your own.

⚠️ Use rem for all breakpoints, as the defaults do. Tailwind can only sort breakpoints that use the same unit; mixing px and rem gives an unpredictable order.

Responsive typography

Recap

  • Add <meta name="viewport" content="width=device-width, initial-scale=1.0"> to every page.
  • Breakpoints: sm 40rem, md 48rem, lg 64rem, xl 80rem, 2xl 96rem; each compiles to @media (width >= …).
  • Mobile first: unprefixed = all sizes; md: = md and up. Don't use sm: to mean "phones".
  • max-md: applies below md; md:max-lg: targets one range.
  • Change breakpoints with --breakpoint-* in @theme (rem only); one-offs with min-[900px]:.
  • container snaps to breakpoint widths; container queries (@container, @md:) respond to a parent's width.

Exercises

Exercise 1 🟢 easy read

Describe what class="w-full md:w-1/2 xl:w-1/3" does at 500 px, 900 px and 1400 px.

Show solution

500 px: full width. 900 px (≥ md): half width. 1400 px (≥ xl): one third.

Exercise 2 🟢 easy fix

Someone wants a button full-width on phones and auto width from 640 px. They wrote sm:w-full w-auto. Fix it.

Show solution

w-full sm:w-auto. Unprefixed is the phone style; sm: overrides from 640 px up.

Exercise 3 🟢 easy values

Which media query does lg: compile to, and how many pixels is that?

Show solution

@media (width >= 64rem), 1024 px with the default 16 px root font size.

Exercise 4 🟢 easy show/hide

Show a "Download the app" banner only on screens narrower than 768 px.

Show solution

<div class="md:hidden"> (visible by default, hidden from md up), or equivalently class="hidden max-md:block".

Exercise 5 🟡 medium range

Make a sidebar 16 rem wide only between md and xl, full width below md, and 20 rem from xl.

Show solution

w-full md:w-64 xl:w-80. Mobile first means you don't need max-xl: here: xl:w-80 overrides md:w-64 from xl up.

Exercise 6 🟡 medium theme

Your designer's breakpoints are 360, 768 and 1200 pixels, named phone, tablet, desktop, and no others. Write the @theme block.

Show solution

@theme { --breakpoint-*: initial; --breakpoint-phone: 22.5rem; --breakpoint-tablet: 48rem; --breakpoint-desktop: 75rem; }. Convert to rem (÷16) so they sort correctly. Use them as tablet:flex.

Exercise 7 🟡 medium playground

In chapters/06/index.html, build the "Show and hide" header, then add a third layout: from lg up, add a "Sign in" button on the right. Check it with the browser's device toolbar at 380, 800 and 1100 px.

Show solution

Add <a class="hidden rounded-md bg-white px-3 py-1 text-slate-900 lg:block">Sign in</a> after the nav. In Chrome open DevTools and press Ctrl/Cmd+Shift+M to resize the viewport.

Exercise 8 🟡 medium explain

Why does md:max-lg:flex generate two nested media queries instead of one combined query?

Show solution

Each variant wraps the rule in its own condition, left to right: md: adds @media (width >= 48rem), then max-lg: adds @media (width < 64rem) inside it. Nested media queries combine like "and", so the result is the same as one query with both conditions.

Exercise 9 🔴 hard layout

Build a pricing section: three cards stacked on phones, a row of three from lg, and between sm and lg two per row with the third card spanning both columns.

Show solution

Container: grid grid-cols-1 gap-6 sm:grid-cols-2 lg:grid-cols-3. Third card: sm:max-lg:col-span-2 (or sm:col-span-2 lg:col-span-1).

Exercise 10 🔴 hard viewport vs container

The same "user card" appears in a 300 px sidebar and in a 900 px main column on a 1440 px screen. Why can't md:flex-row lay it out correctly in both places, and what do you use instead?

Show solution

md: looks at the viewport, which is 1440 px in both places, so both cards would be in a row, including the cramped sidebar one. Make each card's wrapper a container (@container) and use @md:flex-row, which looks at the wrapper's own width (Chapter 18).
