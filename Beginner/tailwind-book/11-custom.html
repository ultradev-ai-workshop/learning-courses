Custom Styles, Directives & Detection

Tailwind is extended in CSS, with a handful of directives: at-rules like @utility, @custom-variant and @source. This chapter covers the docs' Adding custom styles, Functions and directives and Detecting classes in source files pages: base styles, your own utilities (simple and with values), your own variants, and exactly how Tailwind decides which classes to generate, including how to add or exclude files and safelist classes.

You will learn

  • How to add base styles in @layer base.
  • How to create utilities with @utility, including functional ones with --value().
  • How to create variants with @custom-variant, and use variants in CSS with @variant.
  • How class detection works and what it ignores.
  • How to use @source to add paths, exclude paths and safelist classes.
  • A summary of every directive and function.

A custom utility behaves like a built-in one: it's only output when used, it's sorted with the other utilities, and it works with every variant:

Compare with a class in @layer components (Chapter 10), which is always output and can't take variants. Rule of thumb: one job, needs variants → @utility; a bundle of styles for a component → @layer components.

Functional utilities: --value()

Add -* to the name to accept a value. --value() says which values are allowed: theme keys, bare values of a type, or arbitrary values in brackets:

A declaration whose --value() doesn't match the class is dropped, which is why grid-fill-48 only kept the first grid-template-columns and grid-fill-[12rem] only the second. --value() accepts:

  • --value(--depth-*): a key from a theme namespace (depth-modal).
  • --value(integer), number, percentage, ratio: a bare value of that type (depth-3).
  • --value([length]), [color], [*]…: an arbitrary value in brackets of that type.
  • --value("inherit", "auto"): literal keywords.

Since v4.3 a functional utility can also have a default for the bare name: --value(integer, --default(4)) makes stack alone mean stack-4. And --modifier() reads the part after a slash, like /50 in bg-sky-500/50.

🧠 Analogy: @utility depth-* is a vending machine. The * is the slot for the button you press, and --value() is the list of buttons that work: named products from the theme, any number, or a custom order in brackets. Press a button that isn't on the list, and nothing comes out.

How Tailwind detects classes

Tailwind doesn't understand HTML, JSX or templates. It reads every source file as plain text, splits it into tokens that could be class names, and generates CSS for the tokens that match a utility. That's why it works with any language, and why it has two quirks.

Quirk 1: dynamic class names don't work. Tailwind sees the text, not the result of your code:

Quirk 2: ordinary words can become classes. Words in your text that happen to be utility names generate CSS. In Chapter 6, the words "resize me" in an example generated a .resize rule. It's harmless: a few unused bytes. (Below, "hidden." isn't picked up because of the full stop after it: a class name can't end with a dot.)

Which files are scanned

Tailwind starts from the current working directory (for the CLI) or the project root (for Vite and PostCSS) and scans every file except:

  • files and folders in your .gitignore;
  • node_modules;
  • binary files (images, videos, zip files);
  • CSS files;
  • common package-manager lock files.

Controlling detection: @source

NeedWrite
Scan a folder that's ignored, e.g. a UI library in node_modules@source "../node_modules/@acme/ui";
Scan only one folder, not the whole project@import "tailwindcss" source("../src");
Turn off automatic detection, list paths yourself@import "tailwindcss" source(none); + @source lines
Exclude a path@source not "./src/legacy";
Always generate some classes (safelist)@source inline("underline");
Never generate a class@source not inline("container");

Paths in @source are relative to the CSS file. A safelist with brace expansion generates many classes at once, useful when class names come from a CMS or database:

{hover:,} means "with hover: or with nothing", and {100,500} lists shades; {100..900..100} would be a range in steps of 100. text-red-500 wasn't generated because source(none) turned off scanning.

Recap

  • Element defaults go in @layer base; utilities override them.
  • @utility name { … } creates a utility that's output on demand and supports variants.
  • @utility name-* { prop: --value(…); } accepts theme keys, bare values and bracket values; --modifier() reads /x; --default() (v4.3) sets the bare name's value.
  • @custom-variant defines variants from selectors or at-rules; @variant uses them inside custom CSS.
  • Detection reads files as plain text: write full class names; stray words may generate harmless CSS.
  • Ignored: .gitignored paths, node_modules, binaries, CSS, lock files. @source adds, excludes (not) and safelists (inline()).

Exercises

Exercise 1 🟢 easy base

Give every h2 a default size of text-xl and weight semibold, in a way utilities can still override.

Show solution

@layer base { h2 { font-size: var(--text-xl); line-height: var(--text-xl--line-height); font-weight: var(--font-weight-semibold); } } (or @apply text-xl font-semibold; inside the rule).

Exercise 2 🟢 easy utility

Create a utility no-scrollbar that sets scrollbar-width: none, and use it only on large screens.

Show solution

@utility no-scrollbar { scrollbar-width: none; } and class="lg:no-scrollbar". (v4.3 also has a built-in scrollbar-none.)

Exercise 3 🟢 easy detection

Will Tailwind generate bg-blue-500 for: className={isActive ? "bg-blue-500" : "bg-white"}? And for className={"bg-" + color + "-500"}?

Show solution

Yes for the first (both full names appear in the file). No for the second (no full name appears).

Exercise 4 🟢 easy source

Your design system's components are in node_modules/@acme/ui. Their classes aren't generated. Fix it from src/app.css.

Show solution

@source "../node_modules/@acme/ui"; (relative to src/app.css), after @import "tailwindcss";.

Exercise 5 🟡 medium functional

Write a utility stack-* that makes a vertical flex column with a gap of N spacing units, where plain stack means stack-4.

Show solution

@utility stack-* { display: flex; flex-direction: column; gap: --spacing(--value(integer, --default(4))); }

Exercise 6 🟡 medium variant

Create a variant rtl-only that applies when the element is inside dir="rtl", and use it to flip an arrow icon.

Show solution

@custom-variant rtl-only (&:where([dir="rtl"] *)); and class="rtl-only:-scale-x-100". (Tailwind already has rtl: and ltr: variants; this is for practice.)

Exercise 7 🟡 medium safelist

Editors may pick a background from bg-{red,amber,emerald}-{100,200} in a CMS. Safelist exactly those six classes.

Show solution

@source inline("bg-{red,amber,emerald}-{100,200}");

Exercise 8 🟡 medium playground

In chapters/11/ define a depth-* utility with three named layers from the theme, and a hocus variant. Use both on a dropdown button and its menu. Then check output.css: is --depth-toast there if you don't use depth-toast?

Show solution

No: like other theme variables, it's only output when a utility uses it. Use @theme static if you need it anyway.

Exercise 9 🔴 hard monorepo

A monorepo has apps/web/src/app.css, apps/web/src/**, packages/ui/src/** and a huge apps/web/src/generated/ folder with no classes. Write the CSS to scan exactly the web app's source and the UI package, minus generated.

Show solution

@import "tailwindcss" source(none); then @source "./"; (the src folder), @source "../../../packages/ui/src";, and @source not "./generated";.

Exercise 10 🔴 hard explain

Explain why @utility classes support hover: but classes in @layer components don't.

Show solution

@utility registers a name with Tailwind's engine, so when it sees hover:name it knows how to generate a rule for that candidate. A class in @layer components is plain CSS that Tailwind just passes through; the engine doesn't know name is a utility, so hover:name matches nothing.
