Theme Variables & Colors

Every design decision behind Tailwind's utilities (colours, spacing, fonts, breakpoints, shadows) is a theme variable defined with the @theme directive. Adding a variable adds utilities; changing one changes every utility that uses it. This chapter covers the docs' Theme variables and Colors pages: namespaces, extending and overriding the theme, inline and static, sharing a theme between projects, and how colours and opacity work.

You will learn

  • What @theme does that :root doesn't.
  • Theme namespaces: which variable prefix creates which utilities.
  • How to extend, override and replace the default theme.
  • The inline and static options, and sharing a theme across projects.
  • The default palette, OKLCH, opacity modifiers, and using colours in your own CSS.

The @theme directive

Add a colour to your theme, and Tailwind creates every colour utility for it:

Those are the colour variables in the theme layer of the output (the layer also has the fonts and --spacing, which Preflight and the utilities use). Your variable is written to :root like the defaults, so you can use var(--color-mint-500) anywhere. So why not just write it in :root yourself? Because a plain CSS variable creates no utilities. @theme tells Tailwind "this is a design token; make classes for it". Use @theme for values you want utilities for, :root for other variables.

Namespaces

The variable's name decides which utilities it creates. --color-* feeds every colour utility, --font-* the font- family utilities, and so on:

NamespaceUtility classes
--color-*bg-red-500, text-sky-300, border-*, fill-*, shadow-*…
--font-*font-sans, font-mono (family)
--text-*text-xl (font size)
--font-weight-*font-bold
--tracking-*tracking-wide (letter spacing)
--leading-*leading-tight (line height)
--breakpoint-*sm:* and other responsive variants
--container-*@sm:* container variants, max-w-md
--spacingpx-4, mt-8, w-12… (all spacing and sizing)
--radius-*rounded-sm
--shadow-*, --inset-shadow-*, --drop-shadow-*, --text-shadow-*shadow-md, inset-shadow-xs, drop-shadow-lg, text-shadow-sm
--blur-*blur-md
--perspective-*perspective-near
--aspect-*aspect-video
--ease-*ease-out
--animate-*animate-spin

🧠 Analogy: the theme is a paint shop's colour catalogue, and namespaces are its sections: paints, brushes, rollers. When you add "mint" to the paints section, every product that takes a paint (walls, doors, trims; bg, text, border) can now order it. A new entry in the rollers section (--radius-*) does nothing for paints.

Referencing other variables: @theme inline

When a theme variable points to another variable, the utility uses var(--color-…), and CSS resolves the inner variable where the theme variable is defined (on :root), not where the utility is used. That can give surprising results when the inner variable changes on a child. @theme inline writes the value straight into the utility instead:

This is exactly the "semantic colours" pattern from Chapter 7: a --surface that changes in dark mode, registered with @theme inline.

Colours

The default palette has 26 colour names × 11 shades, defined in OKLCH: oklch(lightness chroma hue). OKLCH is a colour space where equal steps in lightness look equal, and it can express the more vivid colours of modern P3 displays. You use colours by name, so the format rarely matters, except when you define your own: any CSS colour works (#hex, rgb(), hsl(), oklch()).

Opacity

Add / and a number to any colour utility for opacity. Values in steps of 5 are typical, but any number, an arbitrary value, or a variable works:

Special colours

  • current: the element's text colour (currentColor). border-current makes the border match the text.
  • transparent, inherit: as in CSS.
  • black and white: no shades.

Recap

  • @theme defines design tokens: CSS variables that also create utilities. Plain :root variables create none.
  • The namespace (--color-*, --font-*, --breakpoint-*…) decides which utilities a variable feeds.
  • New names extend the theme; existing names override; --color-*: initial clears a namespace; --*: initial clears everything.
  • @theme inline for variables that reference other variables; @theme static to output every variable.
  • Share themes by importing a CSS file.
  • The palette is OKLCH; /50, /[33%], /(--var) set opacity via color-mix().
  • In custom CSS use var(--color-…), --alpha() and --spacing().

Exercises

Exercise 1 🟢 easy namespace

Which namespace would you use to add: (a) a rounded-pill radius, (b) a font-brand typeface, (c) a shadow-glow?

Show solution

(a) --radius-pill; (b) --font-brand; (c) --shadow-glow.

Exercise 2 🟢 easy add

Add a colour tangerine (#f28500) to the theme and use it as a button background.

Show solution

@theme { --color-tangerine: #f28500; } and <button class="bg-tangerine">.

Exercise 3 🟢 easy @theme vs :root

You put --color-tangerine: #f28500; inside :root { } instead. Does bg-tangerine work? Why?

Show solution

No. Only @theme variables create utilities; a :root variable is just CSS. You could still write bg-(--color-tangerine).

Exercise 4 🟢 easy opacity

Write a black overlay at 40% opacity that covers its parent.

Show solution

<div class="absolute inset-0 bg-black/40"></div> (the parent needs relative).

Exercise 5 🟡 medium replace

A company allows only four colours: white, black, #0047ab (cobalt) and #ffd700 (gold). Configure the theme so no other colour utilities exist.

Show solution

@theme { --color-*: initial; --color-white: #fff; --color-black: #000; --color-cobalt: #0047ab; --color-gold: #ffd700; }

Exercise 6 🟡 medium compute

With --spacing: 0.2rem, what are p-10 and w-50 in pixels? What about w-1/2?

Show solution

p-10 = 2 rem = 32 px; w-50 = 10 rem = 160 px. w-1/2 is a fraction (50%) and doesn't use --spacing.

Exercise 7 🟡 medium inline

Explain in your own words when you need @theme inline rather than @theme.

Show solution

When a theme variable's value is another variable (var(--accent)) that can change on different elements (per theme, per component). With plain @theme the utility points to --color-accent, which was resolved once on :root; with inline the utility uses var(--accent) directly, so it picks up the nearest value.

Exercise 8 🟡 medium playground

In chapters/08/, create theme.css with your own brand colour (three shades), a display font and a --radius-card. Import it from the main CSS and build a card that uses all of them.

Show solution

theme.css: @theme { --color-brand-100: …; --color-brand-500: …; --color-brand-900: …; --font-display: …; --radius-card: 1.25rem; }. Main CSS: @import "tailwindcss"; @import "./theme.css";. Card: class="rounded-card bg-brand-100 p-6" with a font-display text-brand-900 heading.

Exercise 9 🔴 hard debug

JavaScript reads getComputedStyle(document.documentElement).getPropertyValue("--color-sky-500") and gets an empty string, although Tailwind is installed. Why? Give two fixes.

Show solution

Only variables used by some utility are emitted, and no class uses sky-500. Fixes: use @theme static { … } for the variables JavaScript needs (or @import "tailwindcss" theme(static); for all), or define your own :root variable for JavaScript.

Exercise 10 🔴 hard design system

Design a theme file for a design system with: a single brand hue in 5 shades, semantic surface/ink colours that change in dark mode, a 4-step type scale, and no default colours. Which parts go in @theme, which in @theme inline, and which in :root?

Show solution

@theme: --color-*: initial, the five --color-brand-* shades, white/black, and the --text-* sizes (with --text-*--line-height). :root and a dark block: --surface and --ink raw values. @theme inline: --color-surface: var(--surface); --color-ink: var(--ink); so the utilities follow the mode.
