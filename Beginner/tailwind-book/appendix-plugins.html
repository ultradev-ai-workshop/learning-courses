Appendix B

Plugins: Typography & Forms

Tailwind's core only has utilities. Two official plugins cover the common gaps: Typography styles long-form content you can't add classes to (Markdown, CMS output), and Forms gives form controls a clean, consistent base that's easy to restyle with utilities. In v4, you load a plugin with one line of CSS: @plugin. This appendix shows both, and how to write a tiny plugin of your own.

You will learn

  • How to load JavaScript plugins with @plugin.
  • How to style Markdown and CMS content with prose, size and colour modifiers, dark:prose-invert and not-prose.
  • How to customise prose elements with prose-a:, prose-headings: and friends.
  • What the Forms plugin does, and its class strategy.
  • When to write your own plugin, and when @utility is enough.

The Typography plugin

Now wrap content in prose. Every element inside gets sensible typography: heading sizes, paragraph spacing, list bullets, link and code styles, quotes and tables:

None of those elements has a class. That's exactly the situation of HTML generated from Markdown.

🧠 Analogy: Preflight strips every element bare, which is great for building UI but bad for reading an article. prose is a typesetter you hire for one region of the page: inside it, headings, paragraphs and lists get professional default typography; outside it, you're back to utilities.

Element modifiers

To change one kind of element inside prose, use prose-{element}: variants: prose-headings:, prose-a:, prose-p:, prose-li:, prose-img:, prose-code:, prose-blockquote: and more.

The Forms plugin

Browsers draw form controls in their own style, and some of those styles are hard to override. @tailwindcss/forms resets inputs, selects, checkboxes and radios to a simple, consistent look that utilities can then change:

Note text-sky-600 on the checkbox: the plugin draws checkboxes so their colour follows currentColor, and focus:ring-* styles the focus ring it adds.

If you only want the plugin's styles on elements you choose, use the class strategy: @plugin "@tailwindcss/forms" { strategy: "class"; }, then add form-input, form-select, form-checkbox where you want them.

Only the .form-input class gets the plugin's styles; plain inputs on the page are left alone.

Writing your own plugin

For most needs, @utility and @custom-variant in CSS are simpler (Chapter 11). A JavaScript plugin is useful when you generate many utilities from data, or share something as an npm package. The v3 plugin API still works; load a local file with a path:

The same thing in CSS is three lines: @utility text-stroke-* { -webkit-text-stroke-width: --value([length]); -webkit-text-stroke-width: calc(--value(integer) * 1px); }. Prefer CSS unless you're publishing a package.

Recap

  • Load plugins with @plugin "package-or-path"; in your CSS.
  • prose styles uncontrolled HTML; size with prose-lg, grey with prose-slate, dark with dark:prose-invert, opt out with not-prose.
  • prose-a:, prose-headings:… customise individual elements.
  • @tailwindcss/forms normalises inputs, selects and checkboxes; strategy: "class" limits it to form-* classes.
  • JavaScript plugins (matchUtilities, addUtilities) still work, but @utility is usually enough.

Exercises

Exercise 1 🟢 easy setup

Write the two lines that add Tailwind and the Typography plugin to a CSS file.

Show solution

@import "tailwindcss"; and @plugin "@tailwindcss/typography";

Exercise 2 🟢 easy prose

Style a blog post body: prose, large on desktop, zinc greys, light text in dark mode.

Show solution

<article class="prose prose-zinc lg:prose-lg dark:prose-invert">

Exercise 3 🟢 easy width

Your prose content should fill its container instead of stopping at 65 characters. Which class?

Show solution

max-w-none

Exercise 4 🟢 easy not-prose

A newsletter sign-up box in the middle of an article picks up prose margins and link styles. Fix it.

Show solution

Add not-prose to the box's wrapper and style it with utilities.

Exercise 7 🟡 medium playground

In chapters/appendix-b/ there's a Markdown file converted to HTML. Style it with prose, then add a dark-mode toggle and check dark:prose-invert.

Show solution

Wrap the content in <article class="prose dark:prose-invert">, add @plugin "@tailwindcss/typography"; to the page's CSS, and reuse the toggle from Chapter 7.

Exercise 8 🟡 medium strategy

Why might you choose the Forms plugin's class strategy in an existing app?

Show solution

The default (base) strategy restyles every input on the site, which can break third-party widgets or forms that already have their own styles. With strategy: "class" nothing changes until you add form-input etc., so you can adopt it gradually.

Exercise 9 🔴 hard plugin vs utility

Rewrite the text-stroke plugin as a CSS @utility that accepts integers (pixels) and arbitrary lengths.

Show solution

@utility text-stroke-* { -webkit-text-stroke-width: calc(--value(integer) * 1px); -webkit-text-stroke-width: --value([length]); }. Only the declaration whose --value() matches the class is kept.

Exercise 10 🔴 hard design

A documentation site has Markdown pages with custom "callout" boxes written as <div class="callout">. How do you style the callouts and keep prose styles for everything else?

Show solution

Keep prose on the wrapper and define .callout in @layer components with @apply or theme variables. Prose styles still apply to the paragraphs inside the callout; if you don't want that, add not-prose to the callout in the Markdown renderer's output.
