Installing Tailwind

Tailwind runs as part of your build. The docs offer four ways to plug it in: a Vite plugin (the recommended one), the Tailwind CLI, a PostCSS plugin, and a Play CDN script for quick experiments. All four use the same engine and produce the same CSS. This chapter installs each one, shows what @import "tailwindcss" really imports, and explains the build commands you'll run every day.

You will learn

  • How to add Tailwind to a Vite project, and how to build it for production.
  • How to use the standalone Tailwind CLI, including watch mode and minification.
  • How to use the PostCSS plugin (the way frameworks like Next.js use it).
  • What the Play CDN is for, and why not to use it in production.
  • What @import "tailwindcss" expands to, and which install to pick.

🧠 Analogy: the four install options are four ways to get the same coffee. The Vite plugin is a machine built into your kitchen counter (your build tool). The CLI is a standalone machine you switch on yourself. PostCSS is a pod that fits machines other brands already make (Next.js, webpack setups). The Play CDN is instant coffee: fine for a quick taste, not what you serve guests.

Option 2: the Tailwind CLI

The CLI needs no other build tool. It reads a CSS file, scans the folder for class names, and writes a CSS file. It's ideal for plain HTML sites, server-rendered templates (Django, Rails, Laravel, Spring), and for learning, which is why most examples in this book use it.

Build once, and keep the generated file next to your HTML:

During development, add --watch (or -w): the CLI stays running and rebuilds every time you save a file. For production, add --minify:

--silent (new in 4.3.1) hides the version and timing lines. The main options, from npx @tailwindcss/cli --help:

OptionWhat it does
-i, --inputThe CSS file with @import "tailwindcss".
-o, --outputWhere to write the result (default: print to the terminal).
-w, --watchRebuild when files change.
-m, --minifyOptimise and minify the output.
--optimizeOptimise without minifying.
--cwdThe folder to scan from (default: the current folder).
--mapWrite a source map.
--silentPrint errors only.

💡 Put the commands in package.json scripts so nobody has to remember them: "dev": "tailwindcss -i ./input.css -o ./output.css --watch" and "build": "tailwindcss -i ./input.css -o ./output.css --minify". Inside scripts you can drop npx and the package name: the installed command is called tailwindcss.

📝 No Node.js at all? Tailwind also publishes a standalone executable of the CLI for macOS, Linux and Windows on its GitHub releases page. It works the same way: ./tailwindcss -i input.css -o output.css.

Option 3: PostCSS

PostCSS is a tool that transforms CSS with plugins. Many frameworks already run PostCSS on your CSS, so Tailwind can plug in as one more plugin. This is the setup the Tailwind docs use for Next.js and Angular (and the one you'll use in the capstone).

Option 4: the Play CDN

For a quick experiment in a single HTML file, with no install at all, add one script tag. It runs Tailwind in the browser: it watches the page and generates styles as classes appear.

⚠️ The Play CDN is for development only. Every visitor downloads the whole Tailwind engine (hundreds of kilobytes of JavaScript) and generates the CSS on their own device, and the page flashes unstyled content while it loads. For anything you publish, use one of the build options above.

You can customise the CDN version with a <style type="text/tailwindcss"> block containing @theme and other directives (Chapter 8). The official Tailwind Play website is an online editor built on the same idea.

What @import "tailwindcss" imports

The line imports the package's index.css, which is the same as these four lines:

  • theme.css holds the default design tokens: 26 colour palettes, the spacing unit, font sizes, breakpoints, shadows… as @theme variables.
  • preflight.css is the reset (base styles).
  • utilities.css contains one line, @tailwind utilities;, the spot where generated utilities are inserted.

Knowing this lets you leave parts out. For example, a project that already has its own reset can skip Preflight by writing the lines without preflight.css:

Without Preflight the h1 keeps the browser's default size (2 em) and margins. With Preflight, headings have no margin and inherit the body's font size, as you'll see in Chapter 3.

Recap

  • Every setup needs the tailwindcss package plus one integration: @tailwindcss/vite, @tailwindcss/cli or @tailwindcss/postcss.
  • Your CSS needs one line: @import "tailwindcss";.
  • Vite: add tailwindcss() to plugins; npm run dev while working, npm run build to publish.
  • CLI: npx @tailwindcss/cli -i input.css -o output.css, with --watch in development and --minify for production.
  • PostCSS: a postcss.config.mjs with "@tailwindcss/postcss": {}; your framework runs it.
  • The Play CDN runs Tailwind in the browser: for experiments only.
  • @import "tailwindcss" = theme + Preflight + utilities, each in its layer.

Exercises

Exercise 1 🟢 easy recall

Name the npm packages you install for (a) a Vite project, (b) the CLI, (c) PostCSS.

Show solution

(a) tailwindcss @tailwindcss/vite; (b) tailwindcss @tailwindcss/cli; (c) tailwindcss @tailwindcss/postcss postcss.

Exercise 2 🟢 easy command

Write the CLI command that reads src/input.css, writes src/output.css, and rebuilds whenever you save.

Show solution

npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --watch

Exercise 3 🟢 easy choose

Which install would you pick for: (a) a Svelte app made with Vite, (b) a Django site with server-rendered templates, (c) a Next.js app, (d) a one-off test page you'll delete tomorrow?

Show solution

(a) @tailwindcss/vite; (b) the CLI (or standalone executable) with --watch; (c) @tailwindcss/postcss as in the Tailwind docs' Next.js guide; (d) the Play CDN.

Exercise 4 🟢 easy why

Give two reasons not to use the Play CDN on a public website.

Show solution

Every visitor downloads the whole engine as JavaScript and builds the CSS on their device (slow, wasteful); the page shows unstyled content until the script runs; it needs JavaScript enabled; you depend on a third-party CDN at runtime.

Exercise 5 🟡 medium playground

In the playground, run npm run dev and open /chapters/02/. Change the heading's text-3xl to text-5xl and save. What happens in the browser, and did you rebuild anything yourself?

Show solution

The heading grows immediately. Vite's dev server noticed the change, the Tailwind plugin generated the new text-5xl rule, and Vite pushed the updated CSS to the page (hot module replacement). No manual build.

Exercise 6 🟡 medium scripts

A CLI project has no scripts. Add dev and build scripts to its package.json for an input css/app.css and output public/app.css.

Show solution

"dev": "tailwindcss -i ./css/app.css -o ./public/app.css --watch", "build": "tailwindcss -i ./css/app.css -o ./public/app.css --minify".

Exercise 7 🟡 medium expand

Write the four lines @import "tailwindcss" stands for. Which line would you remove to keep your own reset instead of Preflight?

Show solution

@layer theme, base, components, utilities;, @import "tailwindcss/theme.css" layer(theme);, @import "tailwindcss/preflight.css" layer(base);, @import "tailwindcss/utilities.css" layer(utilities);. Remove the preflight.css line.

Exercise 8 🟡 medium explain

The minified CSS in this chapter is about 600 bytes (11%) smaller than the normal one. Where does the saving come from, given that both contain the same rules?

Show solution

Whitespace, line breaks, indentation and comments are removed, and values are written in their shortest form. The rules are the same; only the formatting changes. Compression on the server (gzip or Brotli) shrinks it much further.

Exercise 9 🔴 hard debug

Someone's Vite project shows unstyled HTML. Their style.css has @import "tailwindcss";, the classes are correct, and the package is installed. List three things to check, in order.

Show solution

(1) vite.config imports @tailwindcss/vite and has tailwindcss() in plugins. (2) The HTML (or the JavaScript entry) actually loads the CSS: a <link href="/src/style.css"> or import './style.css'. (3) The dev server was restarted after changing the config, and the browser DevTools Network tab shows the CSS loading. Also check the files are not in a folder ignored by .gitignore (Chapter 11).

Exercise 10 🔴 hard build it

Without looking, set up a new folder with the CLI from scratch: package.json, an input file, an HTML page with a blue rounded button, and dev/build scripts. Build it and confirm the button rule is in the output with a grep.

Show solution

mkdir demo && cd demo && npm init -y && npm install tailwindcss @tailwindcss/cli; input.css with @import "tailwindcss";; index.html linking ./output.css with <button class="rounded-lg bg-blue-600 px-4 py-2 text-white">; scripts as in "More examples"; npm run build; grep -c "bg-blue-600" output.css prints 1 when minified (one line), or check with grep -A2 "\.bg-blue-600" before minifying.
