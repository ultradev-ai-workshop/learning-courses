Functions & Closures

Functions are values in JavaScript: you pass them, return them and store them. This chapter covers the ES6 function features (arrows, default and rest parameters), the rules behind this, and closures, the idea that powers callbacks, factories and private state.

You will learn

  • The four ways to create a function, and how they differ.
  • Default parameters, rest parameters and spread arguments ES2015.
  • Arrow functions and lexical this.
  • The rules that decide this: plain call, method call, call/apply/bind, new.
  • Closures: what they are, the loop-var trap, and practical uses.

Four ways to create a function

Functions are objects: they have properties such as name and length (the number of declared parameters before the first default or rest parameter), and they can be passed to and returned from other functions. A function that takes or returns a function is a higher-order function.

Parameters ES2015

Default parameters

A default applies only when the argument is undefined (missing, or passed as undefined), not for null, 0 or "". Defaults are evaluated at call time, and they can use earlier parameters.

Rest parameters and the old arguments object

...rest collects the remaining arguments into a real array. It replaces the old arguments object, which is array-like but not an array, and doesn't exist in arrow functions.

Arrow functions ES2015

  • Concise body: x => x * 2 returns the expression. With braces, x => { return x * 2; }, you need return.
  • To return an object literal, wrap it in parentheses: () => ({ ok: true }).
  • Arrows have no own this, arguments, super or new.target. They use the ones of the surrounding code (lexical this).
  • Arrows can't be used with new and have no prototype.

How this is decided

For normal functions, this is decided by how the function is called, not where it's defined. Check the rules in this order:

The classic bug: losing this in a callback

❌ A regular callback gets its own this

✅ An arrow keeps the method's this

💡 Rule of thumb: use method shorthand for object and class methods (they need their own this) and arrows for callbacks inside them (they should share the method's this).

☕ Java: Java's this is fixed to the instance, always. JavaScript's this is a hidden parameter, filled in at call time. That's why passing obj.method around "forgets" obj, a mistake Java never lets you make.

Closures

A closure is a function together with the variables it can see from the scope where it was created. The inner function keeps those variables alive even after the outer function has returned.

Analogy: a function leaves home with a backpack. Inside are the variables from where it was born. It carries the backpack wherever it goes, and it can still read and change what's inside.

Each call to makeCounter creates a new count, so orders and invoices don't share state.

The loop-var trap

❌ var: one shared variable

✅ let: a fresh binding per iteration

Closures capture variables, not values. With var there is only one i, which is 3 by the time the functions run. With let, each iteration gets its own i. This was one of the main motivations for let.

📝 Older syntax you'll still see: the IIFE, an immediately invoked function expression, (function () { var private = 1; })();. It was used to create a private scope before block scope and modules existed. Today a { } block or a module does the job.

Recap

  • Function declarations are hoisted. Expressions and arrows are values assigned like any other.
  • Defaults apply only for undefined and are evaluated per call. ...rest is a real array, replacing arguments.
  • Arrows have lexical this and no arguments, and they can't be constructors. Wrap returned object literals in ( ).
  • this is decided at call time: new > call/apply/bind > method call > plain call (undefined in strict mode).
  • Closures capture variables. let in loops gives one binding per iteration. Closures power private state, memoization and debouncing.

Exercise 9 🔴 hard explain why
