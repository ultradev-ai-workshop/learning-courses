Grammar, Types & Declarations

let and const replaced var for good reasons. This chapter shows exactly what changed, including hoisting and the "temporal dead zone", and then tours JavaScript's eight data types and their literals.

A few grammar basics

  • JavaScript is case-sensitive and uses Unicode: total and Total are different names, and prix_€ is a valid identifier.
  • Comments are // line and /* block */. A #!/usr/bin/env node shebang is allowed as the very first line.
  • Statements end with ;. Automatic semicolon insertion (ASI) adds missing ones, but it has traps, so most style guides either always write semicolons or use a formatter.

const means "constant binding", not "frozen value"

const stops you from re-assigning the name. If the value is an object, you can still change what's inside it. To make the object itself unchangeable, use Object.freeze, which is shallow: nested objects stay mutable.

(The assignment to a frozen property was silently ignored, because the REPL runs in sloppy mode. In a module it would throw a TypeError.)

💡 Default to const, use let when you really re-assign, and don't use var in new code. Seeing let then tells the reader "this changes later".

☕ Java: const is like final on a reference: final List<String> l can still be added to. JavaScript variables have no declared type; the value carries the type.

Hoisting and the temporal dead zone

Before running a scope, the engine registers every declaration in it. This is called hoisting. What a name holds before its declaration line runs depends on how it was declared:

  • var: the name exists and is undefined.
  • function declarations: fully hoisted, so you can call them before the line that defines them.
  • let, const, class: the name exists, but touching it throws a ReferenceError until the declaration runs. That gap is the temporal dead zone (TDZ).

⚠️ Pitfall: function expressions are not fully hoisted. const f = () => … is a const, so calling f() above that line throws. Only function name() {} declarations can be called early.

The TDZ is about time, not position: a function can mention a let variable declared below it, as long as the function is called after the declaration has run.

💡 Reliable type checks: x === null for null, Array.isArray(x) for arrays, Number.isNaN(x) for NaN, and x instanceof Date for class instances. typeof is best for primitives and functions.

undefined vs null

Both mean "no value", by convention in different ways. undefined is what the language gives you (a missing property, a missing argument, a function with no return). null is what programmers write on purpose to say "intentionally empty". Many codebases check for both with x == null, the one widely accepted use of ==, or with x ?? fallback (Chapter 5).

Symbols, in one paragraph

Every Symbol() call creates a unique value, so it can be used as an object key that never collides with string keys. The built-in "well-known" symbols such as Symbol.iterator let you hook into language features (Chapters 13 and 15).

Primitives vs references

Assigning a primitive copies the value. Assigning an object copies a reference to the same object, just as in Java.

Comparing objects with === compares identity: {} === {} is false. Chapter 5 covers equality in depth.

Recap

  • Use const by default and let when you re-assign. var is function-scoped, re-declarable and hoisted as undefined.
  • let, const and class are in the TDZ until their line runs. Function declarations are fully hoisted.
  • const freezes the binding, not the value. Object.freeze is shallow.
  • There are seven primitives plus objects. typeof null === "object", so use Array.isArray and Number.isNaN for those checks.
  • Primitives copy by value and objects by reference. structuredClone makes a deep copy.
