Modern JavaScript & ECMAScript

You can already write JavaScript. This chapter gives you the map: how the language is versioned, what ES6 changed, where your code runs, and the two modes (scripts and modules) that quietly change the rules.

JavaScript, ECMAScript, engines and runtimes

Four words get mixed up all the time. Keeping them apart explains a lot of "why does this work here but not there?" moments.

WordMeaningExamples
ECMAScriptThe language specification (ECMA-262): syntax, types, built-in objects like Array and PromiseES5, ES2015 (ES6), ES2025
JavaScriptThe everyday name for ECMAScript plus whatever the host adds—
EngineThe program that parses and runs the languageV8 (Chrome, Node), SpiderMonkey (Firefox), JavaScriptCore (Safari)
Runtime / hostAn engine plus extra APIs for its environmentBrowsers add document, fetch; Node adds fs, process; also Deno and Bun

So Array.prototype.map is language and works everywhere, while document.querySelector is a browser API and doesn't exist in Node. This book teaches the language and uses Node 26 to run it. When an example needs a browser, it says so.

☕ Java: despite the name, JavaScript is not related to Java. The syntax looks similar (braces, if, for), but JavaScript is dynamically typed, uses prototypes instead of class-based inheritance under the hood, and has first-class functions. The name was a 1995 marketing decision.

How the language evolves

A committee called TC39 designs new features. Each proposal moves through numbered stages: 0 (idea), 1 (proposal), 2 (draft), 2.7 (approved in principle, needs tests), 3 (ready to implement), and 4 (finished). Everything that reaches stage 4 by early in the year goes into that year's edition. Engines often ship a feature at stage 3, before it's officially "in" the standard.

Throughout the book, a badge like ES2015 or ES2023 shows when a feature arrived. Blue badges mark ES6 features; the yellow ones are later.

📝 Why "ES6" and "ES2015" both exist: the sixth edition was released in 2015. After it, TC39 switched to yearly releases named after the year, so there is no "ES7" in official use, though people still say it.

Strict mode

ES5 introduced strict mode, an opt-in variant of the language that turns silent mistakes into errors and removes a few confusing features. You turn it on by putting the string "use strict"; at the very top of a script or a function.

SituationSloppy modeStrict mode
Assigning to an undeclared variablesilently creates a globalReferenceError
this in a plain function callthe global objectundefined
Writing to a read-only propertysilently ignoredTypeError
Duplicate parameter names function f(a, a)allowedSyntaxError
with statement, octal literals like 010allowedSyntaxError

💡 Good news: you rarely write "use strict" yourself today. Modules and class bodies are always strict. Since this book uses modules everywhere, you get strict mode for free.

Scripts vs modules

The same code can behave differently depending on whether it's loaded as a classic script or as a module (an ES module, or ESM, covered fully in Chapter 14).

⚠️ Pitfall: copy a snippet that uses import into a plain .js file, run it in a folder with no package.json, and older Node versions throw SyntaxError: Cannot use import statement outside a module. Node 22+ detects ESM syntax automatically, but the clear fix is to use .mjs, or to add "type": "module" to package.json, as the book's playground does.

Recap

  • ECMAScript is the spec, engines run it, and runtimes (browsers, Node) add host APIs.
  • TC39 ships a new edition every year. ES6/ES2015 was the big modernisation.
  • Run code with the Node REPL, node file.js, or the browser console.
  • Strict mode turns silent bugs into errors, and modules and classes are always strict.
  • Modules have private top-level scope, this === undefined at the top, import/export and top-level await.

Exercise 8 🟡 medium explain why

A teammate says: "This feature is stage 3, so it's part of ES2025." Is that right?

Show solution

No. Stage 3 means the design is finished and engines may ship it, but it only joins an edition after reaching stage 4 (two shipping implementations and tests). Many stage-3 features are already usable in Node or browsers, but they're not "in" the standard yet.
