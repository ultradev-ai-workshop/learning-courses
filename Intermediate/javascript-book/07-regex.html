Regular Expressions

Regular expressions are a small language for describing text patterns. JavaScript's regex engine gained a lot since ES5: named groups, lookbehind, Unicode properties, matchAll, new flags and RegExp.escape.

You will learn

  • How to create a regex: literals vs the RegExp constructor, and escaping user input.
  • Character classes, quantifiers, anchors, groups and backreferences.
  • Named groups and lookbehind ES2018, Unicode property escapes.
  • The flags g i m s u y d v, and what each changes.
  • test, exec, match, matchAll ES2020, replace and split, plus the stateful lastIndex trap.

Creating a regular expression

⚠️ Pitfall: never put raw user input into new RegExp(input). Characters like ., + and ( have special meanings, and a malicious pattern can freeze your program (catastrophic backtracking). Use RegExp.escape ES2025. (Notice that it even escapes a leading letter, as \x61, so that the result is safe in any position.)

Pattern syntax

PatternMatches
.any character except line breaks (unless the s flag is set)
\d \w \s / \D \W \Sa digit, a word character [A-Za-z0-9_], whitespace / their opposites
[aeiou] [^,] [a-z]one character from a set / not in a set / a range
\p{L}, \p{Lu}, \p{Emoji}Unicode properties: any letter, an uppercase letter, an emoji (needs u or v)
* + ? {2} {2,5} {2,}0+, 1+, 0 or 1, exactly 2, 2 to 5, at least 2 times
*? +? ??lazy versions: match as little as possible
^ $ \b \Bstart, end, word boundary, not a boundary
(…) (?:…) (?<name>…)capturing group, non-capturing group, named group ES2018
\1 \k<name>backreference to a group's text
a|balternation
(?=…) (?!…)lookahead: followed by / not followed by
(?<=…) (?<!…)lookbehind: preceded by / not preceded by ES2018

The first of the last two examples is a classic surprise. The goal was "numbers not followed by ' qty'". 100 is followed by " qty", so the lookahead fails, and the engine backtracks: it tries the shorter 10, which is followed by 0, not " qty". So 10 matches, and you get #0. Adding \d to the negative lookahead, (?!\d| qty), forbids stopping in the middle of a number. Always test lookarounds on real data.

Named groups ES2018

Named groups make patterns self-documenting, and they show up on match.groups. In replace, refer to them with $<name>.

The lastIndex trap

A regex with g or y remembers where its last match ended, in lastIndex. Reusing the same regex object with test or exec continues from there, which leads to alternating results.

Recap

  • Use literals for fixed patterns and new RegExp for dynamic ones; escape user input with RegExp.escape.
  • Quantifiers are greedy unless you add ?. Use \b for word boundaries, and lookarounds to check context without consuming it.
  • Named groups give readable match.groups, and $<name> in replacements.
  • Flags: g i m s u y d v. Use u or v for Unicode-correct matching.
  • Use matchAll for full details of every match. Never share a g regex for test() checks.

Exercise 4 🟢 easy explain why

Why does /^\p{L}+$/.test("Émile") throw or misbehave without a flag, and what fixes it?

Show solution

Without u (or v), \p is just an escaped "p", so the pattern means "one or more p's followed by {L}", and it fails. Adding the u flag enables Unicode property escapes: /^\p{L}+$/u.
