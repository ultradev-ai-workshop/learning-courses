Control Flow, Errors & Loops

Branching, exceptions and loops look familiar, but each has sharp edges: falsy values, switch fall-through, finally overriding return, and the crucial difference between for…in and for…of.

  • The built-in error types, and how to write your own error class.
  • Every loop: for, while, do…while, labels, break/continue.
  • for…in (keys) vs for…of (values) ES2015, and when to use which.

Conditions and truthiness

An if condition doesn't need a boolean: JavaScript converts the value. Exactly eight values are falsy, and everything else is truthy, including "0", "false", [] and {}.

Falsy values
false · 0 · -0 · 0n · "" · null · undefined · NaN

⚠️ Pitfall: if (qty) treats a real quantity of 0 as "missing". When 0 or "" are valid values, test explicitly: if (qty !== undefined), or use ?? (Chapter 5).

switch compares with ===, and falls through

switch compares with strict equality (===), and execution falls through into the next case unless you break or return. Wrap a case body in { } if you declare let/const inside it, because all cases share one block scope.

Exceptions

throw can throw any value, but always throw an Error (or a subclass): it records a stack trace, and the code that catches it can rely on .name and .message.

break, continue and labels

A label names a loop, so that break or continue can target an outer loop. It's rare, but it's the clean way to leave nested loops.

Recap

  • Eight values are falsy. Test explicitly when 0 or "" are valid.
  • switch uses === and falls through without break/return.
  • Throw Error objects. catch {} needs no binding, wrap errors with { cause }, and never return from finally.
  • Extend Error for domain errors, and re-throw what you don't handle.
  • for…of gives values, for…in gives string keys (even inherited ones). Use entries() for indexes, and labels to break out of nested loops.

Exercise 4 🟢 easy explain why

Why should you throw new Error("x") rather than throw "x"?

Show solution

An Error carries a stack trace, plus name, message and optionally cause. Code that catches it can use instanceof and those properties. A thrown string has none of that, and is hard to debug.

Exercise 9 🔴 hard explain why

Why can't you stop array.forEach with break? Give two alternatives for "stop at the first match".

Show solution

The forEach callback is a separate function; break is only valid inside a loop statement, and return just ends that one callback call. Alternatives: a for…of loop with break, or methods that stop early by design: find, findIndex, some and every (Chapter 8).
