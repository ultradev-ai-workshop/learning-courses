Operators, Destructuring & Equality

Modern JavaScript added operators that remove whole lines of defensive code (?., ??, ??=) and syntax that unpacks data in one step (destructuring and spread). This chapter also settles the == vs === question for good.

You will learn

  • Arithmetic quirks: **, % with negatives, + with strings.
  • && and || return operands; optional chaining ?. and nullish coalescing ?? ES2020.
  • Logical assignment ??=, ||=, &&= ES2021.
  • Array and object destructuring, and spread ES2015 ES2018.
  • ==, === and Object.is: three kinds of sameness.

Arithmetic and string operators

  • ** ES2016 is right-associative: 2 ** 3 ** 2 is 2 ** 9.
  • % is a remainder: its sign follows the left operand (like Java, unlike Python's modulo).
  • + concatenates as soon as either side is a string; the other arithmetic operators convert to numbers.

⚠️ Pitfall: -2 ** 2 is a SyntaxError. JavaScript refuses to guess whether you mean (-2) ** 2 or -(2 ** 2), so add parentheses.

Logical operators return values

a || b returns a if it's truthy, otherwise b. a && b returns a if it's falsy, otherwise b. Both short-circuit: the right side isn't evaluated when it isn't needed.

Nullish coalescing ?? ES2020

a ?? b returns b only when a is null or undefined. Unlike ||, it keeps 0, "" and false.

❌ || treats 0 as missing

✅ ?? only replaces null/undefined

You can't mix ?? with || or && without parentheses: a || b ?? c is a SyntaxError. Write (a || b) ?? c.

Optional chaining ?. ES2020

obj?.prop returns undefined instead of throwing when obj is null or undefined. It also works for computed access (obj?.[key]) and calls (fn?.()). Once it short-circuits, the rest of the chain is skipped.

💡 Don't overuse ?.. Use it where a value may legitimately be missing. If something should always exist, plain . is better, because a TypeError shows the bug early instead of hiding it as undefined.

Destructuring ES2015

Destructuring pulls values out of arrays (by position) or objects (by name) into variables, with optional renaming, defaults and rest. Like default parameters, destructuring defaults apply only for undefined.

In function parameters

Destructuring a parameter object is the idiomatic way to take "named arguments" with defaults. The trailing = {} lets callers omit the argument entirely.

⚠️ Pitfall: destructuring null or undefined throws: const { a } = null gives a TypeError. Defaults in the pattern don't help; give the whole parameter a default (= {}), or use ?? {}.

Why == surprises people

== converts its operands before comparing, following a set of rules. null and undefined equal each other and nothing else. Otherwise, objects are converted to primitives and then to numbers, and booleans become numbers first. The results are hard to predict:

💡 Rule: always use === and !==. The single common exception is x == null, which checks for "null or undefined" in one go.

☕ Java: === on objects compares references, like Java's == on objects. There's no built-in equals() for value comparison of objects; you compare fields, or serialize the objects.

Recap

  • ** is right-associative and needs parentheses with unary minus. % follows the left operand's sign. + with a string concatenates.
  • ||/&& return operands. ?? replaces only null/undefined. ?. stops at null/undefined.
  • ??=, ||= and &&= assign conditionally.
  • Destructuring unpacks by position or by name, with renames, defaults (for undefined only) and rest. Spread copies shallowly, and later keys win.
  • Use === (and x == null). Object.is distinguishes NaN and -0; includes and Map use SameValueZero.

Exercise 8 🟡 medium explain why

Why is [] == ![] true?

Show solution

![] is false, because [] is truthy. Then [] == false: the boolean becomes 0, and the array is converted to a primitive, "", then to a number, 0. So 0 == 0 is true. That's exactly why === is the default.
