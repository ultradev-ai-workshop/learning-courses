Iterators & Generators

for…of, spread and destructuring all work through one small protocol introduced in ES6. Learn the protocol, write your own iterables with generators, chain the new iterator helpers lazily, and stream asynchronous data with for await.

You will learn

  • The iterable and iterator protocols, and which language features use them ES2015.
  • How to make your own objects iterable.
  • Generator functions: yield, yield*, two-way next(value), infinite sequences.
  • Iterator helpers: lazy map, filter, take, drop, toArray ES2025.
  • Async iteration: Symbol.asyncIterator, async generators and for await…of ES2018.

The iteration protocols

  • An iterable is an object with a [Symbol.iterator]() method that returns an iterator.
  • An iterator is an object with a next() method that returns { value, done } objects.

Built-in iterables: arrays, strings, Map, Set, typed arrays, arguments, NodeLists, and the results of entries(), keys() and values(). Plain objects are not iterable; use Object.entries(obj).

Consumers of the protocol
for…of · spread [...x] · array destructuring · Array.from · new Map(x) / new Set(x) · Promise.all(x) · yield* · Object.fromEntries(x)

Making an object iterable

Hand-written iterators are verbose. Generators, next, do the same job in a few lines.

Generators ES2015

A generator function (function*) returns a generator object, which is both an iterator and an iterable. Calling the function runs none of its body. Each next() runs the body up to the next yield, pauses there, and hands out the yielded value.

Generators as iterator implementations

Infinite and lazy sequences

A generator computes values only when asked, so infinite sequences are fine, as long as the consumer stops.

Two-way communication

next(value) sends a value into the generator: it becomes the result of the paused yield expression. (The first next() only starts the generator, so a value sent with it is ignored.)

☕ Java: a JavaScript iterable is Iterable<T>, and an iterator's next() folds hasNext()/next() into one call that returns { value, done }. Generators are like coroutines; Java has no direct equivalent (the closest is a Stream built from a Supplier).

Iterator helpers ES2025

Iterators now have their own lazy methods, so you can process huge or infinite sequences without first building arrays. They live on Iterator.prototype, and every built-in iterator and generator has them.

Lazy (return iterators)Eager (consume the iterator)
map, filter, take(n), drop(n), flatMaptoArray, reduce, forEach, some, every, find

⚠️ Arrays vs iterators: [1, 2, 3].map(f) is the array method (eager, returns an array). [1, 2, 3].values().map(f) is the iterator helper (lazy, returns an iterator). Iterators are single-use: once consumed, they're empty.

Async iteration ES2018

When each value arrives asynchronously, like pages from an API, lines from a file or chunks from a stream, use an async iterable: an object with [Symbol.asyncIterator](), whose next() returns a promise of { value, done }. An async function* creates one, and for await…of consumes it.

Recap

  • An iterable has [Symbol.iterator](); an iterator's next() returns { value, done }. for…of, spread and destructuring all use them.
  • function* plus yield makes iterators easy: they're lazy, they can be infinite, they pause and resume, and yield* delegates.
  • break calls return(), so a generator's finally blocks run, which is good for cleanup.
  • Iterator helpers (map/filter/take/drop/toArray…) process sequences lazily and without arrays.
  • async function* plus for await…of streams asynchronous data such as pages, lines and events, and Array.fromAsync collects it.

Exercise 8 🟡 medium explain why

Why can an infinite generator be used safely with .take(5).toArray(), but not with [...gen()]?

Show solution

Spread keeps calling next() until done is true, which never happens, so it runs forever (and runs out of memory). take(5) is lazy: it pulls only five values and then stops asking, so the generator never runs further.
