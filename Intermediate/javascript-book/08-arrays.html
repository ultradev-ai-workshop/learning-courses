Arrays & Typed Arrays

Arrays are JavaScript's workhorse. This chapter sorts the methods into "changes the array" and "returns something new", covers the ES2023 copy-returning methods that make immutable code easy, and explains the default sort() trap. It ends with typed arrays for raw binary data.

You will learn

  • Creating arrays: literals, Array.from, Array.of ES2015, and the new Array(n) trap.
  • Which methods mutate and which return a new array, including toSorted, toReversed, toSpliced and with ES2023.
  • map, filter, reduce, find/findLast, some/every, flat/flatMap.
  • Sorting correctly: the default string order, comparators and stability.
  • Typed arrays and ArrayBuffer for binary data.

Creating arrays

  • new Array(3) creates three holes (empty slots, not undefined), which many methods skip. Array.of exists precisely to avoid that one-number confusion.
  • Array.from(iterableOrArrayLike, mapFn) converts strings, Sets, Maps, NodeLists and { length: n } objects into real arrays.

⚠️ Pitfall: new Array(3).fill([]) puts the same array in all three slots. Use Array.from({ length: 3 }, () => []) for separate ones.

Reading and length

at() ES2022 accepts negative indexes. Setting length truncates the array. includes ES2016 uses SameValueZero, so it finds NaN, while indexOf uses === and doesn't.

⚠️ Pitfall: reduce without an initial value. [].reduce((a, b) => a + b) throws a TypeError, and with objects the first item becomes the accumulator. Always pass the initial value.

⚠️ Pitfall: map(parseInt). ["1", "2", "3"].map(parseInt) gives [1, NaN, NaN], because map passes (item, index) and parseInt treats the index as a radix. Write .map((s) => parseInt(s, 10)) or .map(Number).

Sorting

Without a comparator, sort converts items to strings and compares UTF-16 code units. That's fine for plain ASCII words, and wrong for numbers.

A comparator returns a negative number if a comes first, a positive number if b does, and 0 for "equal". Since ES2019, sort is stable: equal items keep their order, so sorting by several keys can be done by chaining, or more clearly with ||:

Holes and array-likes

Holes come from new Array(n), [1, , 3], or writing past the end. forEach, map and filter skip them, while for…of, spread and Array.from treat them as undefined. Avoid creating holes.

Typed arrays

A typed array is a fixed-length array of raw numbers of one type, stored in an ArrayBuffer (a block of bytes). They're used for binary file formats, network protocols, images, audio, WebGL and WebAssembly. Several views can look at the same buffer.

words[0] is 16711935 (0x00FF00FF) because this machine is little-endian: the first byte is the least significant one. Typed arrays have most array methods (map, slice, toSorted, …), but a fixed length, so there's no push.

Recap

  • Use Array.from to convert iterables and build arrays, and Array.of for one number; avoid holes.
  • push/pop/shift/unshift/splice/sort/reverse/fill mutate; prefer toSorted/toReversed/toSpliced/with, spread and map/filter for shared data.
  • Always give reduce an initial value. find/some/every stop early. flatMap maps and flattens one level.
  • The default sort compares strings, so pass (a, b) => a - b for numbers and localeCompare for text. Sorting is stable.
  • Typed arrays are fixed-size numeric views over an ArrayBuffer; integer views wrap on overflow.

Exercise 8 🟡 medium explain why

Why does Array(3).map((_, i) => i) give [ <3 empty items> ], while Array.from({ length: 3 }, (_, i) => i) gives [0, 1, 2]?

Show solution

Array(3) has three holes, and map skips holes, so the callback never runs. Array.from reads indexes 0 to length−1 explicitly, so it calls the function for each one.
