Maps, Sets & Weak Collections

Before ES6, plain objects did double duty as dictionaries, with string-only keys and prototype surprises. Map and Set are the proper tools. ES2024 and ES2025 added grouping and set algebra, and the weak collections let the garbage collector clean up after you.

You will learn

  • Map: any key type, ordered, sized, iterable ES2015, and when to choose it over an object.
  • Set: uniqueness, plus the new set operations union, intersection and friends ES2025.
  • Grouping with Object.groupBy and Map.groupBy ES2024.
  • Upserts with getOrInsert/getOrInsertComputed (new in 2026 engines).
  • WeakMap, WeakSet and WeakRef: collections that don't keep their keys alive.

⚠️ Pitfall: map["b1"] = 3 sets an ordinary property on the Map object, not an entry: get("b1") won't see it and size doesn't change. Always use set and get.

Map keys use SameValueZero (Chapter 5): NaN works as a key, and 0 and -0 are the same key.

☕ Java: a Map behaves like LinkedHashMap (it keeps insertion order). But object keys are compared by identity; there's no hashCode()/equals() override, so two equal-looking objects are two different keys.

Upsert: getOrInsert and getOrInsertComputed

"Get the value, or insert a default first" is extremely common. Newer engines (Node 26 included) ship getOrInsert(key, value) and getOrInsertComputed(key, fn), where the function only runs if the key is missing.

📝 Availability: getOrInsert is very new. Check your target runtimes; the has/set/get pattern works everywhere.

Set ES2015

A Set holds unique values, in insertion order, and checks membership quickly.

Set operations ES2025

MethodResultMaths
a.union(b)in a or ba ∪ b
a.intersection(b)in botha ∩ b
a.difference(b)in a, not in ba − b
a.symmetricDifference(b)in exactly onea Δ b
a.isSubsetOf(b), isSupersetOf, isDisjointFrombooleans⊆, ⊇, no overlap

These methods return new sets and never change the originals. The argument may be any "set-like" object with size, has and keys, so a Map works too (its keys are used).

📝 Older syntax you'll still see: new Set([...a].filter((x) => b.has(x))) for intersection, and similar spreads for the others. They still work, but the new methods are clearer and faster.

Grouping ES2024

Object.groupBy(items, fn) returns an object whose keys are the strings fn returns. Map.groupBy returns a Map, so keys can be any value.

⚠️ Pitfall: the object from Object.groupBy has a null prototype, so it has no hasOwnProperty method, and Node prints it as [Object: null prototype] {…}. Use Object.hasOwn(groups, key) or key in groups.

Weak collections

A normal Map keeps its keys alive forever. A WeakMap holds its keys weakly: if nothing else references a key object, the garbage collector may remove the entry. In exchange, keys must be objects (or non-registered symbols), and weak collections can't be iterated or sized, since their contents may vanish at any moment.

Map / SetWeakMap / WeakSet
Keysany valueobjects (and non-registered symbols) only
Iterable, sizeyesno
Keeps keys aliveyesno
Typical usedata you ownmetadata attached to objects you don't own: caches, "seen" markers, private data

WeakRef and FinalizationRegistry ES2021 go one step further: they let you hold a single object weakly and get notified after it's collected. They're advanced tools with unpredictable timing; Chapter 15 covers them.

Recap

  • Use Map for dynamic dictionaries: any key type, insertion order, size, direct iteration. Use get/set, never brackets.
  • Use Set for uniqueness and fast membership. ES2025 adds union, intersection, difference and the subset checks.
  • Object.groupBy returns a null-prototype object; Map.groupBy supports any key type.
  • getOrInsertComputed handles "get or create" in one call, where it's available.
  • WeakMap/WeakSet take object keys only, aren't iterable, and don't prevent garbage collection, which makes them ideal for metadata and caches.

Exercise 6 🟡 medium explain why

Why can't you loop over a WeakMap or read its size?

Show solution

Entries can disappear whenever the garbage collector runs, which happens at unpredictable times. Iteration or a size would expose GC timing and make programs non-deterministic, so the API only offers get/set/has/delete for a key you already hold.
