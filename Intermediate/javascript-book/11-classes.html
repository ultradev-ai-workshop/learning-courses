Classes & the Prototype Chain

ES6 classes look like Java classes, but underneath they're built on JavaScript's original model: objects linked to other objects through a prototype chain. This chapter covers the full modern class syntax, including private #fields and static blocks, and then opens the hood.

You will learn

  • Class syntax: constructor, methods, getters and setters, static members ES2015.
  • Public and private fields, private methods, #x in obj, static blocks ES2022.
  • extends, super, overriding, and extending built-ins like Error.
  • The prototype chain: how property lookup works, and what a class compiles to.
  • this in class methods, arrow-function fields, and mixins.

Class syntax

Facts about classes that surprise Java developers:

  • A class is a special function: typeof Book === "function". It must be called with new.
  • Class bodies are always in strict mode.
  • Class declarations are not hoisted like functions: they're in the TDZ until their line runs.
  • Fields are initialised before the constructor body runs (in a subclass, right after super() returns).
  • There's no overloading and no access modifiers other than #.

Private members ES2022

#name is truly private: it's a syntax error to mention it outside the class body, and it doesn't show up in any reflection (Object.keys, JSON, Reflect.ownKeys). Methods and accessors can be private too. #field in obj checks whether an object has that private field, which is a safe brand check.

📝 Older syntax you'll still see: the _balance underscore convention ("please don't touch"), closures, or WeakMaps keyed by instance for privacy. TypeScript's private keyword only exists at compile time, unlike #.

Under the hood: the prototype chain

Every object has a hidden link, [[Prototype]], to another object (or to null). When you read a property that the object doesn't have itself, JavaScript follows the link and looks there, then follows that object's link, and so on. This lookup path is the prototype chain.

The differences: class methods are non-enumerable, classes can't be called without new, they're strict, they have real #private members, and super works.

☕ Java: there are no separate "class" and "instance" kinds of thing at run time: a class is an object (a function), and inheritance links objects, not types. You can even create an object with a given prototype directly, with Object.create(proto), with no class involved.

this in class methods

Class methods are ordinary functions on the prototype, so they lose this when they're detached (Chapter 4). A class field holding an arrow function is created per instance, and captures that instance's this, which is a common fix for event handlers.

The trade-off: arrow fields aren't on the prototype, so each instance gets its own copy, and subclasses can't call them with super.

Mixins

JavaScript has single inheritance. To share behaviour across unrelated classes, use a mixin: a function that takes a base class and returns a subclass with extra methods.

Recap

  • A class is a strict, non-hoisted, new-only function. Methods live on the prototype; fields live on each instance.
  • #private fields and methods are truly hidden; #x in obj is a brand check; static blocks initialise static state.
  • extends + super() (before this) + super.method(); built-ins like Error and Array can be extended.
  • Property lookup follows the [[Prototype]] chain, and own properties shadow inherited ones. Classes are mostly syntax over constructor functions.
  • Detached methods lose this; arrow-function fields bind it per instance. Use mixins for shared behaviour.
