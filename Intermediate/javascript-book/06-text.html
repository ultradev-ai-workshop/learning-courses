Numbers, Strings, Dates & Intl

The everyday data: numbers that are always floats (plus BigInt), strings made of UTF-16 code units, template literals and tags, the famously awkward Date and its replacement Temporal, and the Intl APIs that format all of it for any language.

You will learn

  • Number precision, safe integers, Number.EPSILON, parsing and rounding pitfalls.
  • Strings as UTF-16: length vs characters, and the modern string methods.
  • Template literals, tagged templates and String.raw ES2015.
  • Date pitfalls, and the Temporal API as the modern alternative.
  • Locale-aware formatting with Intl: currency, dates, plurals, lists, sorting.

Numbers

Every number is a 64-bit IEEE-754 float, the same as Java's double. Integers are exact only up to Number.MAX_SAFE_INTEGER (253 − 1). Beyond that, use BigInt.

💡 Money: store integer cents (1299), not 12.99, and format only for display. That avoids float drift in totals, the same advice as Java's BigDecimal.

Rounding

  • toFixed returns a string, and rounds the binary value: 1.005 is really 1.00499…, so it gives "1.00".
  • Math.round rounds halves up (toward +∞): -2.5 becomes -2.
  • Math.trunc, Math.sign, Math.cbrt and Math.hypot are ES2015 additions.

BigInt ES2020

BigInt division truncates. You can't mix BigInt and Number in arithmetic (that's a TypeError); convert explicitly with BigInt(n) or Number(b). JSON.stringify can't serialize BigInts.

Strings

A string is an immutable sequence of UTF-16 code units. Most characters are one unit, but emoji and other characters outside the Basic Multilingual Plane are two (a surrogate pair). length counts units, not what a reader sees as characters.

Spreading or for…of iterates by code point. For "what the user sees as one character" (for example 👍🏽, which is two code points), use Intl.Segmenter (see the Intl section below).

Template literals ES2015

Backtick strings can span several lines and embed any expression with ${…}.

Tagged templates

A tag is a function placed before a template literal. It receives the literal text pieces and the evaluated values separately, so it can escape, translate or format the values before joining them. Libraries use this for SQL, HTML and CSS.

Dates

Date stores a single moment as milliseconds since 1 January 1970 UTC. It's a leftover from 1995 Java, and it has well-known traps:

TrapExample
Months are 0-based (days are not)new Date(2026, 9, 30) is 30 October
Date-only ISO strings are UTC; date-time strings without a zone are localnew Date("2026-10-30") vs new Date("2026-10-30T00:00")
Dates are mutabled.setDate(d.getDate() + 1) changes d for everyone holding it
Overflow rolls over silentlynew Date(2026, 0, 32) is 1 February
Only local time and UTC; no other time zonesuse Intl to display in another zone

Temporal: the modern replacement

Temporal is a new global API, available in Node 26 and current browsers, that fixes Date's design. It has separate immutable types for different jobs: PlainDate (a calendar date), PlainTime, ZonedDateTime (a moment in a real time zone), Instant and Duration. Months are 1-based, and arithmetic is calendar-aware.

📝 Status: Temporal is new. Check your target browsers or Node version before relying on it, or use the @js-temporal/polyfill package. Date isn't going anywhere, so you'll keep reading it in existing code.

Internationalization with Intl

The Intl namespace formats numbers, dates, lists and plurals, and compares strings, according to a locale such as "de-DE" or "en-IN". Create a formatter once and reuse it; formatters are relatively expensive to build.

⚠️ Pitfall: formatted output may contain special spaces, such as a no-break space before € or a narrow no-break space before AM. Never compare formatted strings in tests against strings you typed by hand; compare the numbers, or use formatToParts().

Recap

  • Numbers are doubles: compare floats with a tolerance, store money as integer cents, and use BigInt beyond 253.
  • Prefer Number() plus Number.isNaN; give parseInt a radix. toFixed returns a string.
  • Strings are UTF-16: length counts code units, spread counts code points, and Intl.Segmenter counts what readers see.
  • Template literals interpolate and span lines. Tags receive the literal parts and values separately.
  • Date has 0-based months and mutable objects; Temporal fixes both. Use Intl for all user-facing formatting.

Exercise 6 🟡 medium explain why

Why does (1.005).toFixed(2) give "1.00" and not "1.01"? How would you round money correctly?

Show solution

1.005 can't be stored exactly. The nearest double is 1.00499999999999989…, which correctly rounds down. Work in integer cents (Math.round(x * 100) at input time), or use a decimal library for exact decimal rounding.

Exercise 7 🟡 medium build it · playground

Create playground/format.js exporting formatPrice(cents, locale, currency), with formatters cached per locale + currency in a Map. Print 1299 cents in en-US/USD, de-DE/EUR and ja-JP/JPY (yen has no minor unit, so 1299 means ¥1,299).

Show solution

Exercise 8 🟡 medium predict the output

What does ["b", "a", "C", "á"].sort() return? And with new Intl.Collator("en").compare?

Show solution

['C', 'a', 'b', 'á'] (by UTF-16 code unit, so uppercase letters come first and accents last), and ['a', 'á', 'b', 'C'] (the human dictionary order for English).

Exercise 9 🔴 hard build it

Using Temporal, compute the delivery date for an order placed on "2026-12-23" with 3 business days of shipping, skipping weekends and the holidays 2026-12-25 and 2026-12-26.

Show solution

Walking forward from the 23rd: the 24th (Thursday) counts as day 1; the 25th (Friday) is a holiday; the 26th and 27th are a weekend (the 26th is also a holiday); the 28th (Monday) is day 2 and the 29th is day 3. So delivery is 2026-12-29. dayOfWeek uses ISO numbering: Monday = 1 through Sunday = 7.
