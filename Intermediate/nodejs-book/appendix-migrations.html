Appendix B

From the Browser & Userland Libraries

Many habits and packages from older Node code or from front-end work have built-in replacements in modern Node. This appendix is a migration guide: browser JavaScript → Node, and the most common npm packages → the features that now ship with Node. Fewer dependencies mean fewer updates, fewer vulnerabilities and faster installs.

You will learn

  • How browser concepts map to Node (window, DOM, storage, modules).
  • Built-in replacements for chalk, axios, dotenv, nodemon, Mocha/Jest, uuid, rimraf, glob, yargs and more.
  • How the Node.js "userland migrations" codemods automate some of this.
  • What WebAssembly and Node-API (native addons) are, and when you'd meet them.

Browser → Node cheat sheet

🧠 Analogy: moving from a hotel to your own flat. In the browser you're a hotel guest: lots is provided (the DOM, storage, a window to look out of), but you can't touch the building (no file system, no raw sockets). Node is your own flat: no room service, but you have the keys to everything — and responsibility for locking the doors (security, Chapter 15).

dotenv, uuid, rimraf, structuredClone

Mocha → node:test

Mocha-style code often needs only the imports changed: describe, it, before, after, beforeEach and afterEach exist in node:test. Replace chai's expect(x).to.equal(y) with assert.equal(x, y), sinon spies with mock.fn(), and the mocha command with node --test. Jest users map jest.fn() → mock.fn(), jest.useFakeTimers() → t.mock.timers.enable(), and expect(...).toEqual → assert.deepEqual.

Automated migrations

The Node.js project maintains userland migrations: codemods that rewrite your code automatically, for example from chalk to util.styleText, from axios to fetch, from Mocha to the test runner, or to add correct .ts extensions to TypeScript imports. They run with the codemod tool:

Always run codemods on a clean git working tree, review the diff, and run your tests afterwards.

WebAssembly in Node

WebAssembly (Wasm) is a compact binary format that languages like Rust, C and Go can compile to. Node runs it with the same WebAssembly API as browsers, so you can use a fast image codec or parser written in another language without native compilation. Native addons and Node-API

Some packages include C or C++ code compiled into a native addon (a .node file): database drivers, image processing (sharp), cryptography. Node-API is the stable C interface they use; its ABI stability means an addon compiled once keeps working across Node versions. As an app developer you mostly meet addons when npm install needs build tools (node-gyp, Python, a C++ compiler) or downloads prebuilt binaries for your platform. Prefer pure-JavaScript or WebAssembly packages when performance allows: they install anywhere. And under the permission model, addons must be explicitly allowed (--allow-addons).

Recap

  • Browser → Node: globalThis instead of window, no DOM or storage, the same web APIs (fetch, URL, streams, WebSocket), files and processes instead.
  • Built-ins replace many small packages: styleText, --env-file, --watch, parseArgs, fetch, node:test, randomUUID, fs.rm/mkdir/cp/glob, structuredClone, node:sqlite.
  • Official codemods automate common migrations; review the diff and run the tests.
  • WebAssembly runs portable compiled code; native addons use Node-API and need build tools or prebuilt binaries.

Exercises

Exercise 1 🟢 easy map it

Name the built-in replacement for: (a) nodemon app.js; (b) require("dotenv").config(); (c) uuidv4(); (d) rimraf dist; (e) chalk.yellow("warn").

Show solution

(a) node --watch app.js; (b) node --env-file=.env app.js or process.loadEnvFile(); (c) crypto.randomUUID(); (d) fs.rm("dist", { recursive: true, force: true }); (e) util.styleText("yellow", "warn").

Exercise 2 🟢 easy browser code

Which lines of this browser snippet fail in Node, and why? const theme = localStorage.getItem("theme"); const url = new URL(location.href); document.title = "Hi"; const res = await fetch("/api");

Show solution

localStorage, location and document don't exist in Node (ReferenceError). fetch exists, but "/api" is a relative URL with no page to resolve it against, so it throws an "invalid URL" TypeError — Node needs absolute URLs. new URL(...) itself works if given an absolute string.

Exercise 3 🟢 easy convert

Rewrite with built-ins: const copy = _.cloneDeep(settings); const id = uuid.v4(); console.log(chalk.green(`saved ${id}`));

Show solution

Exercise 4 🟢 easy explain

Give two reasons to remove a small utility dependency when Node has a built-in equivalent, and one reason you might keep it.

Show solution

Remove: fewer packages to audit and update (smaller supply-chain risk), and faster, smaller installs. Keep: when the package does meaningfully more than the built-in (e.g. yargs' generated help and sub-commands, axios interceptors used everywhere), or when you must support older Node versions that lack the built-in.

Exercise 9 🔴 hard audit

You inherit a package.json with: express, dotenv, nodemon, axios, chalk, uuid, mocha, chai, sinon, rimraf, zod, pg. Which would you remove, keep or replace, and in what order would you do it safely?

Show solution

Keep: express (framework), zod (validation), pg (database driver) — no built-in equivalents. Replace: dotenv → --env-file; nodemon → --watch; chalk → styleText; uuid → randomUUID; rimraf → fs.rm; axios → fetch (with a small wrapper); mocha/chai/sinon → node:test/assert/mock. Order: dev-only tooling first (nodemon, rimraf, dotenv in scripts: zero runtime risk), then trivial runtime swaps (uuid, chalk), then the test stack (migrate files gradually; both runners can coexist), and axios last (most behaviour differences: errors, JSON, timeouts). One change per commit, tests green after each.

Exercise 10 🔴 hard WebAssembly

Modify the WebAssembly example's bytes so the exported function multiplies instead of adds (the opcode for i32.mul is 0x6c), and export it under the name mul. Call it with 6 and 7.

Show solution

The name is three bytes long like "add", so no section sizes change. Real projects never write bytes by hand: wat2wasm (text format) or a compiler (Rust's wasm-pack, Emscripten) produces them.
