Appendix A · Popular Frameworks

LangChain

The most widely used LLM application framework: one interface for every model provider, composable "runnables", tools, agents and retrieval building blocks. Learn what it gives you on top of the raw SDK, and what it costs.

You will learn

  • How LangChain is packaged: langchain-core, langchain, and provider packages such as langchain-anthropic.
  • Chat models, messages and prompt templates.
  • Composing steps with the pipe operator (LCEL): prompt | model | parser, plus streaming and batching.
  • Structured output, tools and the create_agent agent.
  • Retrieval building blocks: splitters, embeddings, vector stores and retrievers.
  • How to test LangChain code with fake models, and when to choose it over the plain SDK.

Versions. This appendix uses langchain 1.x, langchain-core 1.x and langchain-anthropic 1.x. LangChain changed a lot before 1.0 (old LLMChain, initialize_agent and AgentExecutor tutorials are outdated). The examples run against the book's mock server through the real ChatAnthropic class.

What LangChain is

PackageWhat's in it
langchain-corethe interfaces: chat models, messages, prompts, output parsers, tools, runnables, documents, retrievers
langchainhigher-level pieces, notably create_agent and its middleware
langchain-anthropic, langchain-openai, …one package per provider, implementing the core interfaces
langchain-text-splitters, community integrationsdocument loaders, splitters, vector stores

🧠 Analogy: a universal power adapter with a cable organizer. Each provider has its own plug shape (request format). LangChain is the adapter that makes them all fit one socket, plus a box of standard cables (prompts, parsers, retrievers) that snap together. Handy when you travel between providers; extra bulk when you only ever use one socket.

☕ Java: the closest equivalents are LangChain4j (inspired by LangChain, with ChatModel, @Tool and "AI Services" interfaces) and Spring AI (ChatClient, advisors, vector stores). The ideas in this appendix map directly; see Appendix F.

Structured output

with_structured_output returns a runnable that produces validated Pydantic objects. On current Claude models use method="json_schema", which uses the API's structured outputs. The older default forces a tool call, which claude-sonnet-5-5 and claude-opus-5-5 don't support; LangChain warns you about that.

When to use LangChain

Good fitThink twice
you need several providers behind one interfaceyou use one provider and want its newest features on day one
you want ready-made integrations (loaders, vector stores)you need full control of every request field
you'll use LangGraph for stateful agentsyour app is a couple of calls; the SDK is simpler
a team wants shared, familiar building blocksyou want fewer dependencies to upgrade

Know what runs underneath. Every LangChain call is still a Messages API request. When something behaves oddly, look at the actual request (LangSmith tracing, or the SDK's OpenTelemetry spans from Chapter 10) and apply what you know from Chapters 3–5.

Recap

  • LangChain = core interfaces + provider packages + higher-level pieces such as create_agent.
  • Chat models share invoke/stream/batch; LCEL pipes compose prompts, models, parsers and functions.
  • with_structured_output(Model, method="json_schema") on current Claude models; @tool + bind_tools for tools; create_agent for the loop.
  • Retrieval pieces are interfaces; access control, hybrid search, citations and evals are still yours.
  • Fake chat models make chains unit-testable.

Exercises

Exercise 1 🟢 easy explain

What does the | operator do between a prompt template and a chat model?

Show solution

It composes two runnables into a sequence: the prompt's output (a list of messages) becomes the model's input. The result is itself a runnable with invoke, stream and batch.

Exercise 2 🟢 easy fix the bug

llm.with_structured_output(Triage).invoke(...) raises OutputParserException on claude-sonnet-5-5. Why, and what's the fix?

Show solution

The default method forces a tool call, which the newest Claude models reject (forced tool_choice), so no tool call comes back to parse. Use with_structured_output(Triage, method="json_schema"), which uses native structured outputs.
