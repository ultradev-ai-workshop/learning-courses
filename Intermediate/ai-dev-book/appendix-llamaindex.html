Appendix C · Popular Frameworks

LlamaIndex

A framework centred on connecting models to your data: loading, parsing into nodes, indexing, retrieving and querying. Where LangChain is a general toolbox, LlamaIndex is a specialist in the RAG pipeline of Chapter 7.

You will learn

  • LlamaIndex's vocabulary: documents, nodes, indexes, retrievers, query engines.
  • How to parse Markdown into nodes that keep their heading metadata.
  • How to plug in an embedding model and an LLM through Settings.
  • Retrievers, metadata filters and query engines with source nodes.
  • How to write a small custom LLM adapter, and test with MockLLM.
  • When LlamaIndex is the right choice.

Versions. This appendix uses llama-index-core 0.14. Provider integrations (such as llama-index-llms-anthropic) are separate packages that follow their SDKs at their own pace; at the time of writing the Anthropic integration hadn't caught up with anthropic 2.x, so the book writes a 20-line adapter instead. Check the integration's release notes before you pin versions.

Query engineretriever + LLM synthesis → answer with source nodesrag.answer

🧠 Analogy: a library's back office. Documents arrive as donations, cataloguers cut them into indexed cards (nodes) with shelf marks (metadata), the index is the card catalogue, the retriever is the librarian who pulls cards, and the query engine is the reference desk that reads the cards and writes you a reply with the card numbers attached.

Documents and nodes

The Markdown parser keeps the heading path in header_path and copies the document's metadata to every node: the same "keep the heading path" rule as Chapter 7.

Index, retrieve, query

The query engine retrieves, packs the nodes into its prompt template, calls the LLM and returns the answer with source_nodes: the raw material for citations. As with LangChain, access control, hybrid search, abstention and evals are your job.

When to use LlamaIndex

Good fitThink twice
a data-heavy RAG app with many source types (PDFs, wikis, databases)a tool-heavy agent with little retrieval
you want ready parsers, node relationships and query enginesyou need fine control of every prompt and request
you'll use LlamaParse or LlamaCloud for document parsingyou already have a search platform you trust

Recap

  • Documents → nodes (via a node parser) → index → retriever → query engine with source nodes.
  • Settings holds the default embedding model and LLM; adapters are small classes.
  • Filters run inside retrieval; use them for access control.
  • MockLLM and a toy embedding make the pipeline testable offline.
  • Integrations can lag behind SDKs: pin versions, or write a thin adapter.

Exercise 10 🔴 hard design

You must index 20,000 PDFs and Confluence pages, with per-space permissions. Which LlamaIndex pieces would you use, and what would you build yourself?

Show solution
