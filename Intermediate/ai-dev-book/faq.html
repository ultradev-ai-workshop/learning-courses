1. Do I need an Anthropic API key to run or understand this course?

No. You can read the whole book, run every example and do every exercise without a key and without spending any money.

  • The playground repository includes llmkit, which has a local mock of the Messages API. The real anthropic SDK (and openai, LangChain, Pydantic AI and DSPy) talk to it unchanged, so the code you write is the same code you'd ship.
  • The mock checks requests like the real API does for the rules the book teaches. Unknown models, sampling parameters on current models, prefill, forced tool choice and mismatched tool results all fail the way they would for real. It also supports streaming, token counting, prompt caching, batches and injected failures.
  • FakeAnthropic scripts the model's replies, which is how you'll test your own LLM code anyway.

What the mock can't give you is real model behaviour: its answers are honest placeholders ("(mock reply) You said: …"), so you won't see how well Claude actually answers, follows a prompt or picks tools. When you want that, create a key in the Claude Console, unset ANTHROPIC_BASE_URL and export ANTHROPIC_API_KEY. The same examples then call Claude (Using the Playground, step 5).

If you do use a key: start with small inputs, read usage on every response (Chapter 1 shows how to estimate cost), set a spend limit on the key, and use claude-haiku-5-5 for experiments. The eval and batch examples make many calls, so run them on a few cases first.

2. Will this course help me build an agent if I'm clear about the requirements?

Yes. Clear requirements are exactly where the book starts, and the first decision it teaches is whether you need an agent at all. Many "agents" are better built as a workflow: a fixed sequence of steps, some of which call a model, which is cheaper, faster and easier to test. When the next step really depends on what the model finds, the book takes you from the first tool call to a budgeted, tested, secured agent.

A suggested path if your goal is an agent: Chapters 1–5 → 8 → 10 → 12 → 15, then the framework appendix that fits your requirements. Before you write code, write down five things for your agent; each one maps to a part of the book:

  1. The goal and how you'll know it's reached (Ch. 8, Ch. 10).
  2. The tools: which systems it reads, which it may change, and with whose permissions (Ch. 5, Ch. 12).
  3. The budgets: steps, tokens, money, time (Ch. 8, Ch. 11).
  4. The approvals: which actions need a human (Ch. 12).
  5. The eval set: 20–50 realistic tasks with the expected behaviour (Ch. 10).

Beyond the book. If you'd rather not write the loop or host the sandbox yourself, Appendix F introduces Anthropic's Claude Agent SDK and hosted Managed Agents. The design skills from Chapters 8–12 apply to them unchanged.

3. Is there a prerequisite for this course?

The course is Intermediate. You need:

  • Comfortable Python: functions, classes, dictionaries and lists, modules and imports, exceptions, virtual environments and pip. Type hints and async/await appear often; you'll pick them up if they're new. The Python Study Book covers everything required.
  • Basic HTTP and JSON: requests, status codes, headers, a JSON body.
  • A terminal, to run scripts and git clone the playground.

Helpful but not required:

  • Java, for the ☕ boxes, which connect each idea to Java and backend practice. You can skip them.
  • SQL, for the pgvector and access-control parts of Chapters 6, 7 and 12.
  • Backend experience (APIs, retries, caching, tracing). The book leans on it heavily, because LLM features are backend features.

Not needed: machine learning, statistics or linear algebra. The few ideas you need (vectors, cosine similarity, precision and recall, attention) are explained with small code examples where they're used.
