Appendix B · Popular Frameworks

LangGraph

A library for building agents and workflows as explicit graphs of steps over shared state, with checkpoints, human-in-the-loop interrupts and resumable runs. It's what you reach for when the loop from Chapter 8 needs to survive restarts and approvals.

You will learn

  • The three ideas: state, nodes and edges (including conditional edges).
  • Reducers: how parallel or repeated updates to the same key are merged.
  • The prebuilt tool agent: MessagesState, ToolNode, tools_condition.
  • Checkpointers and threads: memory across calls and resumable runs.
  • Human-in-the-loop with interrupt and Command(resume=...).
  • When a graph is worth it, and when a plain loop is enough.

State, nodes and edges

A LangGraph app is a state machine. The state is a typed dict shared by all steps. A node is a function that receives the state and returns an update (a partial dict). Edges say which node runs next; a conditional edge is a function that picks the next node from the state.

🧠 Analogy: a board game. The state is the board, nodes are the moves, and edges are the rules about whose turn is next. A checkpoint is a photo of the board after every move: you can pause the game for days (waiting for an approval), pick it up exactly where it was, or rewind to an earlier photo to see how you got here.

Without the operator.add reducer, each update would replace log; with it, updates are appended. Reducers are how LangGraph merges results from several nodes safely.

☕ Java: think of Spring State Machine or a workflow engine such as Temporal: explicit states and transitions, with the engine persisting progress. LangGraph is lighter, in-process, and designed for steps that call models. LangChain4j has a Java port called LangGraph4j.

The tool-calling agent as a graph

The agent loop of Chapter 5 is two nodes and a conditional edge: the model node calls the model; if the reply has tool calls, tools_condition routes to the ToolNode, which runs them and loops back.

recursion_limit is the step budget: LangGraph raises GraphRecursionError when a run exceeds it. Token, cost and time budgets are still yours to add (a node can check them and route to END).

Checkpointers and threads

Compile with a checkpointer and LangGraph saves the state after every step, keyed by a thread_id. Invoking the same thread again continues the conversation; a crashed run can resume from its last checkpoint. InMemorySaver is for tests; production uses a database-backed saver (Postgres, SQLite, Redis packages exist).

The model sees the whole thread because the checkpointer resends it: the API is still stateless (Chapter 1), LangGraph just stores the history for you. Thread IDs must come from your authenticated session, never from user input, or one user could read another's thread.

Human-in-the-loop with interrupts

interrupt(payload) inside a node pauses the run and saves it. The caller gets the payload (show it to a human), and later resumes with Command(resume=value); the node continues with that value. This is the approval flow of Chapter 12, with persistence built in.

A node re-runs from its start on resume. When you resume, the interrupted node executes again from the top, and interrupt returns the resume value this time. Keep side effects after the interrupt (or in a later node), never before it, or they run twice.

Parallel branches

Edges from one node to several nodes run those nodes in the same step; a reducer merges their updates. That's the "parallelization" workflow pattern of Chapter 8:

In a real review each node would call a model with its own prompt; LangGraph runs them concurrently and the reducer collects every finding.

When a graph is worth it

runs must pause for approvals and resume latera request finishes in one go
you need durable state and crash recoverylosing an in-flight request is acceptable
the workflow has many branches you want to see as a diagramit's one model call plus a few tools
several agents or subgraphs hand work to each otherone agent with a handful of tools

Recap

  • A graph = typed state + nodes that return updates + edges (conditional edges choose the next node).
  • Reducers (Annotated[list, operator.add]) merge updates from repeated or parallel nodes.
  • MessagesState + ToolNode + tools_condition is the tool agent; recursion_limit caps steps.
  • Checkpointers save state per thread_id: memory, resumability and time travel.
  • interrupt + Command(resume=...) give durable human approvals; keep side effects after the interrupt.

Exercises

Exercise 1 🟢 easy explain

What does a node return, and what happens to state keys it doesn't mention?

Show solution

A partial update (a dict with some keys). Keys it doesn't mention keep their values. Mentioned keys are replaced, unless they have a reducer, which merges the old and new values.

Exercise 2 🟢 easy predict

In lg_basics.py, what would log contain if you removed the operator.add reducer?

Show solution

Only the last update, ['attempt 3: ok']: each node's update would replace the list instead of appending to it.

Exercise 3 🟢 easy explain

Where should a thread_id come from, and why?

Show solution

From your server-side session (for example "user id + conversation id" that you created). If a client could pass any thread ID, it could load someone else's checkpointed conversation.

Exercise 4 🟢 easy choose

Plain loop or LangGraph? (a) a one-shot classifier, (b) a change-request agent that waits hours for a manager's approval, (c) a chat with memory across days.

Show solution

(a) Plain call. (b) LangGraph: interrupts with a persistent checkpointer. (c) Either: a conversation table works; LangGraph's checkpointer is convenient if you already use it.

Exercise 8 🟡 medium fix the bug

This node sends an email, then asks for approval. Users get the email twice. Why, and how do you fix it?

Show solution

On resume the node runs again from the top, so send_email runs a second time. Move side effects after the interrupt, or into a separate node before it (completed nodes aren't re-run), and make them idempotent.

Exercise 10 🔴 hard design

Sketch DocsPilot as a LangGraph: list the nodes, the state keys, the conditional edges, where interrupts go, and which checkpointer you'd use in production.

Show solution
  • State: messages, user (from the session), route, chunks, citations, tokens, degraded.
  • Nodes: guard_in (size, budget, redaction) → route → retrieve → answer (citations) or model ⇄ tools → guard_out; plus degrade.
  • Conditional edges: after route (docs / live / out of scope), after retrieve (abstain if weak), after model (tools / budget exceeded / done).
  • Interrupts: before any write tool, with a code-generated summary bound to the arguments.
  • Checkpointer: a Postgres-backed saver, thread ID = conversation ID from your database.
